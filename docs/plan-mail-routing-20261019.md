# 메일함 주소 변경·Cloudflare 자동 수신 연동 · 0.47.0

사용자가 pkdkak1@qaredi.com으로 변경, REA 메일함 설정 저장 시 Cloudflare 수신 규칙 자동 연동, 기존 메일 보존과 Gmail 스팸 분류 보완을 요청했다. 기준0.46.3/9d39c91이며 소스는 WSL Rea_ERP다.

## 구현과 보존

메일함 UUID를 유지해 주소/표시 이름만 변경한다. 기존 메시지·전표·본문·첨부·보낸 사람 기록은 수정하지 않는다. 변경 전 비공개 메일/설정 백업과 CF 규칙 사본을 보관한다. 이전 purchase 주소의 수신 규칙은 새 주소로 갱신하며 기존 메시지의 주소는 역사대로 남긴다.

고정된 서버 도메인/zone/Worker에만 Cloudflare Email Routing Rules API를 사용한다. 이미 승인된 Wrangler OAuth는 공식 auth token --json으로 자동 갱신하며 키/토큰은 자식 프로세스의 비공개 출력에서만 읽고 웹 번들/DB/응답/로그에 넣지 않는다. 고정 Wrangler4.151.1을 실행 의존성으로 둔다. 선택 전용 API 토큰도 서버 비공개 설정에서 지원한다. 전역 키/사용자 지정 URL/브라우저 토큰은 받지 않는다.

mail.manage·기존 세션/CSRF를 확인한 저장만 허용한다. CF 사전 조회로 대상 주소 충돌을 막고 mailbox route_sync에 CAS/작업ID/기한을 기록한 뒤 외부 규칙을 반영·재조회 확인한다. 동시 저장을 막고 부분 실패/불명확 결과는 실패 상태로 남겨 명시 재시도한다. 재시도는 규칙의 결정적 메일함 표식과 실제 상태를 조회해 중복 생성을 피한다. 기존 exact-to→rea-mail-ingress 규칙만 해당 주소에서 인수하며 다른 앱/forward/drop/catch-all은 변경하지 않는다. 사용 해제/제공자 전환은 관리하는 규칙을 비활성화하고 삭제하지 않는다.

Supabase mailbox에 server-owned route_sync JSONB 열을 추가하고 SQLite·백업/복원도 같은 상태를 보존한다. UI는 저장 성공과 수신 연결 성공/실패를 구분하고 기존 주소/메일을 보존하며 연결 상태·재시도·현재 도메인을 보여준다. 공개 상태에는 키/토큰/인증경로를 노출하지 않는다.

## 검증과 운영

순수 합성 테스트로 새 주소/이름 변경·기존 메시지/권한 보존, 연결 신규/변경/비활성, 타 규칙 충돌/미수정, 동시/부분 실패/응답 유실 후 재시도 중복 방지, 관리자/CSRF/비회원 차단을 검사한다. 기존 Node/UI/브라우저와 전체 verify:local·release·REA 근거 검증 후 커밋/푸시→서버 반영·migration→실제 관리자 화면 저장으로 pkdkak1 주소/CF 규칙을 확인한다. 신규 검증 메일은 사용자 요청 범위의 연결 확인만 사용하고 업무자료를 넣지 않는다.

Gmail 현재 조회에서 qaredi.com 발신2통은 INBOX, SPAM0건이며 최근 test 메일의 SPF/DKIM/DMARC 모두 pass다. 사용자가 관찰한 스팸 메일 제목/수신 주소와 이동 여부를 질문했다. 인증 통과가 스팸 해제를 보장하지 않으며 무조건 수신함 보장/필터 우회를 구현하지 않는다. 발신 이름/Reply-To·RFC 형식과 발신 도메인을 일치시키고 실제 새 주소의 헤더/도착 분류를 별도로 검증한다.
