# 구매 집계 축 확장 0.19.0

구매현황 집계에 창고별·담당자별·프로젝트별을 추가해 기존 품목별·거래처별과 함께 최대 다섯 축을 선택한다. 초기 네 칸에서 모두 채우면 다섯 번째 칸 추가, 조건별 지우기, 다른 조건에서 선택한 축 제외, 빈 조건을 건너뛰는 조회, 새 축의 정렬·CSV·인쇄·조회 복구를 연결했다. 원본 소계·상세 이동·서버 집계 전체 동등성은 미완료다.

## 원본 대조

원본의 초기 네 집계 조건과 후보를 직접 확인했다. 네 조건을 채운 뒤 다섯 번째 조건이 추가됐다. 이를 지워도 늘어난 칸은 유지됐으며 첫 다섯 조건이 채워진 상태에서 여섯 번째 조건은 나타나지 않았다. 창고별·담당자별·프로젝트별 단독 조회는 각각 축 이름, 수량, 공급가액, 부가세, 합계의 다섯 열이었다. 프로젝트·창고·담당자·품목 순서의 네 축 조회는 그 순서와 수량·금액을 합한 여덟 열이었다. 여기에 거래처를 다섯 번째 축으로 선택한 조회는 아홉 열이었다. 이미 선택한 축은 다른 조건의 후보에서 제외됐다. 조건2의 지우기는 그 자리만 비우고 다른 축을 유지했다. 조건1~3을 비우고 조건4의 품목별만 선택해도 정상 조회했다. 선택한 축을 지운 후에도 다섯 번째 빈 칸이 유지됐다. 이 관찰은 결과 헤더와 컨트롤 반응만 기록하며 회사 기록·금액·세션 URL은 보관하지 않았다. 원본 업무·설정 저장은 실행하지 않았다.

기존 실제 REA6.4.0 분석 자료의 13개 호출 가능 구간과 8개 정적 매핑을 대조했다. summary_wh→wh, summary_pic→pic, summary_pjt→pjt 소비자와 담당자 pic→PIC/emp_cd 보조 매핑을 확인했다. 이 소비자는 상세 조회 조건 전달 근거이며 원본 서버 GROUP BY·합계 공식의 증거로 확대하지 않는다. 일반 aggregate_not_null은 옵션이 활성화됐을 때 비어 있지 않은 조건이 하나 이상인지를 검사한다. 별도 $$summary의 첫 축·중복 검사를 현재 $$aggregate의 확정 규칙으로 적용하지 않았다. 현재 후보의 중복 제외와 빈 앞·중간 조건 허용은 직접 UI에서 확인했다. 현재 폼의 구체적인 validator 등록은 미확인이다. 새로운 원문 수집·REA 실행은 없고 누적 코퍼스는 72개·12,121,611B로 유지한다.

## 자체 정책과 합격 조건

- 품목·거래처는 기존 행 식별자와 행 거래처 우선순위를 유지한다. 창고·담당자·프로젝트는 자체 전표의 warehouse·employee·project를 각각의 등록자료 코드로 묶는다. 이름이 같아도 코드가 다르면 구분한다. 미지정 선택값은 미지정 그룹으로 표시하는 자체 정책이다.
- 지원 축 다섯 종류에서 최대 다섯 조건을 선택한다. 초기 네 칸을 모두 채우면 다섯 번째 칸을 보이고, 지우기로 줄이지 않으며 다시작성에서 초기 네 칸으로 되돌린다. 빈 자리는 건너뛰되 선택된 축 순서를 보존한다. 모든 칸이 비면 조회를 막는다. 중복 축을 후보에서 비활성화하고 핵심 조회에서도 거부한다.
- 지우기는 해당 칸만 비운다. 다른 칸의 해당 축 후보를 다시 활성화하고, 지운 축을 사용하는 대기 정렬 기준을 제거하며 알린다. 성공한 과거 조회는 다음 검색 전까지 출력 기준으로 보존한다.
- 기존 할인·세금 반올림 후 행별 수량/금액을 한 번씩 합산한다. 다른 통화를 한 결과로 합치지 않는다. 창고·프로젝트 조건과 취소 전표 제외를 먼저 적용한다. 원본 합계·소계 공식의 재현을 주장하지 않는다.
- 마지막 성공 조회의 최대 다섯 축과 현재 미조회 조건을 별도로 보관한다. 수정 후 재조회와 CSV·인쇄는 성공한 결과의 열·순서를 사용한다. 조회 전용 권한에서 업무 자료를 수정하지 않는다.

## 검증과 잔여 범위

합성 자료 신규 검사 아홉 개와 기존 보고서 검사로 단독 다섯 열·네 축 여덟 열·다섯 축 아홉 열, 실제 코드 매핑, 이름 충돌, 미지정 그룹, 필터, 금액 보존, 빈 칸·중복·최대 수 검증, 지우기와 후보 복구, 축 정렬 해제, 성공/대기 조건 분리, 실제 InventoryUI의 조회 전용 5축 CSV·인쇄를 검증한다. 배포 전 전체 결과는 validation.json에 기록한다. 관리 브라우저 연결을 사용할 수 없어 인증된 호스팅 업무 QA는 미수행이며 jsdom 검사와 구분한다. DB 스키마·저장된 자료 형식 변경은 없다.

각 원본 축 옆의 btn-asc와 btn-add-sum은 정렬 방향·소계 관련 별도 컨트롤로 확인했으나 이번 범위에 연결하지 않았다. 현재 자체 정렬창은 기존대로 사용할 수 있다. 선택 후보/자동추가 구현과 서버 상한의 정확한 소스 연결, 추가 축 종류, 축별 방향/소계, 원본 소계 행·상세 이동·기간 비교·그래프·설정 영구 저장, 전역 759개 경로와 버튼별 동등성은 남아 있다.
