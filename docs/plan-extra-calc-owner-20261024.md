# 소요량·이익 계산의 현재 입력창 확인

## 기존과 변경, 이유

0.89.3 다음 계획 OWN-EXTRA-CALC-PREVIEW-LIFECYCLE을 따른다. 소요량 계산/F8·기준 변경과 판매 이익 보고·목표 단가 미리보기는 적용 검사 전에 이전 DB/초안을 읽는다. BOM구분 변경은 검사 오류 대신 다시 계산 안내를 표시할 수 있다. 왜 변경하는가: 적용만 막아도 다른 계정/권한·저장본·닫힌 입력창의 자료로 계산 결과를 계속 만들 수 있기 때문이다.

조회·계산 전 현재 부모 입력창/계정·회사·역할·권한·저장 원문을 확인한다. 실패하면 소요량 계산 결과와 이익 보고/목표 단가 결과를 지우고 사용자 제품 목록·부모 초안·저장 자료를 보존한다. BOM구분 안내는 현재 입력창일 때만 표시한다. 최초 표시 전 초기화와 독립 조회 전용 이익 미리보기는 유지한다. BOM/원가·금액 계산 규칙과 저장 schema는 바꾸지 않는다.

## 검증 및 배포 경계

실제 발주요청/판매 입력창에 연결한 7가지 무효화·닫힌 callback·정상 복구·제품 목록 보존·초안만 적용·조회 전용 검사를 합성 재현한다. 실제 셸 발주요청 소요량/판매 이익 보고·목표 단가를 390/1280px에서 확인한다. 운영 releaseeb8df3a에서 격리0.89.4 후보를 만들며 root전체빌드·미배포 VAT/매핑 설치와 원본 조작은 하지 않는다. 관련 검사/전체 verify:local/자체 REA6.4 후 커밋·push·기존 WSL/Supabase/Cloudflare 배포·계정/자료/양식/서버/메일 보존을 확인한다. 원본 전체동등성 완료로 처리하지 않는다.
