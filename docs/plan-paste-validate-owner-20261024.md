# 웹자료 미리보기·입력 검증의 현재 입력창 확인

## 기존과 변경, 이유

0.89.4 다음 계획 OWN-ENTRY-PASTE-VALIDATE-LIFECYCLE을 따른다. 웹자료올리기 전체 행 검증/미리보기와 EntryTools.validate는 부모 입력창·계정/회사/역할·권한·저장본이 바뀐 뒤에도 DB/초안을 읽었다. 실제 입력 검증 버튼은 필수항목 검사부터 실행해 이전 계정의 입력 오류나 검증 완료를 표시할 수 있었다. 왜 변경하는가: 저장/적용만 막아도 이전 자료로 검증 결과를 만들 수 있기 때문이다.

미리보기 전에 기존 dialog.current를, 독립 검증에는 전달된 assertCurrent를 사용한다. 실제 입력 검증은 필수항목 읽기 전에 부모 소유자를 확인한다. 무효하면 결과·성공 요약을 지우고 미리보기 적용을 비활성화하며 붙여넣은 원문·부모 초안·저장 자료를 보존한다. 정상 계정 복귀 후 다시 검증할 수 있고 독립 조회 전용 미리보기/검증도 유지한다. CSV 파싱·가격·업무 저장 규칙/schema는 바꾸지 않는다.

## 범위와 검증

실제 발주요청 입력창에 연결한 로그아웃/계정/회사/역할/권한/외부 저장본/부모 종료, 닫힌 callback·텍스트/처리방식 수정·복구·정상 초안 적용·조회 전용 검증을 합성 재현한다. 원본/운영 자료 저장은 하지 않는다. root inventory-ui에는 미배포 VAT/매핑 코드가 있어 운영26d12da 기반 격리0.89.5 후보에는 verify의 한 줄 보호만 이식한다. EntryTools는 운영 기본 파일과 일치함을 확인하고 수정 파일을 복사한다. root전체빌드·미배포 VAT/매핑 설치 금지다.
