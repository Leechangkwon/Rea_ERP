# 단가 확정 → 발주서 저장/재조회 연결

## 확인한 차이와 원본 근거

- 공식 교육 EC-VID-13917 04:04: 요청가50,000과 별개로 확정가25,000을 발주서에 적용.
- 원본 단가요청조회 → 도움말 → FAQ 「단가요청을 불러와 발주서를 입력 하려는데, 거래처 값이 안보여요.」 답변: 단가확정된 내역에서 거래처 표시.
- 공식 FAQ 영상 U83Wl1X6jKQ 00:42 확정 선택, 00:57 발주서의 단가요청 피커에 확정 거래처와 6,000 표시. 원본 업무 행 편집·저장 없이 도움말만 조회.
- 현 구현 entry-core 후보/적용과 InventoryCore.convert가 요청가만 복사하며 비교자료를 보지 않음. 빈 원본 거래처 필터/머리항목과 필수거래처 검사 충돌.

## 이번 구현 계약

1. 비교자료가 있는 단가요청은 현재 원본과 일치하는 ready 상태에서 확정가·확정 거래처를 행별 투영한다. 미확정/요청가 확정 행은 거래처를 추정하지 않고 사용자의 발주 거래처를 유지한다. 비교자료 없는 과거 원본은 기존 동작을 보존한다.
2. 거래처 필터와 표시를 확정행 기준으로 연결한다. 서로 다른 확정 거래처를 한 발주서에 섞지 않고 사용자가 행을 골라 분리한다. 최저가/첫 거래처 자동 선택 없음.
3. 후보 조회→적용→첫 저장에 비교 수정번호와 원본 상태를 재검사한다. 저장된 발주는 비교 선택 변경으로 자동 가격 변경하지 않는다. 기존 발주 수정/취소/복원·백업 보존.
4. 실제 sourceLineId만 잔량 연결에 사용한다. 중복 품목·공백 포함 라인 ID 보존. 잔량 합산은 기존 원본행 기준 유지.
5. 비교 원문 가격 문자열은 근거에 보존. 기존 숫자 저장형에서 정확히 왕복하지 못하는 가격은 조용히 반올림하지 않고 적용을 거절한다. 전역 금액 엔진은 이번 변경 범위 밖.
6. 피커 내용복사/잔량연결, 목록의 후속 발주 생성, 편집기 원본 선택 경로 모두 동일 계약 사용.

## 검증/종료

합성 단가요청 생성→회신→확정→발주 피커→부분수량 저장→새로고침/백업 재조회→부분 구매→잔량 대사. 변경된 비교/원본/권한/다른 화면 저장에서 초안과 기존 자료 유지. 과거 비교 없는 자료·양식·메일 보존. 후보에서 관련 Node와 실제 InventoryUI 브라우저 후 전체 회귀1회, 검증된 운영 커밋 기반 격리 후보만 배포.

미확인: 원본 미확정행 실제 저장·요청가 확정의 거래처 지정 세부 정책, 다중거래처 자동분리·유효기간·할인. 이번 보존 정책을 원본 전체 동등성으로 선언하지 않는다. 전체 매뉴얼 완료0 유지.

## 구현 후 보존 검토

확정 근거가 있는 품목/거래처 코드 변경은 현재 명시 거부한다. 근거만 옛 코드로 남겨 백업 재조회 또는 기존 발주 수정이 실패하는 회귀를 막는 자체 보존 제약이다. 향후 코드 별칭/이력 이관 계약 확정 뒤 확장한다. 기존 비교자료 없는 원본의 거래처 상속/필터는 유지한다.
