# 품목 찾기·정렬·할인 미리보기의 현재 입력창 확인

## 기존과 변경, 이유

0.89.2 다음 계획 OWN-ENTRY-TOOLS-PREVIEW-LIFECYCLE을 따른다. EntryTools의 품목 검색·정렬·할인율 미리보기는 적용 검사를 거치기 전에 DB/초안을 읽는다. 실제 할인 버튼은 EntryExtraUI.openAmount로 연결되며 같은 미리보기 누락이 있다. 기존 할인율 창은 ExtraUI가 없는 경우의 지원 경로로 구분한다. 왜 변경하는가: 마지막 적용만 막아도 다른 계정/역할이나 변경된 저장본으로 이전 창의 조회·계산이 계속될 수 있기 때문이다.

부모 입력창·계정/회사/역할·권한·저장 원문을 조회/미리보기 전에 확인한다. 실패하면 이전 표·금액 요약을 지우고 부모 초안/저장 자료·품목 선택과 수량은 보존한다. 품목 체크/수량의 무효한 이벤트는 내부 선택을 바꾸지 않고 원래 값으로 복구한다. 최초 표시 전 초기화와 독립 조회 전용 컴포넌트는 유지한다. 금액 계산 규칙과 저장 schema는 바꾸지 않는다.

## 검증과 배포 경계

실제 부모와 연결한 7가지 무효화, 보조창 종료, 정상 상태 복구, 품목 선택/수량 보존과 조회 전용 미리보기를 합성 검증한다. 실제 셸에서 품목 찾기·정렬·금액조정을 390/1280px로 확인한다. 운영 releasee6ba161에서 격리0.89.3 후보를 만들며 root전체빌드·미배포 VAT/매핑 설치와 원본 조작은 하지 않는다. 관련 검사/전체 verify:local/자체 REA6.4 후 커밋·push·기존 WSL/Supabase/Cloudflare 배포·계정/8전표/양식/서버/메일 보존을 검증한다. 기존 PRD/P1의 보존 수정이며 원본 전체동등성 합격으로 확대하지 않는다.
