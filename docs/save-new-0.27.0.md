# 저장/신규와 모달 초안 0.27.0

발주요청·계획·발주서·구매의 저장/신규를 연결했다. 저장 성공 후 현재 등록된 기본값과 자체 입력 양식의 기본값으로 새 입력을 연다. 검증이나 저장에 실패하면 현재 입력을 유지한다. 다른 신규 초안과 기존 전표의 연결 자료를 구분하고 모달의 새 전표 키·제목·닫기 기준을 갱신한다.

## 원본 관찰과 실제 REA 근거

원본 네 입력 화면의 저장 화살표만 열고 fresh AX와 visible DOM으로 전체 목록을 확인했다. 요청·발주서·구매는 저장/전자결재·내용유지·신규 세 항목, 계획은 내용유지·신규 두 항목이다. 자체 계획 메뉴에서도 미관찰 전자결재 항목을 제거하고 나머지 외부 전자결재는 계속 비활성으로 둔다. 실제 저장 옵션이나 주 입력행을 조작하지 않았으며 구매조회로 돌아와 저장 도구·팝업이 사라진 것을 확인했다. 회사 기록·세션은 보관하지 않았다.

기존78본문의 실제 REA6.4.0 근거39개에서 V3 saveNew와 V56 CreateNewInventorySlipUserAction의 성공 후 신규 입력 재진입을 대조했다. V56은 원래 NEW에서는 현재 요청으로, UPDATE에서는 GET_CREATE로 다시 읽으며 특정 바코드 옵션을 명시 보존한다. 거래처·날짜·품목행·양식 등 일반 필드의 보존/초기화와 페이지별 override·서버 응답, 자체 바코드 상태와의 정확한 대응은 미확인이다. 자체 ‘현재 기본값으로 새 입력’ 정책을 원본 필드 동등성으로 주장하지 않는다.

웹자료올리기의 직접 진입 본문에는 임시저장 호출이 없지만 외부 openWindow·팝업 본문·원본 입력의 전역/blur 이벤트가 미확인이다. 원본에서는 해당 도구를 열지 않고 주 입력행·자동 초안 제한을 유지했다. 새 GET·원문 실행·원본 본문 추가는 없으며 누계78본문과 기존 부분·시간/메모리 중단을 유지한다.

## 자체 동작과 합격 조건

- 신규/수정 문서를 한 번 저장한 뒤 기존 ID를 다음 빈 입력에 붙이지 않는다. 다음 명시적인 저장은 별도 전표를 만든다. 빈 새 양식을 다시 저장하면 검증 오류가 나고 추가 기록은 만들지 않는다. 기존 F7·내용유지의 같은 ID 수정은 유지한다.
- 모달을 유지하며 키를 현재 진입 화면의 new로 바꾸고 제목·기준값을 갱신한다. 깨끗한 새 양식은 추가 확인 없이 닫히고 이후 편집은 새 전표 초안에만 보관된다.
- 같은 진입 화면에 별도로 보관한 신규 초안이 있으면 기존 문서의 저장/신규를 저장 전에 차단한다. 일부 수정만 저장하지 않으며 기존 신규 초안과 현재 수정값을 모두 유지한다. 신규 창에서 초안을 저장하거나 명시적으로 다시 작성해 정리한 후 재시도한다.
- 위 흐름의 검사에서 기존 다시작성 후 모달 기준을 갱신하지 않아 빈 양식이 수정 초안으로 다시 저장되는 문제를 발견했다. 거절 시 현재 값은 유지하고, 확인 후 재렌더된 값으로 baseline/dirty를 갱신해 닫을 때 빈 초안을 재생성하지 않는다.
- 저장된 연결/생성 전표의 sourceId/sourceLineId·planGeneration/planAllocations는 유지한다. 다음 새 입력은 연결을 물려받지 않아 수량·품목을 정상 편집한다. 현재 등록 기본값·양식은 계속 적용한다. 조회 전용·실행 중 권한 상실·검증·저장 공간 실패·오래된 수정은 현재 입력과 저장 자료를 보존한다.

신규 합성 검사16개와 기존 관련29개, 집중45개가 통과했다. 네 입력의 주 화면/모달·실패/권한, 두 명시적 저장의 별도 ID, 새 초안 재개, 별도 초안 충돌의 저장 전 차단/해결, 생성 발주서 배분과 새 입력의 연결 분리, 기본값/최신 수정 충돌, 다시작성 거절/확인/닫기 기준을 검증했다. 독립 검토 및 다시작성 수정 재검토에서 확정 결함을 발견하지 않았다. 전체 결과는 validation.json에 기록한다. 스키마·저장 형식 변경, 원본 저장 및 인증된 호스팅 업무 QA는 없다.

원본 저장/신규의 정확한 필드·바코드 옵션 보존과 서버 규칙, 웹자료올리기·전자결재·다른 입력 보조, 보고서 소계/비교/서버 집계/정렬·설정과 전역759경로의 버튼별 동등성은 남아 있다.
