# 전체 API 매뉴얼 0.5.1

사람이 읽는 설명서: `/api-manual`. 업무·서비스 15개와 소유자 관리 11개, 총 26개 동작을 수록합니다. 이카운트 매뉴얼에서 관찰한 28개 표시 항목과 양방향 대조 링크를 제공합니다. 원본 세션 주소는 포함하지 않습니다.

ERP 화면의 로그인·로그아웃은 `/login`과 상단 계정 메뉴에서 제공합니다. Sites의 `/signin-with-chatgpt` 및 `/signout-with-chatgpt`로 최상위 페이지를 이동하며 회사코드·아이디·비밀번호를 받는 자체 인증 API는 만들지 않습니다. 인증된 HTML에는 실제 Sites 사용자 표시명만 넣고 `private, no-store`로 반환합니다.

계약 데이터는 `dist/api-manual-data.js`이며, 설명서 화면과 기계용 명세 `/api/v1/openapi.json`이 같은 목록을 사용합니다. 관리자 전용 동작은 일반 연동 키로 호출할 수 없습니다. 기계용 명세의 `x-owner-session-required`를 확인하고 Sites 소유자 로그인 세션에서 실행합니다. OpenAPI만으로 관리 세션 인증을 자동 구성하지 않습니다.

판매 변수 대조는 의미 대응표입니다. 날짜·코드·행별 키 변환과 제공자별 인증·구조 변환을 하는 어댑터는 아직 없으며 실제 이카운트 호출을 검증하지 않았습니다. 문서를 읽는 동작은 API 호출이나 업무 자료 변경을 실행하지 않습니다.

# API 연동센터 0.4.0

Self-Customizing의 정보관리 → API인증키발급 또는 환경설정 → 매핑센터에서 사용합니다. 조회·입력 API, 필드 대응, 수신 작업함, 송신 대기함과 재고 대사를 제공합니다.

## 자료와 인증

기존 재고 화면은 브라우저 저장소를 유지합니다. 연동 API는 사이트의 D1에 별도 가상 자료를 보관합니다. 서버 샘플 준비, 브라우저 자료 복사와 서버 자료 받기는 명시적으로 실행합니다. 자료 복사는 미리보기와 현재 수정 번호 검사를 거칩니다. API 처리 기록이 생긴 업무 영역의 자료 교체는 중복 방지 기록과 전표 참조를 보존하기 위해 차단합니다. 새 업무 영역과 별도 복구 도구는 후속 단계입니다.

비공개 사이트 접근은 Sites가 관리합니다. 로그인한 소유자는 화면에서 시험할 수 있습니다. 비사용자 호출자는 `OAI-Sites-Authorization: Bearer <Sites 서비스 접근 자격>`과 `X-Api-Key: <이 앱에서 발급한 키>`가 모두 필요합니다. Sites 자격은 사이트 소유자의 호스팅 관리 기능으로 설정하며 브라우저 코드에 넣지 않습니다. 앱 키만으로 호스팅 접근 통제를 통과할 수 없습니다.

API 키는 SHA-256 해시로 보관하고 원문은 발급 시 한 번만 제공합니다. 권한은 `read`, `write`, `events:process`로 나눕니다. 만료는 1~90일이고 폐기하면 즉시 차단합니다. 소유자 로그인과 함께 키로 시험해도 해당 키의 권한을 적용합니다. 관리 API는 소유자의 사이트 로그인만 허용합니다. 현재 소유자 전용 접근 범위를 여러 사용자로 넓히기 전에 별도의 역할별 인가를 추가해야 합니다.

## 공통 API

| 경로 | 방식 | 권한 | 기능 |
| --- | --- | --- | --- |
| /api/v1/items | GET / POST | read / write | 품목 조회·신규 등록 |
| /api/v1/partners | GET / POST | read / write | 거래처 조회·신규 등록 |
| /api/v1/warehouses | GET | read | 창고 조회 |
| /api/v1/documents | GET / POST | read / write | 전표 조회·신규 입력 |
| /api/v1/stock | GET | read | 품목·창고별 현재고 |
| /api/v1/events | GET / POST | read / write | 수신 작업 조회·등록 |
| /api/v1/events/{id}/process | POST | events:process | 수신 검증·전표 반영 |
| /api/v1/logs | GET | read | 작업 요약 이력 |
| /api/v1/capabilities | GET | read | 공식 기능 대응과 우리 API |
| /api/v1/status | GET | read | 서버 상태와 자료 수정 번호 |
| /api/v1/openapi.json | GET | read | OpenAPI 3 문서 |

입력 자료는 `application/json`입니다. 공통 전표에는 `type`, `date`, `warehouse`, `partner`, `lines` 등을 사용합니다. 판매 예:

```json
{"type":"sale","date":"2026-10-15","partner":"C001","warehouse":"W001","lines":[{"item":"P001","qty":2,"price":20000}]}
```

새 자료 입력에는 `Idempotency-Key`가 필수입니다. 같은 API 키와 중복 방지 키로 같은 자료를 보내면 최초 결과를 반환하고 다른 자료는 409로 차단합니다. 중복 기록은 자동 만료·제거하지 않습니다. 서비스 키를 교체할 때는 최초 작업 결과를 대사하고 외부 작업 번호를 유지하는 별도의 연결별 수신 정책이 필요합니다. 현재 중복 범위는 API 키 또는 로그인 소유자 단위입니다.

새 품목·거래처 API는 기존 코드를 덮어쓰지 않습니다. 전표 ID·금액 합계·진행 상태는 호출자가 지정하지 않고 기존 업무 검증으로 계산합니다. 이 단계에는 수정·취소 API가 없으며 기존 브라우저 전표의 모든 변환·작업 기능을 공개 API로 제공하지는 않습니다.

## 수신과 송신

수신 이벤트는 `eventType: document.create`, 외부 `eventId`, `data`와 선택적인 `profileId`를 받습니다. 연결별 필드 매핑으로 바꾼 자료를 대기함에 보관하고 처리 버튼 또는 처리 API로 검증합니다. 실패 이유와 시도 횟수를 남기며 완료된 수신 작업의 재처리는 기존 전표 번호를 반환합니다. 수신 자료를 바꾸려면 새로운 외부 이벤트 번호가 필요합니다.

입력된 전표는 송신 대기함에 이벤트를 만듭니다. `internal` 대상은 서버 내부 수신 시험이며 실제 외부 통신이 아닙니다. 외부 HTTPS 송신은 운영자가 Sites 런타임 설정에 `OUTBOUND_ALLOWED_HOSTS`와 `CONNECTOR_이름` 비밀값을 설정한 뒤 연결 프로필이 그 비밀 이름을 참조해야 가능합니다. 토큰 원문은 프로필·브라우저·로그에 저장하지 않습니다. 쿼리 문자열·URL 내 인증정보·리디렉션 전송은 차단합니다.

송신은 수동 실행이며 10초 제한과 동일한 이벤트 번호의 `Idempotency-Key`를 사용합니다. 네트워크 실패·5xx는 상대의 반영 여부가 불명확하므로 `unknown`으로 두고 재전송을 차단합니다. 처리 중 서버가 중단된 작업도 자동 재전송하지 않습니다. 상대 시스템의 결과 확인과 복구 도구는 다음 단계입니다. 일정 실행과 자동 발송은 아직 없습니다.

## 이카운트 대응 근거

[이카운트 공식 Open API 안내](https://www.ecount.com/kr/ecount/product/erp_open-api)를 2026년 10월 15일 확인했습니다. 공개된 17개 항목 가운데 14개는 우리 공통 API의 기능에 대응하고, 매출/매입 회계·근태·게시판 3개는 미구현으로 표시합니다. 공식 항목의 입력/조회 방향과 우리 API 경로는 구분합니다.

실제 이카운트 로그인 후 세부 매뉴얼의 인증·요청 URL·필드·요청 제한을 대조하기 전에는 이카운트 호환 연결이 아닙니다. 원본 계정의 업무 쓰기는 수행하지 않았습니다. API 대조표와 재고 수량 대사는 서로 다른 기능입니다.

## 개발과 한도

`npm run db:generate`로 생성한 SQL·메타데이터를 함께 보관합니다. `npm run build`는 기존 정적 자원을 포함한 Worker ESM을 생성하고 Sites가 배포 시 D1 마이그레이션을 적용합니다. 실행 중 테이블을 만들거나 바꾸지 않습니다.

`npm run dev:api`는 127.0.0.1:8781에서 로컬 SQLite와 개발용 소유자 식별을 사용합니다. 키를 제공하면 키 권한을 검사합니다. 이 식별은 호스팅 Worker에 포함되지 않습니다. 로컬 개발 서버는 이 컴퓨터의 검증 전용입니다. 실제 호스팅 DB·접근 검증과 별도입니다.

검증 저장소는 한 개의 가상 업무 영역에 대해 수정 번호를 조건으로 원자적 갱신합니다. 저장 상태 1.5MB, 수신 300건, 중복 기록 1500건, 송신 이력 200건, 키 50개 한도입니다. 송신 보관 한도에서는 새 전표 입력을 차단하며 미전송 작업을 버리지 않습니다. 여러 회사·대량 처리·권한 분리·이력 장기 보관은 분리 테이블과 운영 정책을 갖추는 후속 단계입니다. API 서버 JSON 백업은 업무 자료만 포함하며 키·연결 설정·처리 이력 전체 복구용 DB 백업은 아닙니다.
