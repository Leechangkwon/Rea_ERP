# 발주서 Gmail 발송 개발

사용자가 실제 발주서 이메일 기능을 Gmail로 구현하도록 지시했다. 기준은 운영 0.44.1 / f7e722f이며 기존 계정·회사·브라우저 업무자료·Supabase API 자료와 Cloudflare 구성을 보존한다. 테스트 중 공급처로 실제 메일을 보내지 않는다. 원본 서비스의 Email 발송을 실행하지 않고 자체 Gmail 기능을 구현한다.

발주서 조회에서 선택한 같은 거래처의 발주서를 Email로 열어 수신자·제목·본문·발주서 PDF를 검토한다. 서버가 고정 Gmail SMTP/TLS로 발송하고 사용자에게 Gmail 서버 접수(최종 수신/열람과 구별)·명시 실패·결과 불명확 상태를 표시한다. 서버의 기존 app_state CAS에 사용자별 요청 ID/요청 해시와 발송 메타데이터만 보관해 동시 중복 전송을 막는다. 발송 중·결과 불명확한 요청은 자동 재시도하지 않는다.

Gmail 계정/앱 비밀번호는 기존 사용자 전용 런타임 설정에만 저장한다. UI·소스·DB·로그에는 비밀번호/토큰을 넣지 않는다. 발신 계정은 설정된 한 계정으로 고정한다. 설정 검사에서는 SMTP 인증만 확인하고 메시지를 보내지 않는다. 사용자가 별도로 발신 Gmail 주소를 알려주는 동안 화면·서버·검증을 먼저 완성한다.

메일 API는 기존 앱 세션·회사 범위·inventory.read/write·동일 Origin·CSRF·요청 크기 제한을 적용한다. 수신자는 단일 주소, 같은 거래처 전표만 묶고 임의 첨부 파일/URL/HTML은 받지 않는다. 브라우저에 보관된 선택 전표의 구조화 스냅샷만 서버로 보내 PDF를 생성한다. 앱 비밀번호 설정은 외부 설정을 보존하는 숨김 로컬 입력 도구로 처리한다.

검증: 상태/미연결/권한/CSRF, 잘못된 수신자·수량·전표/헤더 주입·다른 거래처 혼합·첨부 한도, 같은 요청 동시 전송 1회·상충 요청·네트워크 결과 불명확·권한 변경·저장 실패, 한글/긴 품목/페이지 나눔 PDF 실제 렌더, 합성 Gmail 전송·UI·저장 자료 보존. 전체 verify:local, REA 자체 변경 분석, 커밋/푸시 후 기존 운영 경로에 반영하고 실제 Gmail 인증 여부와 실제 발송 여부를 따로 기록한다.

Gmail 설정은 메일 요청 시작 시 한 번 읽어 그 요청의 발신 계정/비밀번호를 고정한다. 설정 후 Email 창을 다시 열면 바로 반영되며 ERP 재시작은 필요 없다. 기존 저장소 설정은 실행 중인 값을 유지하고 Gmail 설정 오류가 ERP 로그인/업무 서버 기동을 막지 않는다.

## 현재 검증·운영 상태

전체 verify:local이 통과했다. 메일 신규 Node 14개, Chromium 신규3개/전체12개가 포함된다. 추가로 실제 Node HTTP에서 Gmail 미연결 상태의 PDF 생성/다운로드와 브라우저 다운로드까지 통과했다. PDFium으로 1쪽/7쪽 문서를 렌더해 한글·마지막 품목과 실제 배치를 확인했다. REA는 dist/worker 4개에 대해 입력·결과 해시와 근거를 검증했고 의미 그래프 unknown/잘림 없음이다. 기존 분석 어댑터가 scripts를 받지 않아 Node 런타임은 node --check·실행 검사로 구분했다.

0.45.0 / a2b8256을 원격 main에 올리고 기존 관리 서버를 재시작했다. 공개 HTTPS 버전과 익명 메일 접근 401을 확인했다. Supabase 두 상태의 본문·수정 번호, 계정/비밀번호 해시·회사·설정·역할이 동일하며 새 메일 레코드는 없다. 기존 ERP 계정의 로그인 유지와 운영 Email 작성창·첨부 목록·샘플 발주서 PDF 다운로드를 확인했다. 확인창을 닫고 선택을 해제했으며 전표 저장/수정이나 실제 발송은 하지 않았다. 이후 사용자 제공 앱 비밀번호를 숨김 TTY로 받아 실제 SMTP 인증 성공 후 비공개 설정에 저장했다. npm run gmail:check가 configured/authenticated=true, sendsEmail=false로 통과했고 설정 파일 600/폴더 700·기존 비메일 설정 보존을 확인했다. 서버 재시작 없이 운영 Email 창의 발신 계정·첨부 목록·최종 확인과 확인 전 발송 차단을 확인했다. 계정/비밀번호 해시·회사·설정·역할은 동일하며 재로그인으로 lastLoginAt·sessions·attempts·audit·loginLogs만 갱신됐다. 새 메일 기록은 0개이며 실제 발송은 하지 않았다. 자세한 현재 상태는 evidence/gmail-purchaseorder-20261019.json을 따른다.
