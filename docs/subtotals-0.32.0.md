# 구매 집계 소계 0.32.0

집계조건 옆 소계 버튼으로 각 축의 소계를 켜고 끕니다. 검색(F8) 후 표·CSV·인쇄에 반영하며 총합계와 그래프의 원래 숫자는 중복 합산하지 않습니다.

## 사용 예와 합격 조건

품목별·거래처별을 선택하면 기본 소계가 켜집니다. 두 축의 소계를 끄고 조회하면 일반 집계와 총합계만 남습니다. 한 축을 끄면 그 축의 경계로 소계를 나누지 않고 켜진 축의 경계만 비교합니다. 조건을 바꾼 뒤 검색하지 않고 출력하면 마지막 성공 결과를 출력해야 합니다. 구매실에서 전표를 고친 후 돌아오면 성공 조건으로 소계를 재계산하고 아직 검색하지 않은 버튼 상태는 보존해야 합니다.

## 원본 관찰과 실제 REA

원본 구매현황 두 집계 축의 ON/ON·OFF/ON·OFF/OFF·ON/OFF를 조회 전용으로 관찰하고 ON/ON으로 복원했습니다. ON은 btn-add-sum/, OFF는 btn-unadd-sum/이며 버튼만 누르면 조회하거나 설정을 저장하지 않습니다. 소계는 해당 축의 직전 일반행 표시값과 ‘ 계’를 합친 제목이고 두 축 전체2칸을 합칩니다. 모두 끄면 소계 병합행이 사라지고 총합계는 남습니다. 실제 업무 이름/값/건수는 보관하지 않았으며 저장/설정 적용/출력은 실행하지 않았습니다.

정확한 DOM script[src]의 Flexion 본문을 일반 비인증 GET1회로 추가했습니다. 신규3,995,664B, SHA8f89fd21c49a9d7c1de6245f02c34fbf9c58cd133fdf2bd13f489a84247e5563. 실제 REA6.4 정적 분석은 parse오류0/AST1,052,715노드로 완료됐고 전체 의미 분석은30초에서 중단됐습니다. 실패를 의미 완료로 승격하지 않았습니다. 누계82본문23,596,477B, 정적81완전/1부분·의미76완전/1부분/3시간중단/2메모리중단입니다. 기존81본문 기준과 common OOM도 유지합니다. 새 정적span98개와 이전common12참조는 검증 버튼 수가 아닙니다.

새 본문의 WidgetDLTBuilder/data_generator 공급 경로는 기존 외부 경계를 좁힙니다. Jl은 소계가 켜진 축만 누계에 등록하고, 입력 순서에서 최초 변경된 활성 축부터 뒤→앞으로 내보내며 끝의 잔여도 뒤→앞으로 처리합니다. 꺼진 상위 축만 달라지면 하위 소계가 나뉘지 않습니다. ql은 해당 축과 직전행을 제목 resolver에 전달하며 cs는 켜짐 수가 아닌 선택된 전체 축 수로 제목을 합칩니다. Ul은 외부 Decimal.add를 사용하며 이 경로에 명시적 반올림은 없습니다. 현재 런타임 바인딩·서버 GROUPBY/정렬/세금 계산·Decimal 정밀도·동적 양식 전체와 CSV/인쇄 동등성은 미확인입니다.

## 자체 구현과 검증

최종 자체 정렬 결과의 인접 행을 활성 축만 비교해 소계를 삽입합니다. 원래 rows/records는 그대로 두고 표/출력용 행을 따로 만듭니다. 총합계는 원래 일반행 summary를 사용하고 그래프도 원래 records만 사용합니다. 수량/금액의 기존 자체 반올림 정책은 원본 Decimal 동등성과 구분합니다. 정렬로 같은 그룹이 떨어지면 전역 재집계하지 않고 각 인접 구간 소계를 표시합니다.

새로 선택한 축의 소계는 ON이며 지우기/재선택도 ON입니다. 직접 호출과 이전 스냅샷에 소계 배열이 없으면 OFF로 복원해 기존 소계 선택을 만들지 않습니다. 축 사이 빈칸과5번째 축의 소계 배열을 함께 압축합니다. 표/인쇄 제목은 선택 축 전체를 합치고 CSV는 제목 다음 축을 빈 셀로 채워 열 개수를 맞춥니다. 원본 기본 이름/미지정 포맷과 자체 코드/이름 표시는 다를 수 있습니다.

성공 결과와 대기 중 버튼 상태를 복사해 각각 보관합니다. 조회 실패 때 출력 결과를 바꾸지 않습니다. 조회 전용 화면은 저장 내용을 바꾸지 않으며 저장 형식/DB 스키마 변경은 없습니다. 독립 검토에서 금액 소수 자릿수 인쇄 회귀를 발견해 수량/금액 구분으로 수정하고 검사를 추가했습니다. 자동 검사 수와 완료 로그는 subtotals/validation.json에 기록합니다. 호스팅 로그인 업무·실기기 시각 검증은 미완료이며 전체 ERP 동등성 완료를 뜻하지 않습니다.
