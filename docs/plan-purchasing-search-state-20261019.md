## 합격 조건과 직접 수정 범위

원본 관찰·기존 공개 REA 입력/결과 해시 검증·자체 재현·독립 구현·합성 검사·운영 확인을 구분한다. 직접 대상은 dist/inventory-ui.js·dist/purchasing-plan-list-ui.js와 관련 Node/jsdom/localhost Playwright 검사다. 저장 모델과 계정/설정/메일 전송 코드는 바꾸지 않는다.

조건을 입력하는 동안 현재 결과·상태탭 건수·선택·CSV는 성공 조건을 사용한다. 검색(F8)/빠른Enter만 적용하며 F3/상태탭/메일 상태 갱신/양식 재표시는 대기조건을 적용하지 않는다. 역전 날짜는 오류를 알리고 이전 결과·선택을 보존한다. IME/조합·수정키/반복·모달 단축키를 구분한다. 목록 재조회 후 적용/대기 조건·열 양식·선택·스크롤과 계획 미저장 변경/원본 충돌 보호를 보존한다. 읽기 전용은 검색만 허용하며 저장 자료가 바뀌지 않는다.

원본 피커/상태/서버 의미를 추정해 새 필드를 채우지 않는다. 관련 검사를 통과한 뒤 전체 verify:local·릴리스·빌드·REA 근거 검증, 버전0.48.0/커밋·푸시 후 기존 수동 서버 반영·읽기 전용 운영 확인·관리페이지 갱신을 진행한다. 합성 자료는 운영에 넣지 않고 운영 전표 저장/발송은 하지 않는다.

## 구현·로컬 검증 완료

원본 재로그인 후 네 조회의 F3/F8·검색 적용 후 접힘과 현재 열 구조를 값 없이 재관찰했다. 자체 기존5개 실패를 재현한 뒤 수정했고 관련Node92/신규9·합성브라우저22/신규2·최종전체verify:local·릴리스4를 통과했다. 문서/API/푸터 버전 메타데이터도0.48.0으로 맞췄다. 큰 원본2번들 의미 그래프는 부분 상태로 보존하고 검색 액션/브리지 AST 범위를 원본 해시와 연결해 추가 분석했다. 원본86누계는 그대로이며 자체2파일도 해시/근거 검증했다. 현재 커밋/푸시 후 기존 수동 서버 반영과 읽기전용 운영 확인을 진행한다.
