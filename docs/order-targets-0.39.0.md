# 발주서 집계대상 0.39.0

발주서 일반 현황에서도 수량·공급가액·부가세·합계 표시 열을 선택합니다. 기존 발주계획 선택창·태그·부분 열/CSV/인쇄와 같은 자체 구현을 사용합니다. 요청/구매의 집계대상은 계속 비활성입니다.

## 사용 예와 합격 조건

품목명[규격]/거래처 두 축에 부가세만 선택하면3열, 소계/합계 제목은 앞2칸 병합, 숫자는 금액 자릿수로 표시해야 합니다. 대상을 모두 지우고 검색하면6열로 돌아갑니다. 미검색 대상/조회 오류는 기존 출력에 섞이지 않아야 합니다. 부분 입고 후에도 일반 발주 입력량/금액을 유지하며 읽기 전용 조회·CSV·인쇄가 저장 자료를 바꾸지 않아야 합니다.

## 원본과 실제 REA

원본 발주서현황 E040306/메뉴515의 별도 집계대상 후보4개를 확인했습니다. 1축+수량/부가세는3열, 2축+부가세는3열/소계·합계2칸 병합/합계 제목, 전체지우기+2축은6열이었습니다. lookup 적용은 임시 조회 조건이며 원본 설정저장/업무저장/주입력행/출력은 실행하지 않았습니다. 회사 자료/세션URL을 보관하지 않았고 집계대상을 지운 뒤 내역/F8로 복귀했습니다.

기존 실제REA ESG016R initProperties의 aggregateInfo.isTargetUse, 메뉴515/FromProgramIdE040306과 공유header REPORT_TARGET→Seq 목록 전달을 연결했습니다. 근거는 order-aggregate/order-status-extension-contract.json과 aggregate-targets/aggregate-target-contract.json입니다. 실제Seq/동적ColumnForm/현재 출력·비교기간·서버 수량/세금 소비자는 미확인입니다. UI 순번을 자체ID/원본Seq로 단정하지 않습니다.

## 자체 정책과 검사

0.38의 자체 target 선택/취소/태그 제거·복사/복원·부분열 서식을 발주서에 허용합니다. 기존17축/2칸 증가/prefix 경계/말단 소계 생략/합계를 유지합니다. 수량/금액은 입력 발주 행의 effectiveLineTotals이며 구매 입고량을 차감하지 않습니다. 원본 전체발주/잔량 식을 확인했다는 뜻이 아닙니다.

새 핵심2개/UI1개/실제 모듈 통합1개로 부분 입고 후 수량·부가세 투영, 금액 첫 열 정밀도, 전체지우기 복귀, 마지막 성공 CSV/인쇄와 저장 무변경을 검사합니다. 검사 수/해시는 order-targets/validation.json에 기록합니다. DB/저장 자료 구조는 바꾸지 않았습니다. 누계84본문25,247,564B와 기존 OOM/timeout/grid 부분 상태를 유지하며 신규GET/의미분석 재시도/원문 실행/비공개API는 없습니다. 원본Seq·동적양식/다른 대상·비교/그래프/서버/출력 동등성 및 호스팅 로그인 업무 검증은 남아 있습니다.
