# 구매관리 원본 대조 0.8.0

원본을 로그인된 브라우저에서 직접 보고 공개 JavaScript의 REA 정적 분석과 대조했다. 회사 전표·입력값·설정은 저장/삭제/취소/발송하지 않았다. 원본의 기본/회사 적용양식은 우리 데이터 모델과 구분한다.

## 반영한 범위

- 발주요청 입력: 헤더 공급처 제거, 품목행별 거래처와 안정적 행 식별자. 확인과 진행 상태를 분리한다.
- 발주계획 조회: 품목행별 열, 수량/단가 변경, 선택 행별 진행/완료와 잔량. 원본은 목록 변경 즉시 서버 저장이므로 관찰 중 변경하지 않았다. 자체 앱은 변경 저장과 명시적 확인을 요구한다.
- 발주서/구매 조회: 원본 관찰 열과 탭, 하단 공통 작업. 행별 작업 열 제거. 구매에는 미확인/확인만 노출한다.
- 발주계획·발주서·구매 입력: 관찰한 헤더/품목열/보조 기능/하단 배치를 반영하고 기존 독립 입력 보조를 연결한다.
- 현황 4종: 초기 검색→결과, 요청/계획/발주서의 문서·품목 이중 머리글, 구매의 직접 관찰 회사양식 `신규_주간` 19열. 날짜/창고/프로젝트/품목/거래처 검색, CSV와 인쇄 미리보기.
- 기존 v2 백업을 유지한다. 새 독립 상태/행 ID는 선택적 필드이며 기존 item 기준 연결이 있는 문서는 키를 바꾸지 않는다. 마감·연결수량·회계반영·지급 보호를 유지한다.

## 근거 및 한계

공개 원본 계획 목록 33,512B(SHA256 21833c77aa981b176f1123bbe4f6988552d4c56fe990cd2b32857dd76302affe), 공통 현황 1,030B(SHA256 6bdc598e619328fe08e0d0fa8211b5d3c8c3ba777dc876863ed7d12621806dce), 구매 목록 735B(SHA256 91d2c28c453a12b3e114b570fc81e9ea59380549665a4084f6be3a0afce83a63)를 rea-agents6.4.0 라이브러리로 실제 정적/의미 분석했다. 파싱 오류0. AST 합계9,004. 작은 화면 모듈은 공통 프로그램으로 위임하므로 서버 전체 구조의 분석 완료를 의미하지 않는다. 이전 0.7.2 공통 동작 모듈의 분석도 참고한다.

CLI는 호스트 프로세스 소유 확인(`ps: fatal library error, lookup self`) 경로가 실패한다. 가드를 우회하지 않고 직접 라이브러리의 순수 정적 분석만 사용했다. 원본 코드를 실행하지 않았다.

미확인 동작은 추정하지 않았다. 집계 구분/기간 비교의 결과, 회사별 관리항목·거래유형·시리얼 상세 검색, 낱개/박스 환산, 첨부 엔진, 저장 하위 분기, 삭제/복구·이력·일부 업로드는 미구현 또는 비활성이다. 외부 메일·메신저·전자결재·지급은 연결하지 않았다. 구매의 지급/할인/미구매/회계미반영 등 보조 화면은 기존 기능을 유지했으며 이번 전체 대조 완료에 포함하지 않는다.

거래유형과 자체 VAT 세율은 다른 개념이다. 거래유형은 미연결 표시하고 VAT는 별도 로컬 계산 영역에서 편집한다. VAT 포함 단가와 금액은 자체 계산 기준임을 표시한다. 원본의 미검증 단위 변환 값을 만들어내지 않는다.

검증은 합성자료 자동 검사와 supervisor 브라우저에서 수행한다. 호스팅 앱 계정 로그인 이후 업무와 실휴대폰/인쇄/스캐너 검증은 별도 미실행이다. 브라우저 업무자료와 서버 D1 API 자료는 별도다.
