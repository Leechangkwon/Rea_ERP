## 구현과 합격 조건

- PO→구매 + 내용복사 + 라인별은 원본 행마다 별도 새 행을 추가한다. 동일 품목/단가/적요/추가항목도 합산하지 않는다. 기존 입력 행의 수량·단가·custom·순서와 기존 lineId를 보존하며 새 행에는 충돌하지 않는 문서 로컬 ID를 부여한다.
- 원본의 lineId는 importedFrom.sourceLineId로만 추적한다. 내용복사는 sourceId/잔량 소비 연결을 만들지 않는다. 이전 0.56의 추가항목 명칭 매핑도 유지한다.
- 기존 요청←주문 라인별 규칙을 같은 append helper로 재사용한다. 다른 전표/품목별/잔량/재고 불러오기 경로를 변경하지 않는다.
- 후속 전표가 있는 lineId 없는 과거 구매는 초안에서 ID를 재배정하지 않고 명시 거부한다. 이미 안정적 lineId가 있는 구매/후속 자료는 기존 참조를 보존한다. 이 과거 자료 보존 제한은 자체 정책이다.
- 합성 절차: 동일 품목 발주2행 → 기존 구매 초안1행 + 라인별 복사2행 → 취소/적용 → 구매 저장/재조회 → 기존 구매에 다시 복사/저장/재조회. 각 행·단가·custom·원본 provenance·재고/채무·발주 잔량과 기존 양식을 대사한다.
- 관련Node와 단일 브라우저 절차 후 VAT 연구를 제외한 분리 후보 전체검사/배포/기존 로그인 및 자료보존을 확인한다. 전체 매뉴얼 합격0과 모아 인증대기 유지.
