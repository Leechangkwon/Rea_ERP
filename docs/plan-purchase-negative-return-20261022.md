# 구매 복사반품의 음수 입력 연결 · 2026-10-22

## 다음 단위 · 0.63.0 이후 확인상태·반영 후 읽기

원본 구매조회는 전체/미확인/확인 탭과 진행상태변경의 미확인/확인을 제공한다. 메뉴만 관찰하고 선택·저장하지 않았다. 기존 반품 매뉴얼은 반품을 음수 구매로 같은 구매조회에서 재열도록 설명한다. REA는 호환용 purchasereturn/credit를 같은 조회에 투영하지만 confirmation 명령 대상에서 제외해 오류가 나고, accounted=true이면 양수 일반 편집기로 되돌아간다. 기존 양수 저장/음수 표시와 배분금액을 보존하며 이 두 연결만 고친다. 원본의 반품 상태변경 서버 결과·실제 회계전표 생성은 미확인이다.

차감반품에만 기존 확인/진행 상태 검증과 transition을 연결한다. 교환반품·다른 전표는 확장하지 않는다. 신규 상태 변경은 명시 확인 뒤 저장하고 기존 상태 없는 반품/백업은 자동 변환하지 않는다. 기존 미확인 제외·수불·채무·반품 잔량·원자적 오류/반영전표 수정금지 정책을 재사용한다. 계정/회사/조회·쓰기권한/원문/저장소/닫힌 모달을 저장 시 재검사한다. 양식 재표시 때 선택된 차감반품도 유지한다.

회계반영된 차감반품은 저장 수량과 고정 배분금액의 음수 읽기 전용 상세로 연다. 저장·행 제외·날짜 편집·회계반영/취소 액션을 추가하지 않는다. 원구매가 현재 미확인이어도 보존된 반품 내용을 조회하며 원구매를 재계산하지 않는다. 닫기·Escape·F8은 업무자료를 쓰지 않는다.

합격: 구매→부분 차감반품 저장→확인/미확인 명시 변경→새로고침→목록/현황·재고/채무·잔량 대사→확인 복원, 기존 원구매/양식/고정금액 보존. 혼합 선택의 원자성·초과복원·accounted·교환·권한/CAS/늦은 이벤트와 양식 재표시 선택 보존을 검증한다. accounted fixture의 음수 읽기/닫기/키보드 불변을 별도로 확인한다. 운영0.63.0 기반 격리 후보에서 전체 회귀 후 push/배포·기존 로그인/자료/양식/서버/메일 보존을 확인한다. 운영 반품0건이므로 반품 저장/반영 후 상세는 합성 검증과 구분한다.

선행 부서 조건 조사: 원본 정보불러오기→부서등록→일치→비교대상은 부서코드/부서명 등록 피커와 신규 버튼이다. 선택/신규/함수적용/설정저장 없이 닫고 미저장 예외를 폐기했다. 자체 safeUser/publicContext/user.save에는 부서/직위/직책 저장 필드와 등록 참조가 없어 사용자등록 계약 확장이 선행되어야 한다. 이번 반품 단위에 추정 속성을 추가하지 않는다.

## 범위와 근거

원본 도움말 EC-HELP-PURCHASE-RETURN / EAM012M_937173820665의 구매번호 → 반품처리 → 음수 수량 수정 → 저장·재조회 절차를 구현한다. 기존 검토 본문과 ProcessReturnInventoryProgram 정적 분석 근거를 재사용하며 원본 저장은 하지 않는다. 초과반품·직접 음수 구매·혼합부호·가격수정·환불 정책은 이 본문만으로 확정하지 않는다.

0.58.0의 구매현황 연결 다음 단계다. 원구매에 연결한 복사반품부터 진행하고, 직접 음수 입력은 별도 계약으로 남긴다. 이번 단계는 원구매 없는 음수 purchase 저장을 허용하지 않는다.

## 내부 저장 결정

기존 purchasereturn/credit를 유일한 저장 전표로 유지한다. 신규 입력 화면은 수량과 고정 금액을 음수로 표시하고 저장 경계에서 처리수량을 양수로 변환하여 기존 convert/document 명령에 전달한다. 별도의 음수 purchase를 동시에 저장하지 않는다. 내부 전표 종류 일치는 원본 매뉴얼의 관찰 조건이 아니며, 사용자에게 보이는 절차·금액·재고·재조회와 원구매 보존으로 평가한다. 기존 양식·백업·메일·반품 참조를 일괄 변환하지 않는다.

세액은 기존 sourceAmounts/returnAmounts의 잔액 배분을 사용한다. 음수에 Math.round를 다시 적용하지 않는다. 기존 반품·교환수량을 함께 빼고, 잔량 초과·원구매/반품 변경·동일 품목의 모호한 행·회계반영 후 수정·초과 지급으로 생기는 음수 채무는 기존 코어의 검증을 유지한다. 이는 호환 보존 정책이며 원본 예외 규칙 합격을 의미하지 않는다. 미완료 VAT 계약 속성이 있는 연구 전표는 명시적으로 거부한다.

## 순서

1. purchase-return-core: 불변 초안 생성·기존 반품 재열기·음수 입력 검증·저장 명령 준비·표시 변환. preview는 복제 자료에서만 실행한다. 저장 직전 원구매/관련 반품 snapshot을 재검사한다. 초안 금액·단가·원본 참조를 외부 입력에서 신뢰하지 않는다.
2. 독립 음수 반품 편집 화면: 원구매/거래처/입고창고 고정, 원본 품목·음수 수량·배분 금액 표시, 품목 제외·날짜 변경·저장/취소/실패 보존. 계정/권한/원문/저장소 충돌을 마지막 저장 경계에서 재검사한다.
3. 기존 구매 상세의 반품처리와 구매조회/현황의 음수 재조회 연결. 기존 일반 구매·기존 반품 편집·양식을 보존한다. 저장형식과 화면형식을 혼동해 양수 반품을 재계산하거나 두 번 차감하지 않는다.
4. 합성 절차: 구매3개/공급15/세액2 → 반품 -1/세액-.67 저장·새로고침 → 반품 -2/세액-1.33 저장·재조회 → 원구매/반품 합산0 및 재고·채무0. 취소·원본 변경·수량 초과·저장 거절·백업 왕복을 검증한다. 전체 후보 회귀·브라우저·REA 후 기존 운영에 배포하고 보존 대조한다.

## 배포 경계

독립 저장 연결 코어만 완성한 상태에서는 운영에 설치하지 않는다. UI/조회/권한/저장 실패/재조회까지 한 절차가 합격한 분리 후보만 버전을 올려 배포한다. main의 VAT5충돌 연구는 포함하지 않는다. 완료 기준은 REQ-PUR-RETURN-001 전체 절차이며, 로컬 연결 코어 합격만으로 완료 처리하지 않는다. 모아 인증 복구 전에는 기존 PRD/아키텍처/로드맵용 갱신 본문을 로컬에 보존하고 게시 성공으로 쓰지 않는다.

## 구현 결정과 검토 반영

신규 전표는 기존 document 저장 명령으로 sourceId가 원구매인 purchasereturn/credit 한 건만 만든다. 원구매의 최초작성일/수정일/작성자는 신규 반품에 복사하지 않으며 미기록 값을 꾸며 넣지 않는다. 기존 반품 수정은 기존 전표/행/custom·memo를 보존한다. 음수 표시 객체는 저장용 객체와 분리한다. 단가·거래처·창고는 편집하지 않고, 품목 제외/음수 수량(기존 6자리 수량 단위)/일자만 이 연결 화면에서 바꾼다. 후속 반품의 추가항목 편집과 단독 양식 인쇄는 미완료다. 구매조회 반품 인쇄는 기존 음수 집계가 있는 구매현황으로 안내한다. 회계반영된 반품의 기존 native 조회는 유지한다. 구매조회 confirmation 변경은 purchasereturn 대상 미지원이며 코어 거절을 완료로 처리하지 않는다.

독립 검토에서 반품 창을 열기 전 계정 전환 시 이전 storageKey에 저장되는 P1을 재현했다. 초기 회사/사용자 identity와 현재 identity, 초기 storageKey와 현재 사용자로 계산한 key, inventory.read를 open/getDb/onCommit에서 재검사하도록 수정했다. 실제 인증 응답의 user.company.code를 사용한다. 동일 재현에서 반품0건·양 계정 저장소 불변을 독립 재확인했다. Playwright는 사용자·회사·중첩 user.company·조회권한 전환을 포함한다. 쓰기권한·저장소 CAS·원구매/관련반품 snapshot도 저장 직전에 확인한다.
