# 입력 보조와 검증결과 0.12.0

구매 입력과 검증창에서 잘못 연결되거나 빠져 있던 공통 동작을 원본 UI와 공개 JavaScript 근거로 보완했다. 전역 메뉴 759개 중 안내 카드 487개, 공통·독립 기능 251개, 부분 전용 경로 21개의 기준은 유지한다. 이번 변경으로 전체 버튼 동등성을 선언하지 않는다.

## 동작과 합격 조건

| 기능 | 사용 예와 구현 | 합격 조건과 남은 경계 |
| --- | --- | --- |
| 입력 찾기 F3 | 현재 입력 행의 선택값·문자·수량을 검색하고 일치 셀 강조. 품목 추가는 별도 버튼 | 원본 searchText는 grid 검색 위젯이다. 조회 전용·연결 전표에서도 검색 가능. 검색 입력이 전표를 변경하거나 제출하지 않음. NFKC·부분일치 비교는 자체 정책이며 원본 grid 엔진 세부 규칙은 미확인 |
| 검증결과 | 전표수량과 검증수량이 다른 행만 별도 읽기 전용 창에 표시 | 품목코드, 정책에 따라 품목명·규격, 전표수량·검증수량. 빈 전표와 스캔품목도 대조. 창 닫기 후 스캔 보존, 다시 F8하면 최신 수량 반영. 일치 성공 알림의 원본 문구·후속 흐름은 미확인 |
| My품목 기본 로드 | 회사·앱 사용자·입력 종류별 기본그룹을 바로 불러오기 | 첫 그룹으로 임의 대체하지 않음. 기본그룹 부재 알림. 사용중단 품목·계정 전환·동시 설정 변경·조회/연결 초안 변경 차단. 기존 개인그룹 저장 형식 유지 |
| My품목설정 | 기본 로드 옆 화살표에서 별도 설정창 열기 | 검증 부모창과 스캔 행을 보존하며 취소. 부모 닫기 시 하위창 정리. 원본 탭명·그룹명·기본과 저장 F8·My코드설정·닫기 관찰. 우리 설정은 개인 브라우저 그룹 편집이며 원본 서버 공유그룹 전체 구조와 다름 |
| 기본수량 바코드 | 합산기본수량과 개별기본수량 선택 | 합산은 바로 앞의 동일 품목 행만 처리. A/B/A 입력이 첫 A에 합쳐지지 않음. 개별은 새 행. 입력 전표는 이동·시리얼 관리·다른 창고 행 합산 차단. 가격·행 메타데이터 보존 |
| 검증 바코드 | 같은 두 기본수량 방식을 독립 스캔 행에 적용 | 이름·규격을 수정한 다른 변형 행을 덮어쓰지 않음. 검증 대조는 합계 기준. 원본 장비 스캐너 이벤트·직렬/음수수량·전체 포커스 규칙은 미검증 |

원본의 합산추가수량·개별추가수량은 UQTY와 exch_rate, 규격식 및 수량 소수자리 설정을 참조한다. 우리 품목 분자·분모와 원본 필드 대응이 입증되지 않아 이번에는 추가수량 모드를 제공하지 않는다. 검증창의 기존 찾기 반복 이동과 세 단계 정렬은 자체 비교 엔진이며 원본 공유 grid 엔진과의 세부 동등성은 남아 있다. My품목 기본그룹을 행에 삽입하는 원본 소비자도 미확인이다.

## 원본 관찰과 임시초안 정리

원본 검증창에서 빈 구매 전표와 별도 검증행을 대조하면 검증결과 창이 열리고, 기본 정책에서 품목코드·전표수량·검증수량과 닫기만 표시됐다. 검증 다시 작성은 별도 행을 초기화했다. 바코드를 켜면 네 수량 모드가 보였다. My품목 기본그룹 미등록 알림과 My품목설정의 열·버튼을 확인하고 저장 없이 닫았다.

비교를 준비하며 원본 구매 입력에 확인용 품목을 선택했을 때 임시저장 표시가 나타났다. 업무 저장은 누르지 않았다. 즉시 다시 작성으로 입력을 비우고 이번에 생긴 임시초안의 삭제만 실행했다. 삭제 전에는 없던 임시초안 알림이 제거되고 빈 구매 행으로 돌아온 것을 확인했다. 이후 원본 주 입력행 편집을 중단하고 조회·팝업·공개 코드 분석으로 범위를 좁혔다. 원본 회사 업무전표 저장·발행·송신·설정 저장은 실행하지 않았다. 실제 품목값·가격·회사자료·세션 URL은 근거와 앱에 보관하지 않는다.

## REA 근거

이번 신규 원문 11개를 실제 rea-agents 6.4.0으로 정적·의미 분석했다. VerificationResult, inventory.function 4개, core/group 5개, contentsloadslip 위젯 1개다. 모두 파싱 오류 0이며 원본 코드는 실행하지 않았다. 기존 원문과 SHA256으로 중복 제거하면 64개·9,481,177B이다. 정적 완전 63개·부분 1개, 의미 완전 62개·부분 1개·시간 중단 1개다. 기존 upbalance 파싱 오류 4개와 menu 의미 분석 시간 중단을 완전 분석으로 바꾸지 않는다. 액션 후보 4,082개는 이전 49개 원문 기준 수량이며 버튼 검증 수량이 아니다.

정확한 URL·해시·소스 위치·미해결 호출은 `evidence/global-rea-20261018/entry-toolbar/`에 있다. 부분 결과·원본 외부 호출은 미확인으로 남긴다. 원문과 대용량 IR은 배포 자원에 포함하지 않는다.

## 검사와 배포

관련 합성 UI·계산 검사 74개가 통과했다. 최종 전체 검사·릴리스·빌드 결과는 같은 근거 폴더의 validation.json에 기록한다. 관리형 로컬 브라우저 도구가 없어 실제 호스팅 앱에 로그인한 업무·휴대폰·장비 스캐너 검증은 남아 있다. jsdom/Worker 검사와 원본 UI 관찰을 그 검증으로 대체하지 않는다. 저장 스키마·DB 마이그레이션·기존 audience·앱 인증 정책은 변경하지 않는다.
