# 기초등록 미완성 숫자 입력의 전환·초안 보존

0.89.8 다음 OWN-MASTER-NUMBER-TRANSITION이다. HTML number의 입력 중 `1e`는 value가 빈 문자열이고 validity.badInput은 true다. 기존 추가 숫자/품목 read는 이를 거절하지만 양식 선택은 formActivate 저장 후 repaint에서 읽어 설정만 바뀔 수 있다. 일반 기초등록의 기본 숫자 필드는 raw 초안에서 빈 값이 될 수 있다. 닫기는 read 예외를 처리하지 않아 사용자에게 이유를 안내하지 못한다.

왜 변경하는가: 브라우저가 공개하지 않는 미완성 숫자를 명시적 빈 값으로 취급하거나, 읽지 못한 초안과 다른 양식을 저장하면 안 된다. 양식 변경/편집 진입 전에 초안 읽기를 선행하고, 닫기/이동은 값을 완성하거나 직접 비울 때까지 입력 요소와 이전 설정을 유지하며 오류 필드에 돌아갈 수 있게 한다. 일반 기초등록 기본 숫자도 동일하게 검증한다. 원문을 복원한다고 주장하거나 문자열을 추측하지 않는다. ItemUI 설정 저장에 같은 후행 read 순서가 확인되면 저장 전 snapshot으로 이동한다.

합성 Chromium의 실제 키 입력으로 390/1280px, 품목/거래처/창고·외화·자원 등 기본/추가 숫자를 검증한다. 수정 전 실패·수정 후 저장명령0/설정 byte동일/동일 input 요소와 badInput 유지/닫기 안내·명시 수정/비움/양식 변경/초안 재개/저장·재조회, 기존 계산식과 계정 보호 회귀를 확인한다. 원본 로그인/쓰기·운영 업무/설정 저장0이다.

운영409b28a 기반 격리0.89.9 후보에 검증한 함수만 이식한다. root전체빌드 금지·미배포 VAT5/매핑 보존. 관련 Node·실제 셸 합성 브라우저·필요 전체 회귀·자체 REA 후 기존 운영에 배포하고 백업/계정/8전표/양식/서버/메일 보존을 별도 검증한다. 모아0.89.0 승인 문구는 저장·재조회25 완료. 16문서 일괄안은 별도 승인 대기이며 heartbeat를 승인으로 간주하지 않는다. 전체 매뉴얼 완료0 유지.

추가 확인: 양식설정 진입의 snapshot 예외도 안내·입력 유지로 처리한다. 기존 assertCurrent의 계정·역할 거절 예외 계약은 보존한다. 왜: 숫자 입력 안내를 위해 기존 권한 검사를 삼키면 안 되기 때문이다.

자체 리뷰: 품목 설정 callback 전 read 검증을 추가하되 callback 후에도 최신 read를 유지한다. 왜: 비동기 사용자가 callback 대기 중 입력한 값을 오래된 snapshot으로 덮어쓰면 안 되기 때문이다. 일반 등록 저장 오류는 추가항목뿐 아니라 기본 숫자 필드에도 초점을 돌린다.

## 다음 독립 검증 범위

이번 master snapshot 보호와 별도로 ItemUI.inputSettings의 readSettings는 기본값 control을 value(field, defaultControl)로 읽고, 순서 이동은 그 결과로 곧바로 다시 그린다. 다음은 해당 숫자 기본값에 실제 native badInput을 입력했을 때 순서 이동·저장·취소가 미완성값을 빈 값으로 바꾸는지 재현한다. 확인 전 완료 처리하지 않는다. 왜: 등록 자료의 초안과 품목 설정의 기본값 초안은 서로 다른 보존 경로이므로 이번 검사를 그대로 합격 근거로 사용할 수 없기 때문이다. 새 설계 문서를 중복 생성하지 않고 이 계획에 이어 기록한다.
