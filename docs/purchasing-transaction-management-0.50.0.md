# 거래유형·관리항목 · 0.50.0

구매조회 Search(F3) → 거래유형 다중 선택 → 적용 → 검색(F8), 발주요청조회 Search(F3) → 관리항목 다중 선택 → 적용 → 검색(F8)을 지원한다. 관리항목 팝업은 코드/이름 검색·사용중단포함·닫기 취소를 제공한다. 품목 조건과 관리항목 조건은 같은 행에서 일치해야 하고 전표는 한 번만 표시한다. 팝업 적용은 대기 조건만 바꾸며 성공한 검색 전까지 기존 결과/CSV/선택을 보존한다.

구매 네 입력의 거래유형은21 부가세율 적용/22 부가세율 미적용과 기존 값을 선택한다. 자체 로컬 계산에서 신규22/22로 명시 변경은 세율0,21로 돌아가면 확인된 적용 세율을 사용한다. 예전 코드·미기록 값을 추정해 분류하지 않으며 기존22 전표의 세율/금액도 백업·무변경 저장에서 보존한다. 원본의 품목/창고/회사 설정 우선순위 및 직접 세율 전체 동등성은 미확인이다.

관리항목 등록자료는 기존 masters.controls를 그대로 쓴다. 입력 화면 Option → 양식설정 → 품목 BODY 양식 → 관리항목 표시 → 양식 저장·적용 후 품목행에 선택한다. 기본은 숨김이므로 기존 양식/열 순서를 바꾸지 않는다. 기존 입력 양식의 읽기 전용·숨김·기본값도 유지한다. 신규 코드는 사용 중 항목만 허용하고, 기존 전표의 중단 코드는 편집 시 보존한다. 관리항목 코드 변경은 기존 품목행 참조도 갱신한다.

원본 관찰은 분리 조회 팝업/공개 코드만 사용했고 원본 입력행/저장/설정 저장을 조작하지 않았다. 공개 코드4작은 범위와 팝업2개, 자체 수정3파일을 고정REA6.4.0으로 파싱/해시/근거 검증했다. 자체 큰 UI 전체 의미그래프는 일부 생략됐고 변경10범위는 생략 없이 보완했다. 외부 바인딩과 원본 서버/인쇄/결재/품목별 관리항목 사용조건은 남아 있다.
