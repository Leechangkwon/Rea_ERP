# 구매 저장 후 내용유지 0.14.0

구매 입력의 저장 옵션에서 저장/내용유지를 활성화했다. 저장이 성공하면 저장된 전표를 다시 읽어 같은 번호의 수정 화면을 연다. 수정 후 다시 저장해도 새 전표를 만들지 않는다. 다른 구매 입력 종류의 저장 옵션, 저장/신규, 저장/전자결재와 지급은 이번 활성화 범위에 포함하지 않는다.

## 근거와 동작

원본 E040303의 하위 메뉴에 저장/내용유지가 있는 것을 직접 관찰했다. 버튼을 실행하지 않고 현재 DOM이 참조한 공개 footer 두 본문과 기존 inventory.function_1 소비자를 실제 REA6.4.0으로 분석했다. inventory footer의 save_review → execSlipSaveReview → saveType=saveReview가 공통 저장 파이프라인을 사용하고, 완료 후 저장 응답 또는 현재 원본 날짜·번호를 Key로 전달하며 EditMode=modify로 같은 페이지에 재진입한다. 자원 키와 관찰 문구의 대응은 위젯·소비자 흐름에 근거한 추론이다. saveReview/saveNew 분기는 isPopup 닫기 분기보다 먼저다. 실제 submitPage의 모달 처리와 원본 서버의 전표 재조회 결과는 미확인이다.

근거는 `evidence/global-rea-20261018/entry-sort/footer-save-contract.json`, `footer-precise-source-evidence.json`, `footer-branch-order-clarification.json`에 있다. 누적 공개 원문은 고유66개·9,628,494B로 유지한다. 모든 신규 호출의 동적 연결과 서버 업무를 복원했다는 의미가 아니다.

우리 구매 화면은 같은 저장 검증·권한·재고·연결 잔량·브라우저 저장 처리를 사용한다. 저장 성공 후 반환된 전표로 입력을 다시 그려 정규화된 값을 보여 주고, 상세창의 전표 번호·수정 제목·변경 비교 기준·초안 보관 키를 갱신한다. 실패하면 기존 입력과 자료를 유지한다. 저장 이후 추가로 수정한 초안은 저장된 전표에 연결해 보관하며, 새 전표 입력에 그 내용이 섞이지 않는다. 별도 입력 메뉴에서도 저장된 식별자를 보관해 메뉴를 이동하고 돌아와 같은 전표를 수정할 수 있다.

## 합격 조건

| 흐름 | 확인 사항 |
| --- | --- |
| 신규 → 저장/내용유지 → 수량 변경 → 내용유지 재저장 → F8 | 같은 번호 한 건 유지, 재고는 변경분만 반영, 마지막 F8에서 상세창 닫기 |
| 저장 직후 닫기 | 불필요한 미저장 경고 없음. 다시 신규를 열면 빈 입력 |
| 저장 후 미저장 수정 → 닫기 → 같은 전표 열기 | 수정 초안을 같은 전표에 복원, 다시 저장해도 중복 생성 없음 |
| 입력 메뉴 → 내용유지 → 메뉴 이동/복귀 | 저장된 번호로 수정 재개 |
| 빈 품목·권한 회수·저장공간 실패 | 저장·화면 전환 차단, 입력과 이전 자료 보존 |
| 연결 구매 | 원본 연결·행 금액·잔량·품목 변경 잠금 보존 |

이 아홉 신규 합성 검사와 기존 구매 입력 검사13개가 통과했다. 최종 전체 검사·릴리스 결과는 `evidence/global-rea-20261018/save-retain/validation.json`에 기록한다. 원본 업무 전표·설정은 저장하지 않았고 회사 자료를 복사하지 않았다. 호스팅 ERP 로그인 후 업무·실휴대폰/스캐너는 미검증이다. 브라우저 업무와 D1 API 자료의 분리, 백업 형식과 DB 스키마는 유지한다.

다른 업무창이나 목록에서 같은 전표를 저장하면 이전 초안의 기준 전표와 비교해 저장을 차단한다. 현재 초안의 값은 보존하고 최신 전표 다시 읽기에서 취소/확인을 선택할 수 있다. 구매실의 상세 전표를 편집한 후 주 입력을 다시 그려도 저장된 번호를 잃지 않도록 부모 초안을 먼저 보관한다. 본인이 F7로 저장한 경우에도 저장 결과와 비교 기준을 갱신해 거짓 충돌이나 중복 전표가 생기지 않게 했다. 신규 입력과 내용유지 후 두 흐름을 별도로 검증했다. 이 충돌 검사는 같은 브라우저 앱 세션 안의 독립 정책이며 서버 다중 사용자 수정 번호나 다른 기기 동기화를 대신하지 않는다.

원본 행 번호 링크를 읽으려 클릭했을 때 숫자 입력 모드로 전환되고, 값을 넣지 않았는데도 빈 임시저장 표시가 생겼다. 즉시 다시 작성 후 이번에 생성된 빈 임시초안만 제거하고 배너가 사라진 것을 확인했다. 실제 품목·수량·가격 입력과 업무 저장은 실행하지 않았다. 이후 원본 주 입력행 컨트롤은 조작하지 않고 정적 DOM 읽기·조회 페이지·공개 코드로 조사한다.

## 이어갈 범위

원본 저장/신규는 저장 키를 신규 화면 초기화에 전달하지만 필드별 초기값·복사 규칙은 미확인이다. 신규 화면을 임의로 비우거나 기존 내용 전체 복제로 구현하지 않는다. 원본 보류는 별도 서버 쓰기이고 직접지급은 저장 후 지급과 다른 지급창 경로다. 현재 독립 앱의 세션 초안 보류·인쇄는 원본 동등성 완료로 표시하지 않는다. 전역 메뉴 759개 중 안내 카드487개 등의 기준도 그대로다.
