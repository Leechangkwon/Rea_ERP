분석일: 2026-10-15. 범위: My품목, 전표바코드, 바코드 수량검증, 할인·VAT, 생산소요량, 이익계산·금액조정, 발주계획의 다른 전표 생성, 보류.

## 1. My품목

원본 UI는 입력화면별 기본 그룹을 라디오로 선택한다. 별도 My코드설정 트리에는 개인 전체/개인 현재/공유 현재/공유 전체 범위가 있다. 단일 공통 즐겨찾기 목록만으로 원본 구조를 설명할 수 없다.

`GetListMyProdCodeFavoriteUserAction`은 `widget.code.prod`/`prod_cd` 문맥의 저장 코드를 조회하고 품목 기본정보를 결합한다. `in_sequence_flag:true`로 저장 순서를 보존하며 바코드 동작은 비활성화한 상태로 입력한다.

`xemd001p_01`의 기본 그룹 저장은 `/SVC/Common/Infra/SaveMyProdFavoriteGroup`에 `ITEM_SNO`, `PRG_ID`, `WIGT_CD`, `WIGT_DV_CD`를 전달한다. 화면/위젯 문맥과 선택 그룹이 저장 계약이다.

`favoritecodetreesetup`의 `/SVC/Common/Infra/SaveFavoriteCode` 요청은 사용 여부와 계층형 그룹·품목 목록으로 나뉜다. 원래 프로그램/위젯 문맥, 부모·자식 관계를 보존하고 접근 불가 노드는 저장에서 탈락시키지 않는다. 같은 그룹의 코드 중복은 대문자로 정규화해 비교한다. 공유 그룹 쓰기 권한과 서버 저장 성공은 확인하지 않았다.

독립 구현에서는 회사·사용자·화면 문맥, 순서, 기본 그룹을 보존한다. 실제 공유 데이터 모델과 권한이 없다면 개인 목록을 공유 목록으로 표시하지 않는다.

## 2. 전표바코드

원본 UI는 바코드 입력란, 일자-No./전표/거래처명 결과 표, 선택삭제·닫기를 제공한다. 실제 업무 바코드는 입력하지 않았다.

팝업은 일자+번호로 전표를 식별하고 선택 결과를 `OpenPopupSlipBarcodeUserAction`에 돌려준다. 공통 `GetTransformDataAction`에는 원본/대상 프로그램, 전표 키, 현재 헤더, 입력 모드, 양식, 외화 여부가 전달된다. `isQtyCheckFlag=true`일 때 `balance_type='N'`으로 전체 수량, false일 때 `'Y'`로 잔량을 적용한다. 신규는 불러온 내용으로 대체하고 다른 모드는 기존 자료에 추가하는 분기가 있다.

**스캔 문자열 문법은 확보한 팝업에 없다.** 공통 `barcodeInput` 위젯으로 위임되므로 추측한 문자열을 이카운트 바코드 형식이라고 표현하면 안 된다. 우리 전표번호를 검색·입력하는 기능은 별도의 로컬 계약으로 명시해야 한다.

## 3. 바코드 수량 검증과 입력 모드

검증은 저장 전 필수값 검사와 별개이다. 원본은 전표의 기존 행과 별도 검증 그리드를 비교한다. 검증 화면의 찾기(F3), 정렬, My품목, 바코드, 검증(F8), 다시작성·닫기를 UI에서 확인했다.

`barcodeverification`의 비교 함수는 다음과 같다.

1. 기본 키는 품목코드다. `DES_INC`/`SIZE_INC` 설정에 따라 품목명·규격이 키에 추가된다.
2. 원본 행과 스캔 행을 각각 키별로 모아 **QTY를 합산**한다.
3. 누락·수량 차이는 원본 수량 `SQTY`와 스캔 수량 `BQTY`로 기록한다. 스캔에만 존재하는 품목도 `SQTY=0`으로 기록한다.
4. 차이가 없으면 성공 알림, 차이가 있으면 별도 결과 팝업이다. 원래 전표 수량을 변경하지 않는다. `UQTY`는 이 비교 함수에서 사용하지 않는다.

일반 바코드 입력 모드에서는 수량/추가수량 대상과 합산/개별이 구분된다. 공통 입력 프로그램의 합산은 직전 같은 품목 행을 대상으로 한다. 모든 동일 품목을 전역 통합하는 동작은 아니다. 시리얼 단일수량 정책은 추가 합산을 제한한다. 실제 스캐너 장비 입력은 검증하지 않았다.

## 4. 할인·VAT·반올림

`xesd006p_05` 할인 팝업은 단가 할인과 전표 금액 모드를 구분한다. `discount_gubun='2'`는 전표 공급가 할인, `'3'`은 전표 공급가 목표금액 조정이며 다른 분기는 선택 행의 단가 할인이다. 전표 모드에서는 전체 행, 단가 모드에서는 체크 행을 사용한다.

비율/정액, 반올림·올림·내림 및 계산 자리수를 받는다. 전표 정액할인은 기본공급가 비율로 배분하고 마지막 행에 잔여 차이를 더한다. 할인액과 최종 공급가액, VAT 포함/별도 단가가 각각 존재한다. 적용 결과는 `ROWKEY`별 단가·공급가·VAT 및 전체 할인액·합계를 부모 창에 반환한다.

세율 우선순위는 전표 고정 세율 사용 여부를 먼저 보고, 그 외에는 품목별→창고별→입출고 전역 세율이다. 할인창의 VAT는 공통 계산기로 재계산된다. 전체 VAT 계산기의 회사별 반올림·전표별 배분 정책까지 분석한 것은 아니다. UI에서 빈 행의 거래별계산을 눌러 외관이 변하지 않았다는 사실은 계산 정확성의 증거가 아니다.

판매 화면의 **별도 금액조정 버튼**과 할인창의 목표금액 모드가 완전히 같다는 근거는 없다. 실제 금액조정 진입 시 입력양식에 합계 사용이 필요하다는 알림을 확인했으며 설정은 바꾸지 않았다.

## 5. 생산소요량과 BOM

`EstimatedBOMUserAction`은 소요량 입력창에서 받은 `ConsumData.Prods`와 BOM 구분을 서버 계산에 전달한다. 결과 적용 옵션은 순서·규격을 보존하며 **기존 그리드를 초기화**한다. 따라서 독립 구현에는 적용 전 교체 안내와 취소 동작이 필요하다.

공개 `xesj003m`은 전표일자·창고·BOM 구분과 품목·BOM·수량·추가수량 등의 입력 정의를 제공한다. 별도 BOM 전개 서비스는 BOM 코드·버전·수량 문맥을 사용한다. 다단계 BOM, 손실률, 단위 변환과 실제 소요량 계산은 서버 영역이므로 현재 소스만으로 원본 수식을 확정할 수 없다.

## 6. 판매 이익

원본 템플릿과 UI에서 이익계산 버튼을 확인했다. 원본 팝업에는 판매금액의 공급가/VAT포함 기준과 FIFO·월별·입고품목·입고 VAT제외 원가 기준이 있다. 확보된 추가 파일은 공통 페이지 코드에 그쳐 정확한 원가 산식·재고층 소비 규칙은 확인되지 않았다.

현재 마스터 입고단가를 사용한 추정이익을 FIFO 이익과 동일하게 표시해서는 안 된다. 독립 구현에서 제공하는 원가 기준과 원가가 없는 품목 처리 방식을 화면에서 구별해야 한다.

## 7. 발주계획 → 발주서 정리방식

원본 UI의 다른전표생성 → 발주서에서 아래 다섯 선택을 확인했다.

| 원본 선택명 | UI 명칭에서 알 수 있는 범위 |
|---|---|
| 거래처별납기일자별라인별 | 거래처·납기별 전표, 원래 행 단위 |
| 거래처별납기일자별품목별 | 거래처·납기별 전표, 품목 단위 정리 |
| 1장라인별 | 단일 전표, 원래 행 단위 |
| 1장품목별 | 단일 전표, 품목 단위 정리 |
| 직접설정 | 설정 진입 제공; 선택 자료가 없으면 진행 제한 |

위 표는 **원본 UI 명칭의 해석**이며 정확한 서버 그룹키의 정적 분석 결과가 아니다. 원본 자료가 없어 생성하지 않았다. 통화·창고·단가·세율 차이에 대한 실제 병합 규칙은 미확인이다. 수집된 `xesg009m`은 구매입력이며 발주계획의 생성 알고리즘으로 인용하지 않는다.

독립 구현에서는 서로 다른 가격·세율·창고·통화가 부주의하게 합쳐지지 않도록 별도 안전 정책이 필요하다. 그 정책을 원본 검증 사실과 구분한다.

## 8. 보류

원본 판매 툴바에 보류가 존재한다. 공개 입력 모델은 `additional_info.hold_target_info`를 전달하며 `USE_HOLD`를 저장 이후 신규 `GET_CREATE`로 전환한다. 정상 저장 이후 별도의 임시저장 자료 삭제도 확인했다.

이는 정식 수불 전표의 상태만 보류로 변경하는 모델과 같다는 근거가 아니다. 원본 보류 저장 API 및 자동 임시저장과의 정확한 관계는 미확인이다. 독립 구현은 사용자별 초안을 정식 전표·수불과 분리해 보관하고 재개하며, 정식 저장에 성공한 후 제거하는 범위로 다룬다.

## 검증 경계

우리 구현의 수량·금액·권한·초안 유지·취소·5000개 품목 성능은 별도 로컬 테스트가 필요하다. 특히 페이지 이동 후 지연된 팝업 적용, 혼합 전표의 연결 수량, 적용 전 취소를 검사해야 한다. 이 문서의 REA 결과는 그 테스트를 대신하지 않는다.

## 0.6.4 구현과 사용법
