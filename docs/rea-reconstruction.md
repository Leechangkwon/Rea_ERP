# REA 근거에 따른 전체 기존 기능 재정비 — 0.6.0

이 기록은 기존 메뉴·재고·양식·API·매뉴얼·로그인과 신규 Self-Customizing을 빠짐없이 기능군으로 분류하고, 원본에서 확인한 근거와 독립 구현·검증을 연결합니다. 검증된 계산 커널은 유지하고, 명령 경계·인증·권한·정책·저장·설정 적용·문서 흐름을 개편했습니다. 모든 줄을 다시 작성했다거나 이카운트 전체와 동일하다는 의미는 아닙니다.

|---|---:|---|

정확한 전체 항목 목록은 `evidence/rea-reconstruction-ledger.json`에 있습니다. 230개 재고 경로, 20종 전표, 31개 Self 화면, 36개 API, 24개 설정 작업, 28개 원본 참조를 각각 열거합니다. 메뉴 구조 자체는 `dist/menus.json`과 `tests/menu-core.cjs`의 759개 검사를 기준으로 삼습니다.

## 실제로 수행한 REA 분석

REA 버전은 `rea-agents@6.4.0`으로 고정했습니다.

1. 원본의 공개 CDN JavaScript 11개, 총 633,493바이트를 인증정보 없이 받았습니다. 로그인, 회사정보, 사용자·권한, 기본값, 접속 현황, 양식, 재고 주문 및 부가세 모듈을 포함합니다. 원본 스크립트는 비활성 텍스트로만 취급했고 실행하지 않았습니다. URL·바이트 수·SHA-256은 `evidence/self-public-sources.json`에 있습니다.
2. 기존 배포 커밋 `66669868c7cdddba2cef4e7172c083682da5169b`의 JS/CJS 14개를 별도 디렉터리에 추출해 전체 애플리케이션 분석을 수행했습니다. 입력 목록과 해시는 `evidence/rea-rebuild-baseline.json`에 있습니다.
3. 재정비한 JS/CJS 18개를 동일한 REA 정적 분석기로 분석했습니다. 전체 결과 예산으로 의미 그래프가 생략된 `inventory-ui`, `app-service`, `gateway`는 각각 별도 분석하여 보완했습니다.
4. `scripts/rea_evidence.mjs`는 REA의 `parseApplicationGraphEvidence`로 분석 증거를 검증하고, 실제 `traceApplicationFeature`, `queryJavaScriptSemanticGraph`, `compareApplicationVersionsEvidenceValidated` 함수를 호출합니다. 단순 문자열 검색 결과를 REA 분석으로 부르지 않습니다.
5. 54개 추적 기록에 모듈 앵커, 로그인 입력 필드, 권한 필드, 부가세 계산, 메뉴 진입, 재고 명령, 양식 검증, API 실행, 매뉴얼 생성, 설정 검증 및 세션 검사를 연결했습니다. 증거 ID·그래프 ID·원본 위치·요약·모호성·미해결 사실은 `evidence/rea-reconstruction-traces.json`에 남깁니다.

원시 그래프는 `.artifacts/rea-*.json`에만 보관하고 배포에 포함하지 않습니다. 추적 파일의 SHA-256으로 해당 분석을 식별할 수 있습니다. 기능 추적에서 모듈·자산 노드를 연결한 사실은 실행 경로의 증명이 아닙니다. 의미 추적의 `ambiguous`·`partial`·`unknown` 상태는 해소된 것으로 바꾸지 않습니다.

### 분석 한계

- 원본 11개 파일과 기존·신규 구현 모두 구문 분석 실패는 0개였습니다. 구문 분석 성공은 동작 성공이나 전체 의미 복구를 뜻하지 않습니다.
- 원본 `ecount.infra.attribute`는 전체 결과 예산 때문에 일부 의미 그래프가 생략됐습니다. 정적 자산·모듈 정보는 남아 있으며 누락을 기능 부재로 해석하지 않습니다.
- 기존 전체 그래프의 `inventory-ui`와 신규 전체 그래프의 `inventory-ui`·`app-service`·`gateway`에는 같은 예산 한계가 있었습니다. 신규 파일별 보완 분석에서 해당 생략은 제거했지만, 동적 속성·호출·분기 등 정적 분석의 미확정 상태는 계속 남습니다.
- REA 버전 대조는 양쪽 그래프가 부분적이므로 일부 항목을 `unknown`으로 분류합니다. 이 값으로 변경 없는 코드가 없었다거나 모든 구현이 새로 작성됐다고 주장하지 않습니다. 파일별 정확한 유지·변경 판단에는 별도 SHA-256 대조를 사용합니다.
- 원본 서버의 비밀번호 저장, 세션, 권한 평가, 트랜잭션, 전표별 예외, 외부 API 결과는 공개 JavaScript에서 확정할 수 없습니다. 해당 부분은 독립 설계와 독립 시험으로 구분합니다.

## 인증 및 데이터 보존 원칙

- 사용자가 회사코드·앱 ID·비밀번호를 직접 정합니다. 기본 비밀번호나 사전 생성 운영 계정을 배포하지 않습니다.
- 현재 소유자 전용 Sites 접근 제한은 호스팅 바깥 관문으로 유지됩니다. 해당 ChatGPT 식별자만으로 ERP에 로그인하거나 업무 API를 호출할 수 없습니다.
- 비밀번호 원문은 로그·브라우저 저장소·배포 소스에 넣지 않습니다. 세션 원문은 보안 쿠키로만 전달하고 저장소에는 해시를 남깁니다.
- 기존 `gateway_state` 업무·API 키·수신·송신 이력을 보존하고 회사·계정·설정은 새 `app_state`에 저장합니다. 데이터 초기화는 별도 권한·확인·수정 번호 검사와 복구를 사용하며 기존 연동 이력이 있으면 중지합니다.
- 원본의 비공개 업무 레코드·인증키·세션 URL·쿠키를 재현 근거에 저장하지 않습니다.

## 재실행 및 최종성 확인

```powershell
python -X utf8 scripts/rea_rebuild.py rebuilt
node scripts/rea_evidence.mjs --focus
npm test
node scripts/check-release.cjs
```

REA 패키지가 자동 탐색되지 않으면 `--rea-package <설치된 rea-agents@6.4.0 디렉터리>`를 지정합니다. 공개 원본 입력을 다시 준비할 때만 `capture`, `original`을 실행하고, 기존 커밋 기준 입력이 필요할 때만 `baseline`을 실행합니다. 기준 커밋을 바꿨다면 비교의 기준이 바뀌었다는 사실도 기록해야 합니다.

릴리스 직전에 `evidence/rea-reconstruction-traces.json`의 `files_changed_after_rebuilt_analysis`가 비어 있어야 최신 전체 분석과 배포 파일이 일치합니다. 원시 그래프·기능 추적·검증 시험·호스팅 결과는 각각의 확인 범위를 유지하며, 분석 범위 밖의 기능을 완료로 올리지 않습니다.
