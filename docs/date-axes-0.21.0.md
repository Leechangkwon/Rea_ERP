# 구매 날짜 집계 축 0.21.0

구매현황 집계에 일별·월별·분기별·반기별·연별을 추가했다. 기존 다섯 축과 함께 열 종류에서 최대 다섯 축을 선택하며 정렬·방향·지우기·CSV·인쇄와 조회 복구에 연결한다. 주차는 회사 달력과 일반 집계 경계가 미확인이므로 지원하지 않는다.

## 원본 관찰과 근거의 범위

원본 후보의 날짜 축을 직접 열고 다섯 단독 조회에서 축 이름, 수량, 공급가액, 부가세, 합계의 다섯 열을 확인했다. 일별을 선택한 상태에서도 다른 날짜 축이 후보에 남았고 일별+월별 조회는 여섯 열이었다. 회사의 실제 날짜·금액·기록을 보관하지 않고 숫자를 가린 표기만 대조했다. 일별은 DDDD/DD/DD, 월별은 DDDD/DD, 분기별은 DDDD/ D분기, 반기별은 DDDD/ 하반기, 연별은 DDDD/ 형태였다. 마지막 슬래시는 실제 관찰한 표기다. 원본 업무·설정 저장은 실행하지 않았다.

기존 공개 원문의 실제 REA 근거24개에서 summary_date_day/month/quarter/half/year와 달력 구간 변환을 찾았다. 이 경로는 집계 행을 눌렀을 때 상세 조건으로 변환하는 드릴다운이다. V5는 data_dt refer_type, V56은 inv_s$data_dt prop_id로 매핑한다. 이를 원본 일반 조회의 prop_id·그룹 키·표시 포맷 구현이나 서버 집계 공식의 증거로 확대하지 않는다. 선택 항목은 동적 템플릿 메타의 prop_id/display_name/refer_type/data_type을 전달한다. 현재 화면의 완전한 메타 연결은 미확인이다.

축별 소계 렌더러를 찾기 위해 추가로 DOM에서 관찰한 공식 공개 모듈 네 개를 각 한 번 무인증 GET하고 실제 REA6.4.0으로 분석했다. uikit 756,271B와 bridge 35,008B는 정적·의미 분석이 완료됐다. ec-lib 103,862B는 정적 완료 후 의미 분석이 2GiB 메모리 한도로 중단됐고 react-for-v5 1,187,329B는 정적 완료 후 의미 분석이 30초로 중단됐다. 같은 전체 분석을 재시도하지 않았다. 현재 집계의 실제 토글 구현은 네 본문에서 찾지 못했고 일반 그리드 ColSort를 해당 컨트롤로 대신 표기하지 않았다.

누계는 SHA 중복 제거한 78본문·19,149,569B, 정적 완전77/부분1, 의미 완전73/부분1/시간중단2/메모리중단2다. 기존 부분 분석과 중단을 보존한다. 새 날짜 조사 자체에는 추가 GET이나 원문 실행이 없었다. 본문 수와 별도 발췌 분석 수, 기존49본문의 액션 후보4,082개를 검증된 버튼 수로 계산하지 않는다.

## 자체 동작과 합격 조건

- 자체 전표의 date를 기준으로 일·월·달력 분기·상하반기·연도에 묶는다. 그룹 키는 각각 YYYY-MM-DD, YYYY-MM, YYYY-Qn, YYYY-Hn, YYYY다. 날짜 키와 표기용 라벨을 구분해 방향·정렬과 기록 대응을 유지한다.
- 표시 라벨은 직접 관찰한 형식을 사용한다. 상반기는 1~6월, 하반기는 7~12월이다. 윤일·3/4월·6/7월·12/1월 경계를 처리하고 잘못된 일자는 거부한다. 이는 자체 날짜 자료 모델의 정책이며 원본 일반 조회 그룹 키의 재현을 주장하지 않는다.
- 날짜·품목·행 거래처 등 축을 조합한다. 날짜·거래처·품목·창고·전표 취소 조건을 먼저 적용하고 기존 행별 할인·세금 반올림 후 금액을 한 번씩 합산한다. 다른 통화 합산은 계속 막는다.
- 새 축은 고유한 정렬 필드 ID를 갖는다. 축 교체·지우기는 사용할 수 없는 정렬을 해제하고 알린다. 성공 조회와 현재 미조회 조건을 별도로 보관하며 수정 후 재조회·CSV·인쇄는 성공 결과의 열·방향·형식을 유지한다.
- 조회 권한에서 날짜 집계와 출력을 사용할 수 있고 저장 권한을 늘리지 않는다. DB 스키마·저장된 자료 형식은 바꾸지 않는다.

## 검증과 남은 작업

신규 합성 검사9개와 관련 집중 검사78개로 다섯 단독 축, 윤년·분기·반기·연도 경계, 필터와 취소 제외, 행 거래처, 방향·정렬·축 교체, 조회 복구, 실제 InventoryUI의 조회 전용 CSV·인쇄를 확인했다. 전체 결과는 validation.json에 기록한다. 관리 브라우저를 사용할 수 없어 인증된 호스팅 업무 QA는 미수행이며 합성 Worker/jsdom 검사와 구분한다.

주차·거래유형·전표·관리항목·라인·품목/거래처/프로젝트 그룹 등 추가 축, 원본 소계 행·상세 이동·정렬 우선순위·서버 공식, 페이지분할·비교·그래프·설정 저장과 전역759개 경로의 버튼별 동등성은 남아 있다.
