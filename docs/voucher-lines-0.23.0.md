# 구매 전표별·라인별 집계 0.23.0

구매현황 집계에 전표별·라인별을 추가했다. 기존 축과 함께 열다섯 종류에서 최대 다섯 축을 선택한다. 전표는 자체 전표 ID, 행은 전표 ID와 기존 안정 행 식별자로 구분한다. 표시에는 자체 전표 일자·번호와 현재 행 번호를 사용한다. 같은 품목의 반복 행도 각각 보존한다.

## 원본 관찰과 REA 근거

원본에서 두 축을 각각 선택해 조회했다. 모두 축 이름, 수량, 공급가액, 부가세, 합계의 다섯 열이었다. 첫 라벨의 숫자만 가린 형식은 전표별 `####/##/## -#`, 라인별 `####/##/## -#-#`이다. 날짜·번호·회사 기록·금액·세션은 보관하지 않았다. 원본 저장·주 입력행 조작은 실행하지 않았다.

기존 실제 REA6.4.0 근거19개를 대조했다. summary_slip과 summary_line은 V5 data_dt, V56 inv_s$data_dt로 드릴다운 검색을 만든다. 해당 날짜 helper 자체는 당일 범위만 만들며 정확한 전표·행 필터는 증명하지 않는다. 별도 비교기간 key extractor의 날짜/전표번호/행순번 조합도 일반 집계 키로 확대하지 않는다. 입력 이동의 data_sid·record_sid와 record_seq_no는 별도 필드이고 행순번에는 위치 기반 포커스 용도가 있다. 원본 안정 식별자와 자체 ID의 동등성은 미확인이다.

free 조건이 summary_line 하나인 경우 checkAggregate는 false를 반환하지만 조회 뒤 계산되는 모드 플래그다. 이를 서버 groups 변경이나 자체 행 키의 증거로 사용하지 않는다. 원본 일반 GROUPBY·선택 축 prop_id/datatype·표시 변환·SID 수명·정확한 드릴다운 범위·서버 합계는 미확인이다. 새 GET·원문 실행은 없고 누계78본문/19,149,569B와 기존 부분·시간/메모리 중단을 유지한다.

## 자체 정책과 합격 조건

- 전표별 키는 기존 doc.id다. 표시하는 날짜를 바꿔도 같은 전표로 유지한다. 서로 다른 전표와 같은 품목은 섞이지 않는다.
- 라인별 키는 JSON으로 구분한 전표 ID, id 태그, lineId다. 전표 사이에 같은 lineId가 있어도 다르다. 안정 ID가 없는 이전 자료는 position 태그와 필터 전 원래 행 번호로 구분한다. 이 이전 자료의 위치 키는 재정렬 뒤 안정성을 보증하지 않는다. 저장 형식 변환이나 ID 생성은 하지 않는다.
- 자체 표시 형식은 기존 구매 상세의 ISO 일자와 전체 전표 ID를 유지하고, 라인별에 ` · N행`을 붙인다. 원본 번호·날짜 형식과 동일하다고 주장하지 않는다. 조회 도움말·성공 결과·인쇄에 REA 번호와 현재 행 번호라는 안내를 넣는다.
- 기본 방향은 표시 일자·전표·행 번호를 한국어 숫자 비교로 정렬한다. 불투명한 lineId가 화면 순서를 정하지 않는다. 명시 정렬이 우선하며 동률에는 기존 축 순서가 남는다. 필터로 일부 행만 보아도 원래 행 번호를 표시한다.
- 필터·취소 제외·자체 행별 할인/세액 반올림 후 금액·통화 혼합 차단, 다섯 축·빈칸 방향·후보 제외·교체 시 정렬 해제, 성공/미조회 조건 복원과 조회 전용 CSV·인쇄를 유지한다. 집계 행의 전표 열기는 연결하지 않는다.

## 검증과 남은 범위

신규 합성 검사9개, 집중 검사84개로 반복 품목·전표 간 같은 행 ID·12행 숫자 순서·날짜 변경·재정렬·이전 위치 키·필터 전 행 번호·명시 정렬과 records 대응·다섯 축·취소 제외·성공/대기 복원·조회 전용 출력과 저장 불변을 검증했다. 독립 검토에서 확정 결함을 발견하지 않았다. 전체 결과는 validation.json에 기록한다. 인증된 호스팅 업무 QA는 미수행이다.

거래처·프로젝트 그룹과 주차·거래유형·관리항목 등 추가 축, 원본 소계·상세 이동·비교·그래프·설정 저장, 서버 집계/정렬과 전역759경로의 버튼별 동등성이 남아 있다.
