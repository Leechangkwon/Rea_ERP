# 구매 집계조건과 다시작성 0.37.0

구매현황의 집계조건5칸을 처음부터 표시합니다. 다섯 번째 칸만 선택해도 집계할 수 있습니다. 같은 조회 모드에서 다시작성을 누르면 마지막으로 성공한 검색조건을 복원하며 표시 중인 결과는 그대로 둡니다.

## 사용 예와 합격 조건

집계조건5에 품목별/내림차순/소계OFF로 조회합니다. F3에서 창고별로 바꾸고 잘못된 기간으로 검색해도 성공 결과가 남아야 합니다. 다시작성은 품목별/내림차순/OFF와 성공 기간을 복원하고 대기 중 그래프 체크/지표는 유지합니다. 다시 검색하기 전까지 CSV/인쇄는 기존 성공 결과를 사용합니다. 이전4칸 스냅샷도5칸으로 열고 없는 소계 플래그는OFF로 유지합니다. 성공 이력이 없거나 모드가 달라졌으면 기존 초기화 정책을 사용합니다.

## 원본 관찰과 실제 REA

현재 구매현황V56의 최초/복귀 집계조건은5칸이었습니다. 다시작성은 선택 축/집계모드를 무조건 지우지 않았습니다. 연별/오름차순/소계ON으로 조회한 뒤 미검색 방향/OFF를 바꾸고 다시작성하면 연별/오름차순/ON으로 돌아왔습니다. 이어 연별/내림차순/OFF로 조회한 뒤 다시작성하면 그 조합을 유지했습니다. 축을 월별로 바꾸고 미검색 상태에서 다시작성하면 마지막 연별/내림차순/OFF로 복원됐습니다. 대기 그래프 체크는 유지됐습니다.

보관 common RewriteSearchUserAction.executeAsync의 같은 마지막 검색 모델ID→마지막 검색 모델 교체, 다른ID→preset/origin 복원 분기를 연결했습니다. 현재 버튼의 실제action binding/modelID를 확인한 것은 아닙니다. 자체는 같은 문서/같은 조회 모드를 같은 모델의 근사 조건으로 사용하고, 나머지 preset/origin의 원본 전체 동등성은 주장하지 않습니다.

현재 그래프와 같은 wrapper/차트/범례 생성 후보도60참조(기존semantic30/static-only30)로 좁혔습니다. 직접 이벤트는 render/hover/tooltip이고 ConfigureGraphOptions의 현재 caller는 확인되지 않았습니다. 설정·종류·지표·랭킹 진입을 추정 연결하지 않았습니다. Option의 검색항목설정/양식설정/조건양식설정/문서발송내역/구매현황OLD만 관찰했습니다. 30개 변환 경고를 취소하고 연도별 그래프를 읽기 전용으로 확인했습니다.

누계84본문25,247,564B는 변하지 않았습니다. 신규GET/의미분석 재시도/원문 실행/비공개API는 없습니다. commonOOM·Flexion timeout·grid5구문오류 부분 상태를 보존했습니다. 원본 저장/설정 적용/주입력행/출력은 실행하지 않았고 업무 자료/세션 URL을 파일에 넣지 않았습니다. 시리얼 검색값의 읽기 전용 입력 시도는 실패해 임시 문자열도 들어가지 않았습니다. 그래프OFF·방향/소계 기본과 일반 현황F8로 복귀했습니다.

## 자체 정책과 검사

구매만 고정5칸과 성공 조건 복원 정책을 적용합니다. 축·방향·소계·검색값·기간·마스터·정렬을 성공 조건 복사본으로 복원하며 다시 조회하거나 결과를 교체하지 않습니다. 그래프 체크와 자체 지표는 대기 값을 유지합니다. 이전 스냅샷의 빈 소계는OFF로 유지하며 반환된 배열/성공 조건은 별도 복사본입니다. 같은 모드의 상세 조회 조건 복원도 자체 모델 정책으로 검사합니다. 원본의 모든 일반필터/정렬/그래프 지표·preset·모델ID를 확인했다는 뜻이 아닙니다.

새5개UI/복원 검사와1개 실제모듈 통합 검사를 추가했습니다. 읽기 전용 CSV/인쇄·메뉴 이동 정리·저장 자료 무변경을 검사합니다. 요청의 고정5칸과 계획/발주서의2칸 증가 정책은 유지합니다. DB와 저장 자료 구조는 바꾸지 않았습니다. 전체 검사 수와 해시는 purchase-rewrite/validation.json에 기록합니다. 그래프 설정/랭킹 진입, 동적 양식/서버/출력 전체 동등성과 호스팅 로그인 업무 검증은 남아 있습니다.
