# 조건양식 ID·화면모드·3조건 AND 저장/재조회

기준: 운영0.60.0/2fb85fe, main84aa73b(미완료VAT5 포함, main 전체 빌드 설치 금지). REQ-COM-FORMS-001과 EAM012M_120422034974 본문, 실제 조건등록/피커를 대조한다. 기존 PRD·아키텍처를 확장하며 새 설계 문서를 중복 생성하지 않는다.

## 확인 범위

원본 단가요청조회 Option > 조건양식설정 > 신규에서 조건1~3, 적용양식, 우선순위를 관찰했다. 항목 피커는 화면모드/ID, 화면모드 값은 PC/MOBILE이다. 입력·저장/설정 저장/업무 행 조작 없음. 구매조회별 항목을 추가 관찰해 범위를 구분한다. 매뉴얼은3조건 AND와 입력/조회/인쇄 적용, 일괄인쇄 첫 전표 조건을 명시한다. 일괄인쇄는 기존 미구현이므로 이번 완료에 포함하지 않는다.

## 저장과 적용

기존 version1 store와 단일 field/operator/value 규칙을 자동 변환하지 않는다. 새 규칙만 conditionVersion1과1~3개 conditions 배열을 명시 저장한다. 사업 필드·로그인 ID·클라이언트 모드를 source로 구분하고 모든 조건이 일치해야 적용한다. 첫 일치 우선순위/컨텍스트/활성 양식 fallback은 유지한다. 기존 규칙의 저장/왕복/우선순위와 미지 메타데이터를 보존한다.

ID는 내부owner key가 아닌 AuthUI.state().user.loginId를 읽는다. 문서 custom/작성자 값으로 대체하지 않는다. 화면모드는 브라우저의 모바일 신호를 사용하고 화면 폭만으로 바꾸지 않는다. unknown 환경은 ID/모드 조건에 일치시키지 않는다. UI/코어가 같은 resolver를 사용하며 runtime 환경은 전표/백업에 저장하지 않는다. 기존 API/서버 권한을 확장하지 않는다.

## 편집과 보호

조건명·사용·양식·순서와 최대3세부조건을 제공한다. 기존 business 조건 연산자는 보존하고 ID/모드 신규 선택은 같음만 제공한다. ID는 직접 입력, 화면모드는 PC/MOBILE 선택이다. 값/조건 오류는 원본 규칙을 보존하며 오류를 표시한다. 신규/삭제/순서/닫기·Escape는 명시 저장 전에는 저장하지 않는다. 읽기전용, 사용자/회사 변경, 닫힌 창/교체된 양식 화면, 저장소 CAS/저장 실패를 차단하고 초안을 보존한다.

## 합격 절차

기존 단일조건이 있는 자료에 새3조건을 작성→취소/보존→명시 저장→reload→로그인ID·모드·업무조건 각각 다른 경우 fallback→입력/조회/인쇄 적용→원전표/기존양식/규칙 보존. 실제 사용자loginId와 internal id 구분, 문서의 가짜환경 필드, narrow PC와 mobile UA, 없는 환경, 실패/늦은 이벤트를 검사한다. 관련Node/jsdom 후 production 기반 격리후보 전체 verify:local·브라우저 확인, REA6.4.0 자체/원본조건 scope의 입력/결과해시/schema 검증. 커밋/push 후 비공개 백업·기존런타임 배포·실제로그인/읽기/보존 확인. 운영에는 업무·양식 설정을 저장하지 않으며 해당 유자료 저장 합격은 합성 검증과 구분한다. 모아 기존문서는 인증복구 전 로컬추가본문만 보존한다.
