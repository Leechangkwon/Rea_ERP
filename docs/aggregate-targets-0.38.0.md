# 발주계획 집계대상 0.38.0

발주계획 집계에서 수량·공급가액·부가세·합계 중 표시할 숫자 열을 선택합니다. 집계조건은 그룹을 정하고 집계대상은 숫자 열을 정합니다. 선택이 없으면 네 열을 모두 표시합니다.

## 사용 예와 합격 조건

품목명[규격]/거래처 두 축에 공급가액만 선택하면3열과 앞2칸을 합친 소계/합계가 나와야 합니다. 첫 숫자 열이 금액일 때도 금액 자릿수를 사용해야 합니다. 대상을 모두 지우고 검색하면6열로 돌아갑니다. 선택창은 이미 고른 항목을 제외하고 새 선택을 임시 보관합니다. 적용(F8)은 검색 조건만 바꾸며 F8 검색 전까지 표/CSV/인쇄는 마지막 성공 결과를 유지합니다. 닫기/Escape는 미적용 선택을 버리고, 메뉴 이동/복원은 열린 선택창을 정리해야 합니다.

## 원본 관찰과 실제 REA

원본 발주계획 E041015/메뉴2764의 별도 집계대상 lookup을 직접 확인했습니다. 수량·공급가액·부가세·합계 체크박스, 적용(F8)/닫기, 선택된 항목의 태그/개별제거/전체지우기가 있습니다. 선택된 대상은 다시 연 후보 목록에서 빠집니다. 수량/공급가액을 고른 뒤 남은 항목이1부가세/2합계로 다시 번호가 매겨져 UI 순번이 실제Seq라는 추정을 배제했습니다.

1축+수량/공급가액은3열, 2축+공급가액은3열과 소계/합계2칸 병합, 전체지우기+2축은6열을 확인했습니다. 이 현재 화면의 빈선택=전체/표시열 제한은 UI 근거입니다. 보관 V3header의38개 실제REA 참조는 REPORT_TARGET을 선택Seq목록으로 넘기는 별도 lookup 프로토콜까지 확인합니다. 빈값은[]로 넘기며 기본전체 변환/현재 ESG002R binding/실제ColumnForm·비교기간·소계 수치 소비자는 확인되지 않았습니다. UI 순번이나 자체ID를 원본Seq로 쓰지 않습니다.

누계84본문25,247,564B는 그대로입니다. 신규GET/의미분석 재시도/원문 실행/비공개API는 없습니다. commonOOM·Flexion timeout·grid5구문오류 부분 분석을 유지합니다. lookup의 적용은 임시 조회 조건 선택에만 사용했고 원본 설정저장/업무저장/주입력행/출력은 실행하지 않았습니다. 회사 자료/세션URL은 보관하지 않았습니다. 집계대상을 모두 지우고 내역/F8로 복귀했습니다.

## 자체 구현과 검증

발주계획만 집계대상을 활성화합니다. 자체ID quantity/supply/tax/total과 고정된 숫자열 순서를 사용합니다. 다른 현황에 임의 연결하지 않습니다. 0~4개 고유ID만 허용하고 배열 구멍·알 수 없는 항목·중복·잘못된 형식을 거부합니다. 원시 records/summary의 네 수치는 유지하며 행/소계/합계/내보내기에 표시 열만 투영합니다. 첫 숫자 열의 위치가 아닌 measureID로 수량/금액 반올림과 표시 자릿수를 구분합니다.

선택창은 현재 선택을 제외한 후보를 제공하고 새 선택만 부모의 대기 조건에 추가합니다. 개별/전체 제거도 대기 조건에만 작용합니다. 과거 스냅샷에 대상이 없으면 전체4개를 사용하며 성공/대기 배열을 별도 복사합니다. 초기화는 대상을 지우고 기본4열로 돌아갑니다. 공유 표/CSV/인쇄와 선택 대상 안내/요약을 같은 성공 결과에서 만듭니다. 복원/초기화/메뉴 이동에서 열린 선택창을 정리합니다.

새 핵심5개/UI6개/실제 모듈 통합1개를 추가했습니다. 통합 money표시 검사는 실제 페이지처럼 inventory-ui 뒤에 SelfCore를 로드한 상태에서 검증합니다. 테스트 자료의 세금 소수 설정도 명시했습니다. 검사 수/해시는 aggregate-targets/validation.json에 기록합니다. DB와 저장 자료 구조는 바꾸지 않았습니다. 원본Seq·동적 양식·다른 화면 대상·비교/그래프/서버 계산/출력 전체 동등성과 호스팅 로그인 업무 검증은 남아 있습니다.
