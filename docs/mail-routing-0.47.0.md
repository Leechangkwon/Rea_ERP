# REA 메일함 자동 수신 연결 · 0.47.0 / 0.47.2

기존 메일함을 선택해 주소·이름·사용 여부·구성원을 저장하면, 연결된 회사 도메인의 Cloudflare 수신 규칙을 자동으로 맞추고 결과를 표시한다. 고정된 qaredi.com과 rea-mail-ingress Worker만 사용하며 도메인 등록·DNS 변경·다른 앱 규칙·전체수신 규칙은 건드리지 않는다.

## 사용

Self-Customizing → 기타관리시스템 → Webmail설정 → REA 메일함 열기 → 메일함 관리에서 메일함을 선택한다. 주소 변경은 같은 메일함 UUID를 사용하므로 이전 받은편지·보낸편지·첨부·전표 연결이 남는다. 과거 메일의 발신/수신 주소는 당시 기록대로 보존한다. 이전 주소의 수신 규칙은 새 주소로 바뀐다.

저장 후 수신 연결됨을 확인한다. 연결 실패 시 저장/연결 결과를 구분해서 표시하며 수신 연결 다시 시도로 실제 규칙을 조회해 복구한다. 수신 연결 처리 중인 동시 저장은 차단한다. 사용 해제/다른 발신 서비스 전환은 소유한 규칙을 비활성화하고 삭제하지 않는다. 같은 주소의 다른 수신 규칙은 덮어쓰지 않고 충돌을 표시한다.

## 서버와 검증

서버는 기존 승인된 Wrangler OAuth를 공식 auth token 명령으로 갱신한다. 고정 Wrangler4.151.1을 실행 의존성에 포함한다. 자식 출력만 비공개로 읽고 WRANGLER_WRITE_LOGS=false로 인증값의 디스크 로그를 차단한다. 전역 키는 거부하며 브라우저/컴파일 파일/DB에는 토큰을 주지 않는다. 별도 서버용 routing token도 비공개 설정에서만 지원한다. 관리 권한과 CSRF를 확인하고 외부 반영 직전에 권한을 다시 확인한다. Supabase/SQLite의 route_sync에 작업ID·CAS/기한·연결 결과를 저장해 부분 실패/불명확 결과를 명시적으로 복구한다.

전체 verify:local·관련 Node66개·브라우저20개·릴리스4개가 통과했다. REA6.4의 자체 변경3개 파일 입력/결과 해시·근거·비부분 분석을 확인했고 원본86개 누계는 바꾸지 않는다. 현재 운영 반영/주소 변경 검증은 evidence/mail-routing-20261019.json을 따른다.

## Gmail 스팸 분류

사용자가 신고한 메일은 pkdkak1@gmail.com으로 받은 test이며, 처음 SPAM에 있다가 직접 스팸 아님으로 옮겼다고 확인했다. 현재 INBOX 표시는 최초 분류의 근거가 아니다. 해당 메일의 SPF/DKIM/DMARC와 발신 IP의 정방향/역방향 DNS는 정상이다. 새 주소의 표시 이름과 Reply-To를 발신 주소에 맞췄다. 인증 통과만으로 Gmail 받은편지함 분류를 보장하지 않으며 Google은 발신 IP/도메인 평판 등도 고려한다. 이 메일의 분류 원인은 미확정이다. Gmail 필터/허용목록을 자동 추가하거나 기존 편지를 이동하지 않았다.

## 운영 확인

최종0.47.2/305cde5에서 pkdkak1@qaredi.com 변경 저장·자동 수신 규칙 갱신과 수신 연결 다시 시도를 확인했다. CF 규칙ID와 기존 메일함ID를 유지했으며 기존메일6건·첨부·구성원과 다른메일함/규칙·전체수신 설정은 그대로다. 같은 세션의 새로고침 뒤에도 주소/연결됨을 확인했고 비공개 백업3함/6메시지/1파일과 복원 미리보기0충돌을 검증했다. 사용자가 새 주소 시험 각1통을 승인해 양방향 모두 완료했다. Gmail→새 주소는21:10:57 KST REA inbox 수신·본문/첨부0/읽음 저장과 Gmail SENT를 확인했다. 기존 계정 재로그인 후 REA 회신1통을 실제 화면에서 발송해21:34경 Gmail 첫 조회INBOX/UNREAD·SPF/DKIM/DMARC pass·From/Reply-To/회신ID 일치를 확인했다. 메일 이동이나 Gmail 필터 추가는 없었다. 기존메일6건·첨부·다른메일함/규칙·기존설정·ERP 보호상태를 재검증했고 양방향 포함 백업3함/8메시지/1파일·복원미리보기0충돌이다. 승인각1통을 모두 사용했으므로 반복 발송하지 않는다. 이번 발신은 회신 스레드 시험이며 그 결과만으로 과거 test의 분류 원인이나 향후 모든 메일의 분류를 단정하지 않는다.
