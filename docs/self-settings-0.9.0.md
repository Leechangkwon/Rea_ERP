# Self-Customizing 대조 개발 0.9.0

## 원본 관찰

로그인된 원본에서 기본값설정의 공통 트리와 반올림/숫자 표시 팝업을 직접 열었다. 기능설정의 공통·회계·재고·관리·그룹웨어·데이터센터 6개 탭의 항목을 대조하고, 재고의 자료불러오기집계기준 및 진행상태 변경 기본설정을 분해했다. 매핑센터의 신규 → 불러올 메뉴 → 생성할 메뉴 선택까지 관찰했다. 원본 회사 설정·전표를 저장/중단/재사용/삭제/송신하지 않았다.

공개 JS 7개 52,281바이트를 rea-agents6.4.0의 직접 정적·의미 분석 함수로 실제 분석했다. 구문 오류0, AST13,830, callable224, call856, 동적 frontier956. 입력별 SHA256·코드 범위·정적 추론과 미확인은 docs/self-settings-rea.md에 기록했다. CLI 전체 application graph는 기존 프로세스 소유 확인 오류로 성공하지 않았으며 이를 우회하지 않았다.

## 구현

- 기본값 트리와 기능설정 6개 탭·검색·접기, 확인된 항목별 저장 모달.
- 공급가액/부가세 처리 방법, 금액 자릿수, 0 표시·뒷자리 0, 천 단위/소수점 구분자 저장.
- 새 전표에 계산 정책을 명시적으로 복사. 기존 전표와 원본 연결의 정책은 유지. 표시 설정은 숫자 자체를 변경하지 않음.
- 재고 불러오기: 품목명/규격 인식 범위, 라인/품목별 표시, 조회/미현황 초기 조건 적용. 품목별은 서로 다른 단가·적요·출처를 보존하는 자체 묶음 표시이며 원본 집계의 세부 합산 알고리즘과 동일하다고 주장하지 않음. 품목별 잔량 연결은 차단.
- 진행 규칙: 실제 연결 전표 저장에만 적용. 계획은 선택 원본행만, 구매는 확인 축 유지. 복사 참조·취소·미확인 자식 제외. 마감/회계반영/잘못된 규칙은 자식 저장까지 함께 실패.
- 매핑센터를 외부 API 센터와 분리. 원본처럼 메뉴 쌍 목록/등록/사용중단/재사용/CSV 제공. 외부 API 기능은 API인증키발급 경로에 보존.
- 전표 불러오기에서 내부 행 ID만 다른 같은 업무 조건의 행을 거절하던 오류 수정. 조건이 다른 구조화 요청/계획의 행은 따로 보존.
- 서버 설정 권한·CSRF·수정 번호·원자 저장 유지. 기존 기본값5개/기능설정5개 및 이전 자료를 보존. 신규 설정은 앱 계정 상태로 전달.

## 검증과 제한

클라우드 전체 자동 검사624개 통과 후 매핑 메뉴 조회 권한 검사를 1개 추가해 관련 통합·탭 검사를 재통과했다. 배포 파일 검사4개와 Worker 빌드 성공. 실제 Worker·전체 app.js 메뉴 라우팅을 사용하는 합성 통합에서 설정 저장→사용자 설정 갱신→새 전표 적용·기존 자료 보존, 불러오기 초기 상태, 매핑/API 분리, 조회 권한, 수정 충돌을 검증했다.

supervisor 브라우저에서 공급가액 버림/금액0자리 저장 후 새 요청 수량1·단가3.7의 공급가액3/부가세0/합계3 표시를 확인했다. 호스팅 앱 계정 업무와 실휴대폰은 별도 미검증이다.

원본에서 하위 편집을 확인하지 않은 항목은 목록에 '미확인'과 비활성 이유를 표시한다. 글꼴·수량/단가 자릿수·인쇄/회계/관리/그룹웨어의 상세 동작 등을 구현 완료로 기록하지 않는다. 매핑의 필드별 편집기는 원본 신규 저장을 수행해야 다음 화면이 열리므로 임의 저장하지 않았고 미구현이다. 메뉴 쌍 등록은 실제 필드 매핑이나 전표 전송을 수행하지 않는다. 외부 API 매핑과도 별개다.

이전 화면의 '기존 행 추가/덮어쓰기' 기본값은 원본 기능설정의 집계조건/불러오기조건과 다른 개념이다. 관찰되지 않은 전역 덮어쓰기 기본값을 만들지 않았다. 코드 오류를 수정하고 실제 확인된 설정을 연결했다.
