2026-10-19 사용자 요청: 기존 발주요청조회 구현을 정확히 파악하고 원본과 대조한 뒤 미구현·차이부터 개발한다. 발주요청·발주서·구매의 목록·검색·입력·보조·저장·상태·전환·이력·출력·현황 및 권한/보관을 모두 재검토한다. 기존 0.42.0 기능과 F3 보완, 환경 개선의 미커밋 변경을 보존한다.

## 진행 원칙

1. 기존 구현 파일·함수·테스트와 현재 원본 계약을 기능별 기준표로 확정한다. 과거 미구현 메모만으로 새 기능을 만들지 않는다.
2. 로그인된 Ego에서 조회 전용 화면과 값 없는 정적 DOM·메뉴·분리 팝업을 관찰한다. 공개 JS는 인증 없는 GET, 해시와 고정 REA 분석으로 보완한다.
3. 실제 차이와 근거 미확인을 구분한다. 확인된 차이 중 영향이 크고 검증 가능한 항목을 구현하고 합성자료로 검사한다.
4. 원본 주 입력행·행 번호/선택/이동·원본 저장/삭제/발송/설정 저장은 조작하지 않는다. 입력값·회사 업무 행·인증 정보·세션 URL을 수집하지 않는다. 운영 배포는 이번 개발 결과와 구분한다.

## 수정한 실제 차이

1. `dist/entry-core.js`: 계획 품목행의 `progress`가 비계획 대상에 복사되어 저장 검증에 걸리는 오류를 제거. 원본 연결 ID·수량·출처는 유지한다.
2. 같은 파일: 요청/계획의 행 거래처로 문서를 찾고 해당 거래처 행만 표시한다. 행 거래처명/코드도 통합검색에 반영한다. 일반 잔량 연결의 기존 헤더 거래처 제한과 창고·잔량 검증을 유지한다.
3. 같은 파일과 `dist/inventory-core.js`: 일반 불러오기에서도 완료된 계획 행은 잔량 연결 후보에서 제외한다. 공유 `validatePlanOrderRows`로 합친 전체 초안 행과 최종 저장을 모두 재확인하여, 기존 초안의 거래처 변경이나 선택 후 계획 완료를 놓치지 않게 한다. 완료 전에 저장된 발주서는 같은 연결 수량의 단가 수정은 허용하고 새 수량 증가는 차단한다. 내용 복사는 별개로 유지한다.
4. `dist/inventory-ui.js`: 요청·발주서·구매 조회에 프로젝트/품목 조건과 검색(F8)을 추가하고 F3 키를 공통 연결한다. 이전 검색 양식의 필드 ID·라벨·저장 설정은 보존한다.
5. 같은 파일: 사용자 양식에서 c0 선택 열을 이동/이름 변경해도 전체선택이 유지되도록 한다. 의도적 숨김을 존중하고 페이지 이동 시 체크/부분 체크 상태를 현재 페이지 기준으로 갱신한다.

신규 재현/회귀 검사는 `tests/purchasing-review.cjs` 12개와 `tests/purchasing-integration.cjs`의 새 필터/키/기존 검색 양식/선택 열 검사 4개다. localhost Playwright는 3종 검색 흐름을 포함해 6개이며 모두 실제 원본과 분리된 합성 자료를 사용한다. 독립 읽기 전용 검토에서 기존 초안 행의 검증 사각지대를 지적받았고, 재현 검사 5개와 합친 전체 행/최종 저장의 공유 검증기로 보완했다. 후속 경계 검토에서 0.000001 수량 증가도 엄격히 차단하도록 6자리 정규화 수량을 직접 비교하고 별도 검사했다.

실제 원본 발주요청·구매 F3는 Ego keyboard로, legacy 발주서 F3는 Ego CDP의 F3 virtual key 114를 포함한 실제 키 이벤트로 펼치기/접기를 확인했다. Ego의 기본 keyboard.press만으로는 legacy 쪽이 반응하지 않아 원본 미동작으로 판단하지 않았다. 입력값이나 회사 결과 행을 읽지 않았다.

## 공개 코드와 REA의 한계

원본 DOM에서 관찰한 공개 공통 번들 3개를 인증 없는 직접 GET으로 개별 확보했다. 합계 1,101,854B, 실제 REA 6.4.0 CLI/근거 스키마 검증 및 구문 분석 3개/오류0. usecase와 user_action 두 번들은 의미 그래프 노드 상한으로 부분 분석이고 order_management는 coverage unknown/미잘림이다. 정적 후보 노드는 현재 런타임 이벤트·검색 서버 조건·권한·저장 결과의 확인이 아니다. `.artifacts/purchasing-review-20261019/rea-summary.json`에 세 상태를 각각 기록했으며 기존 86본문·이전 완료 누계는 변경하지 않았다.
