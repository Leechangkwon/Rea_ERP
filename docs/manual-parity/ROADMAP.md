# 매뉴얼 기반 재현 진행 순서

계획판 0.1 · 2026-10-21. 각 단계의 완료는 PRD 합격 조건으로 판단한다. 단계 번호는 의존성을 정한 순서이며, 아직 확인하지 않은 기능을 구현 완료로 바꾸지 않는다. P0 설계 게시를 완료했고 전체 매뉴얼 조사는 계속한다. P2.1의 날짜 검색을0.51.0, BOM 1단계를0.52.0에 반영했다.

외부 의존성 조사는 해당 기능을 구현하기 전에 진행한다. 권한·결재·메일·API 등 공통 기능은 P8/P9가 될 때까지 미루지 않고 앞 단계에서 필요한 부분을 먼저 만든다. 최종 전체 매뉴얼 검증은 해당 단계에서 다시 수행한다.

## 기능 하나의 반복 순서

매뉴얼 본문 읽기 → 절차/결과/분기 확정 → 기존 구현·테스트 확인 → 원본 조회와 REA 분석 → 차이표와 작은 변경계획 → 독립 구현 → 합성 단위/저장/권한 검사 → localhost 브라우저 → 기존 자료 보존 검사 → 버전/커밋/push → 운영 반영 → 로그인 후 확인 → 모아 기록·다음 요구사항.

불확실한 원본 동작을 보기 좋게 추정하여 추가하지 않는다. 접근이 막힌 작업은 이유/필요입력/다음행동을 남기고 다른 독립 조사·검사를 진행한다. 승인 없이 원본 주 입력행을 조작하거나 실제 고객 메일·신고·결제를 테스트하지 않는다.

## 완료 수치 관리

`sourceCount`, `reviewedSourceCount`, `confirmedRequirementCount`, `implementedCount`, `localPassedCount`, `hostedPassedCount`, `doneCount`, `blockedCount`를 분리한다. 현재 본문4개에서 공식 요구사항13개를 분해했으나 전체모수 미확정으로 완료율 미산정이다. 과거 구매실26절차는 legacy-needs-rebaseline 상태이며 새 공식 매뉴얼 기준 done=0이다. 기존 기능을 삭제하거나 과거 검증 성공을 부정하는 의미가 아니다.

## 범위 변경과 다음 세션 인계

매뉴얼이 추가/개정되면 원래 기준판과 해시를 남기고 영향 요구사항을 다시 연다. 일방적으로 항목을 제외하지 않는다. 다음 작업자는 이 문서의 큐, PROGRESS.md, 원본/구현 차이표와 실제 변경대상만 먼저 읽는다. 다른 프로젝트·별도 사이트로 작업 대상을 바꾸지 않는다.

## 첫 본문 조사 후 실행 큐 · 2026-10-21

1. REQ-COM-DATE-001/002: 발주요청 작성일·수정일 범위 검색과 최초 저장 시각. 0.51.0 구현/전체 로컬 검사 통과, 운영 읽기 전용 검색 및 자료 보존 확인. 유자료 저장 시나리오 합격은 별도.

## 0.52.0 이후 다음 작업

BOM 전체/1단계 구현·합성 저장/재조회·운영 미리보기와 자료 보존을 확인했다. 요청 주문 불러오기의 품목별은 동일 조건 합산이 이미 존재했다. 라인별까지 합산하던 결함을0.53.0에서 수정했다. 서로 다른 단가·거래처·납기·적요·출처를 어떤 규칙으로 보존하는지 원본 근거를 먼저 확인하고 다른 전표의 잔량 연결을 임의 변경하지 않는다.

## 0.53.0 이후 실행 큐
1. 거래별 부가세 차액 조정: 매뉴얼 본문과 현재 금액 함수 대조 후 순수 계산 계약부터 구현. [계획](../plan-manual-transaction-vat-20261021.md)을 따른다.
2. 브라우저 입력 복구 후0.53.0 브라우저 JSON 보존 대조 및 모아 재로그인 후0.52/0.53 기록 읽기·필요시 추가·재조회. 상태를 우회하거나 게시 성공으로 간주하지 않는다.
3. 주문 품목별의 서로 다른 단가·거래처·납기 합산 정책은 원본 확인 전 기존 분리 정책을 유지한다. 공식13개 중3개 로컬/운영 일부 확인, 주문1개 로컬 부분/운영 미저장 입력 확인, 최종완료0이다.
