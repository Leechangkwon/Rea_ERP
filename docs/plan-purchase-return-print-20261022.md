# 구매조회 반품 인쇄 · 2026-10-22

## 원본 근거와 범위

EC-HELP-PURCHASE-RETURN의 음수 구매/반품 구분과 구매·발주 도움말의 조회 → 인쇄 → 양식설정 흐름을 기준으로, 현재 구매조회에서 안내만 하는 차감반품 인쇄를 연결한다. 저장된 고정 배분 금액을 사용하고 원구매·반품·기존 양식은 변환하지 않는다. 신규 미저장 초안 인쇄나 여러 전표 일괄 인쇄까지 확대하지 않는다.

추가로 읽은 EAM012M_326237497798 「전표인쇄와 건별인쇄의 차이점」은 회계의 입금보고서/지출결의서/가지급정산서 인쇄 전용이다. 이 선택을 구매에 임의 추가하지 않는다. EAM012M_120422034974 「조건에 따라서 입력화면/리스트/전표 양식이 다르게 나타나도록 설정하는 방법」은 ID·PC/Mobile 조건, 최대3 AND, 일괄인쇄 첫 전표 기준을 설명한다. 현재 FormCore는 단일 조건이며 이 전체 계약을 완료 처리하지 않는다. 이번에는 기존에 저장된 지원 조건과 선택 양식을 재사용한다.

## 구현 계약

1. purchase-return-core.printModel은 canonical purchasereturn/credit와 별도로 출력 모델을 만든다. qty/supply/tax/total은 고정 returnAmounts를 음수로 투영하고 단가/메모/추가항목은 보존한다. 음수로 세액을 다시 반올림하지 않는다. 이 모델을 저장 명령에 전달하지 않는다.
2. 반품 양식 namespace에 기존 설정이 있으면 이를 우선한다. 반품 양식 설정이 없으면 기존 구매 양식을 함께 사용한다. 자동 복제/활성화/조건 저장은 하지 않으며, 공유 구매 양식을 바꾸면 일반 구매 출력에도 적용됨을 화면에 표시한다. 이 우선순위는 기존 양식 보존을 위한 자체 호환 정책이다.
3. 구매조회에서 반품 한 건을 선택하고 인쇄하면 음수 미리보기를 보여준다. 기존 열 순서/가시성/너비·페이지 설정·지원 조건·계산식을 유지한다. 합계는 저장 배분액이다. readonly 사용자도 조회/인쇄할 수 있지만 양식 변경은 기존 쓰기권한을 따른다.
4. 계정/회사/조회권한/초기 storageKey/저장소 CAS를 출력 열기·양식 선택·실제 인쇄 직전에 재검사한다. 닫힌 창의 늦은 이벤트는 저장·인쇄하지 않는다. 실제 window.print는 명시 인쇄 클릭 때만 호출한다.

## 합격과 배포

소수 세액 반품3개를 나눠 -.67/-1.33으로 인쇄하는 기본/사용자/조건 양식, 기존 독립 반품 양식 우선, 양식 선택 취소/명시 저장, 계정·권한·저장소 변경 차단, 백업 불변을 검사한다. 합성 조회 → 선택 → 미리보기 → 닫기 → 저장자료 재조회 한 절차를 브라우저로 검증한다. 분리 운영후보에서 전체 회귀·REA·릴리스 검사 후 push/배포/운영 조회와 보존 대조한다. 실제 원본/운영 업무 저장·메일 발송·프린터 출력은 수행하지 않는다. 원본의 사용자 ID/3 AND/Mobile/일괄인쇄와 단독 양식의 최종 동등성은 별도 미완료다.
