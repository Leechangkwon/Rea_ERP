# 거래별 부가세 차액 조정 · 다음 구현 계획

## 근거
공식 매뉴얼 EC-HELP-REQUEST-001, 보관 본문 `.artifacts/manual-parity-20261021/manual-total-vat-split.txt`, 출처/해시는 `evidence/manual-parity-20261021/online-manual-index.json`을 따른다. 모든 메뉴에 동일한 설정 절차라고 명시한다. 기본설정=라인별, 직접입력=라인별/거래별. 거래별은 동일 부가세율의 합계금액을 기준으로 공급가액과 부가세를 다시 구하고, 저장 시 차액 알림 확인 후 세율별 마지막 행에 차액을 반영하며 음영 표시한다.

기준 예: 909.09×5의 3행에서 라인별 공급가액4,545·부가세455·합계5,000씩, 총액15,000. 거래별 공급가액13,636·부가세1,364로 조정하며 마지막 행 공급가액4,546·부가세454. 이 숫자는 해당 원본 예의 표시/반올림 조건을 포함한다. 현재 기본 소수2자리 정책으로 값이 다르다고 즉시 전체 기본값을 바꾸지 않는다.

## 현재 구조와 위험
- `dist/inventory-core.js` lineTotals/effectiveLineTotals/totals는 행별 계산. taxRounding/supplyRounding 계약을 사용한다. effectiveLineTotals는 반품/교환 returnAmounts 예외를 이미 보존한다.
- `dist/entry-extra-core.js` stageAmount(kind=rounding)는 반올림 정책이며 거래 총액의 세율별 마지막 행 차액 조정과 다르다.
- `dist/inventory-ui.js`의 ‘거래별계산’은 영업 유형만 노출해 위 rounding 보조를 연다. 이를 매뉴얼 동등 기능으로 간주하지 않는다.
- 현재 전표 vatRate는 헤더 기준이다. 혼합 세율, 외화 환율, 저장 전 확인, 수정 후 차액 재계산, 출력/채무/수불 소비 지점을 함께 확인해야 한다. 기존 저장 전표 금액을 새 기본값으로 재계산/이관하지 않는다.

## 순서
1. 원본 설정 경로를 조회 전용으로 확인하고 공개 코드의 필드/기본값 매핑을 REA6.4.0으로 분석한다. 브라우저가 계속 막히면 저장 본문과 현 코드 대조 및 순수 계산의 합성 검사부터 진행하고 원본 관찰은 미확인으로 남긴다.
2. 현재 self-settings 파일을 `rg --files`로 확인하고 부가세/공급가액·기본값/예외 설정을 좁혀 읽는다. 서버 권한·CAS와 회사/사용자별 기존 양식을 바꾸지 않는 선택적 필드를 설계한다.
3. 순수 미리보기 함수: 원본 행과 기존 반올림 계약을 입력으로 받아 세율 그룹별 현재 합계, 목표 공급가액/세액, 차액, 마지막 대상 행과 증거를 반환한다. 입력 객체는 변경하지 않는다. 총액 보존·그룹별 마지막행·0세율·음수/반품·소수·상한·빈 행 정책을 명시한다. 미확인 혼합세율이나 외화는 성공으로 표시하지 않는다.
4. 저장 적용은 사용자 확인과 스냅샷을 묶는다. 수량/단가/세율/정책/행 순서가 바뀌면 기존 확인을 무효화한다. 취소·권한없음·충돌은 저장하지 않는다. 단가를 억지로 바꿔 차액을 맞추지 않는다.
5. 차액 저장/재조회와 totals/출력/집계/채무·반품 연결을 같은 금액 계약으로 맞추고 기존 전표/양식/백업 보존을 회귀한다. 기존에 저장된 조정금액이 있는 경우 임의 삭제하지 않는다.
6. 관련 합성 검사 및 브라우저 흐름→필요한 전체 verify:local→커밋/push→보존백업→기존 WSL·Supabase·Cloudflare 반영. 현재 브라우저 차단이 해소되기 전 UI 검증/브라우저 자료 보존을 완료 처리하지 않는다.

## 2026-10-21 · 계산 코어 1차 구현

`dist/transaction-vat-core.js`의 `preview`/`verify`를 추가했다. 아직 HTML·기존 전표 저장·출력·설정에 연결하지 않은 순수 계산 모듈이다. 운영 버전은0.53.0이며 새 기능 운영 반영/매뉴얼 합격을 선언하지 않는다.

- 매뉴얼 예제의 총액15,000 유지, 공급13,635→13,636·세액1,365→1,364, 마지막행4,546/454를 재현한다.
- 기존 lineTotals와 반올림 기본값은 그대로 호출한다. 공급가액 기본 소수2자리를 바꾸지 않는다. 거래 총액 재분리는 정수/BigInt 비율로 처리해 반 센트 경계와 누적 부동소수 오차를 피한다.
- snapshot은 정규화된 입력과 순서/행ID/사용자 메타데이터를 묶는다. 계산된 supply/tax/total 캐시는 제외한다. 검증 시 snapshot뿐 아니라 목표금액·차액·대상 행·모든 결과를 재계산한다. 이는 일시적 미리보기 계약이며 저장 형식이나 권한 승인이 아니다.
- 단일 헤더 세율/KRW, 양수 수량, 1~500행, 총액1조 이하, 세율 소수6자리 이내가 현재 계약이다. 외화/혼합세율/반품/기존 조정 메타는 거부한다. 마지막행 음수가 되면 이전행에 임의 배분하지 않고 거부한다. 이 상한과 미지원 분기는 자체 검증 범위이며 원본 제한이라고 주장하지 않는다.
- 희소 배열의 빈 슬롯을 건너뛰던 검토 지적을 수정하고 첫/중간/마지막/전체 빈 슬롯 회귀를 추가했다. 신규21검사에는1500생성사례,500행/1조,소수6자리 세율,브라우저 export 무부작용 검사가 포함된다.

## 다음 저장 통합 계획 — 같은 금액 계약으로 한 묶음 반영

독립 읽기 전용 영향 분석으로 다음 경로를 확인했다. 계산 코어만 먼저 기존 saveDoc에 붙이면 PDF·반품·변환의 금액이 달라질 수 있다.

1. 원본 Option→업무설정→부가세계산방법의 조회·기본값/예외 조건과 공개 필드 매핑을 확인한다. 원본 설정은 저장하지 않는다. 자체 FormOptions/FormCore의 기존 설정/양식을 보존할 선택적 설정 구조를 설계한다. 기본값은 라인별, 이미 저장된 전표에는 자동 적용하지 않는다.
2. 저장할 조정 형식은 별도 확정한다. `inventory-core`의 saveDoc/validateBackup에서 행 정규화 후 동일한 검증·반영을 사용하고 effectiveLineTotals/직접 행 금액이 일치하게 한다. 객체 동일성(indexOf)으로 마지막행을 찾지 않는다. 현재 snapshot 문자열을 장기 저장 형식으로 그대로 채택하지 않는다.
3. 저장 전 차액 알림과 확인/취소를 구현하며, 입력·정렬·양식·정책·권한·원본 수정 충돌 시 재계산한다. 화면의 합계/행 음영은 최종 검증된 금액을 사용한다. 단가·할인율로 차액을 숨기지 않는다.
4. `purchase-mail-core.normalizeDocument`가 lineTotals로 다시 계산하면서 조정 메타를 버리는 점을 수정한다. PDF·목록·인쇄·구매현황·채무·구매실을 같은 검증 금액으로 맞춘다. 발송 없이 로컬 PDF 생성/내용 대사로 검증한다.
5. `convert`의 원본 헤더 복사, EntryCore.stageDocuments, PurchasePlanCore.preview의 복사/분할/병합 시 조정을 대상 전표에 자동 상속하지 않는다. 새 전표의 금액으로 재계산하고 확인한다. `bulkprice` 가격 변경은 이전 조정 확인을 재사용하지 않는다.
6. 반품/교환 returnAmounts 우선 계약을 유지한다. 조정된 구매 금액을 원본 기준으로 부분/최종반품에 배분하고 이미 반품이 있으면 원본 금액 기준 변경을 차단한다. `rename`의 품목·통화 코드 변경은 정상 금액을 무효화하지 않도록 저장 근거의 식별자 갱신을 별도 처리한다.
7. 기존 백업 무변경 → 새 조정 저장/복원 → 모든 금액 소비 화면/PDF 일치 → 부분/최종 반품 합계 → 변경/취소/권한/오래된 확인/중복 저장 차단 → localhost UI → 기존 환경 배포/운영 보존 검증을 실행한다.

브라우저23에서 자료 관리/백업 버튼을 한 번 확인했으나 상태가 바뀌지 않아 반복 조작하지 않았다. 기존 탭21의 닫기 확인 문제와0.53 최종 브라우저 JSON 대조는 아직 대기다. 모아 세션도 로그인 대기이며 기존 게시물을 복제하지 않는다. 독립 코드·검사·설계를 계속한다.

2. `rg --files`로 실제 self-settings/FormOptions 파일을 찾아 해당 기본값/권한·CAS 경로만 읽고, 기존 회사/사용자 양식에 영향을 주지 않는 선택적 설정을 연결한다. 신규 기본은 라인별이며 기존 저장 전표에는 설정을 소급하지 않는다.
3. HTML에 TransactionVatCore 로드 → inventory-ui의 getDoc/refreshTotals/save와 저장 전 차액 확인/취소·행 음영 연결 → 사용권한/충돌 검사 뒤 동일 입력으로 `vatConfirmation` 생성·저장 → 재조회/인쇄/보고의 동일 금액을 합성 브라우저에서 확인한다. 이미 조정된 전표는 편집 중 라인별 금액으로 조용히 되돌아가지 않아야 한다. UI 확인을 보안상 권한 승인으로 간주하지 않는다.
4. 취소/편집/정렬/유형22/동시수정/구버전/반품/기존 양식 보존을 확인하고 전체 검사 후 버전 증가·push·보존백업·운영 반영한다. **현재 빌드는 UI가 연결되지 않은 중간 단계이므로 운영 서버를 재시작하지 않는다.**
5. 브라우저0.53 최종 JSON 대조와 모아0.52/0.53/계산/저장 통합 기록의 실제 저장 본문 재조회는 별도 미완료다. 로그인 복구 시 기존 본문부터 읽어 중복 기록을 피한다. 최종 매뉴얼 완료0 유지.
