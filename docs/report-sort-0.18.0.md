# 구매현황 정렬 기준 0.18.0

구매현황의 정렬기준 설정에서 최대 다섯 기준을 선택하고 방향·우선순위를 지정한다. 적용은 검색 조건을 준비하며 다음 검색(F8)에 반영한다. 조회 결과의 행과 전표 식별자를 함께 정렬해 전표 열기·수정 후 재조회·CSV·인쇄의 순서를 유지한다. 원본 전체 정렬·소계 설정과의 동등성은 미완료다.

## 원본 관찰과 공개 코드

원본 조회 전용 화면에서 초기 세 빈 행, 기준 더블클릭의 항목추가, 수량 선택 후 방향 활성화와 기본 오름차순, 방향 전환, 다른 행의 중복 후보 제외, 세 기준을 채운 뒤 네 번째 빈 행 생성, 선택 행 올림·내림, 선택삭제의 값 초기화와 행 수 유지, 적용 없이 닫고 다시 열면 빈 초기 상태로 돌아오는 반응을 관찰했다. 원본 적용·설정 저장·업무 자료 저장은 실행하지 않았다. 회사 기록을 보관하지 않았다.

기존 0.17.0에서 확보한 공개 원문 세 개를 실제 REA 6.4.0으로 분석한 근거를 사용한다. 초기화는 모든 기준이 채워졌고 다섯 행 미만이면 행을 추가한다. 선택삭제는 선택한 행을 기본값으로 되돌린다. 적용은 유효 행만 걸러 순서를 다시 매긴 뒤 메시지를 보내고 닫는다. 일반 빈 정렬 목록도 허용하므로 자체 구현에서도 기존 정렬 해제에 사용한다. 특수 trx_bal_status의 필수 조건은 구매현황에 일반화하지 않는다. 영구 저장은 use_save와 save_tf 조건이 함께 필요하다.

추가 대조한 공개 수신자와 V3 조회 전 소비자, V56 헤더 조회 소비자는 설정 보관·다음 조회 소비 경로를 보여준다. 현재 원본 화면의 실제 호출자·수신자 연결은 확보하지 못했다. 따라서 자체 적용 후 검색 흐름을 원본의 확정 동작으로 기록하지 않는다. 소스 72개·12,121,611바이트와 기존 partial/timeout 범위는 그대로이며 새 원문 수집은 없다. 상세 위치는 report-sort-config의 계약·수신자 근거에 기록했다.

## 자체 동작과 합격 조건

- 내역은 현재 자체 19개 열, 집계는 선택한 품목·거래처 축과 금액·수량 열에서 선택한다. 다른 행에 선택한 필드는 후보에서 제외한다.
- 초기 세 행에서 모두 채우면 다섯 행까지 늘어난다. 올림·내림은 선택 행의 우선순위를 바꾸고 선택삭제는 값만 비운다. 닫기·Escape는 임시 변경을 폐기한다.
- 숫자와 문자열을 구분하고 같은 값은 기존 순서를 유지한다. 문자열은 한국어 숫자 인식 비교, 빈 값은 오름차순 앞 배치를 쓰는 자체 정책이다. 원본 서버 비교 규칙은 미확인이다.
- 원본과 별개로 접근 가능한 선택 버튼·Enter를 제공한다. 적용 뒤 검색(F8)해야 조회한다는 안내를 표시한다. 조회·집계 항목이 바뀌면 사용할 수 없는 정렬을 해제하고 알린다.
- 마지막 성공 조회의 정렬과 아직 조회하지 않은 조건을 별도로 보관한다. 전표 수정 후 성공 조건으로 다시 계산하고 현재 입력 조건을 복구한다. 전표 링크·합계·소스 자료 식별자를 보존한다.
- 구매 CSV는 화면의 실제 열을 그대로 내보내고 인쇄에 성공한 기간·정렬 조건을 표시한다. 조회 권한 사용자도 정렬·조회·출력을 사용하며 전표 저장 권한은 늘리지 않는다.
- 메뉴를 떠나거나 화면을 다시 그리면 정렬 부모·항목 선택 자식 창과 키 처리를 정리한다. 다른 기능으로 이동할 때 팝업이 남지 않는다.

## 검증과 남은 작업

합성 자료 기반 정렬 핵심·팝업·조회 연결 신규 12개 검사를 추가했다. 수량 10과 2의 숫자 비교, 동률, 다중 기준, 집계 기록 대응, 잘못된 조건 차단, 후보 검색·중복 제외·행 증가·취소·빈 적용, 현재 조건 변경 차단, 전표 수정 후 순서 유지, 실제 화면 경로의 CSV·인쇄·조회 전용 권한과 팝업 정리를 검사한다. 배포 전 전체 결과는 validation-0.18.0.json에 기록한다. 인증된 호스팅 업무 화면 브라우저 검사는 수행하지 못했으며 jsdom 검사를 이 검증으로 대체 표기하지 않는다.

페이지분할·소계라인·상세설정은 비활성 상태다. 원본 서버 소계·페이지 분할·비교·그래프·설정 영구 저장, 현재 원본 적용 후 조회 타이밍, 전역 759개 경로와 버튼별 재현이 남아 있다. 저장 형식과 DB 스키마 변경은 없다.
