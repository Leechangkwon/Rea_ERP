# 발주서 → 구매 추가항목 명칭 승계

기준 운영0.55.0/0ae0af0. REQ-PUR-IMPORT-002의 원본 근거는 발주서 불러오기 온라인매뉴얼 본문의 “발주서와 구매의 추가항목 명칭이 일치하면 내용이 적용”이다. 원문은 .artifacts/manual-purchase-flow-20261021/purchase-order-import-help-body.ax.txt 366번 text이며 원본 서버 변환 구현은 미확인이다.

## 이번 계약

- 발주서→구매의 입력 상단과 품목행 추가항목에 한정한다. 활성/조건 양식의 명칭이 정확히 일치하는 custom 항목을 각각 같은 context 안에서 연결한다. ID만 같고 명칭이 다른 항목은 승계하지 않는다. 원본 미설정/미보관 값은 목표 값을 지우지 않는다.
- 기존 자료와 양식은 수정하지 않는다. 명칭 중복·유형 불일치·선택값/날짜/숫자 오류는 원자적으로 적용 거부한다. 계산식/읽기전용 목표는 승계하지 않는다. 기존 상단 입력값이 다르면 덮어쓰지 않고 오류로 보존한다. 빈/미설정 항목만 채운다. 이 충돌/유형/읽기전용 정책은 자체 보존 규칙이다.
- 품목행은 새로 불러오는 행만 명칭 매핑한다. 기존 입력행과 원본 전표/비연결 custom 보관값은 보존한다. 잔량0 상단정보 불러오기에서도 같은 명칭 규칙을 사용한다.
- 적용은 초안 변경이며 취소는 무저장이다. UI의 상단 custom control과 내부 custom 보관값을 함께 갱신해 저장/재조회에서도 값이 유지되게 한다.
- 합성 절차: 서로 다른 ID/같은 명칭의 발주 추가항목 → 불러오기 취소/적용 → 구매 저장/새로고침 → 상단/품목 값과 원전표/양식/잔량/재고/채무 대사. 관련Node·브라우저 후 운영 분리후보 전체검사/배포/보존확인.

## 남은 범위

전체수량 적용과 다른 단가의 품목별 합산/복수 원전표 연결은 원본 저장 계약 미확인으로 별도 큐다. 추가항목 충돌 자동덮어쓰기·서로 다른 유형 변환·전체 양식의 원본 동등성과 실업무 저장은 이번 완료로 올리지 않는다. main VAT5충돌 연구와 모아 인증대기는 보존한다.
