# 구매 네 업무의 조회 검색 후속 개발

현재 기준은 0.43.0, 커밋 db383d0이며 운영 서버의 계정과 Supabase 자료를 보존한다. 사용자는 발주요청·발주계획·발주서·구매를 원본과 다시 대조하고 빠진 부분을 이어 개발하도록 요청했다. 이번에는 조회 검색에서 확인한 차이를 보완하며 운영 저장 자료나 입력/생성/발송 동작을 바꾸지 않는다.

## 현재 원본 관찰과 범위

기존 Ego 세션 4를 현재 재개 지시에 따라 이어서 사용했다. 네 조회 화면과 검색 패널을 값 없이 관찰했다. 발주요청에는 내.외자구분·발주요청No.가 있다. 발주서·구매에는 현재 내.외자구분이 있으며, 현재 표시된 검색 패널에는 별도 번호 조건이 없으므로 요청 번호 조건을 다른 두 화면에 임의 추가하지 않는다. 원본의 회사별 양식 차이를 공통 기본값으로 덮어쓰지 않는다.

발주계획에는 기준일자·창고·프로젝트·거래처·품목·조회구분·수량이 있고 F3로 검색 패널을 펼치고 접는 것을 실제 키 이벤트로 확인했다. 자체 발주계획 Search(F3)는 빠른검색 재실행뿐이어서 상세검색과 토글·키보드 연결이 빠져 있었다. 이 중 기간·창고·프로젝트·거래처·품목을 이번에 구현한다. 조회구분의 건별/전표별과 수량의 0/0 아님은 표시량/잔량 및 묶음 계약이 더 필요해 이번에 추정 연결하지 않는다.

## 구현과 합격 조건

1. 발주요청·발주서·구매 목록에 내.외자구분 전체/내자/외자를 추가한다. 자체 보고서와 같은 KRW·누락 통화=내자 규칙을 재사용한다. 원본 서버 환산/세무 규칙과 같다고 선언하지 않는다.
2. 발주요청에만 전용 번호 조건을 추가한다. 자체 전표 ID의 대소문자 무시·공백 제거 후 문자 포함 검색이며 SQL 와일드카드나 정규식을 실행하지 않는다. 번호와 적요/통합검색을 구분한다. 원본 서버의 비교 연산자는 미확인이다.
3. 발주계획 상세검색에 기간·창고·프로젝트·거래처·품목과 검색(F8)을 추가한다. 기존 전체 조회를 보존하도록 날짜 기본값은 비우고, 선택한 조건은 F8/검색 또는 빠른검색 Enter로 적용한다. F3 펼침/접기 자체는 검색·저장하지 않는다. 거래처/품목은 같은 계획 품목행에 적용하고 기존 잔량/진행 상태는 독립적으로 유지한다.
4. 신규 조건은 저장 양식의 기존 필드 ID·순서·숨김을 보존한다. 선택·수량/단가 수정 초안·생성 대상 행 ID·CSV와 읽기 전용 권한을 회귀 검사한다. 날짜 범위 오류와 모달·조합 키·반복/IME 이벤트를 처리한다.

직접 수정 대상은 dist/inventory-ui.js, dist/purchasing-plan-list-ui.js 및 해당 Node/jsdom·합성 브라우저 검사다. 원본 입력행 조작/저장/삭제/발송/설정 저장은 하지 않았다. 근거는 .artifacts/purchasing-round2-20261019/와 기존 purchasing-review 관찰 파일에 분리한다. 원본 DOM·기존 REA·자체 구현·합성 검사·운영 상태는 별도로 기록한다.

## 검증 기록

관련 Node/jsdom 75개와 합성 Chromium 8개가 통과했다. 신규 Node 7개·브라우저 2개를 포함한다. 기존 저장 양식, 번호의 리터럴 비교, 읽기 전용, 기간 오류, 같은 품목행 조건, CSV, 수정 초안·선택 보존 및 실제 화면의 hidden CSS를 확인했다. 전체 verify:local 결과는 evidence/purchasing-search-round2-20261019.json에 기록한다.

REA 6.4.0으로 변경한 자체 파일 2개를 정적 분석했다. 입력 해시·캐시 근거 검증과 파싱 실패 0을 확인했다. 정적 그래프는 complete, 의미 그래프는 unknown이며 잘림은 없다. 원본 공개 번들 3개는 입력·결과 SHA-256을 다시 검증한 기존 결과를 재사용했다. 원본 의미 그래프는 partial 2개·unknown 1개이며 전체 동등성을 뜻하지 않는다. 기존 86개 누계는 이번 분석 수와 합산하지 않았다.

운영 반영 전 Supabase 두 상태를 프로젝트 밖 권한 700/파일 600으로 백업했다. 이번 변경은 스키마·자료 이관 없이 기존 로컬 WSL·Supabase·Cloudflare 구성에 적용한다.

운영 반영 중 CDN/브라우저의 기존 JS 4시간 캐시가 화면 버전과 코드를 섞는 것을 발견했다. 빌드할 때 모든 HTML의 로컬 JS/CSS 주소에 package 버전을 자동 추가하고, 실제 컴파일 응답에서 버전 주소·정적 파일 200을 검증했다. 원본 HTML/독립 로컬 미리보기 경로는 그대로 두고 운영 빌드에 적용한다.

## 운영 확인 완료

0.44.0 기능 커밋 1d445dc와 캐시 보완 9e0566e를 원격 main에 올린 뒤 기존 WSL 서버만 수동 재시작했다. 동일 Tunnel·도메인·Supabase를 유지했다. 기존 로그인 세션으로 네 조회의 새 검색 항목과 계획 F3 접기/펼치기·F8을 확인했다. 빈 운영 계획 목록에서의 읽기 전용 검사이며 실제 업무 저장·생성·발송 검증은 아니다. 공개 로그인 200/v0.44.0, 익명 루트 로그인 이동, 업무 API 401, 비공개 상태 경로 404를 확인했다. Supabase 두 상태의 본문과 수정 번호는 백업 전후 동일하다. 상세 근거와 남은 차이는 evidence/purchasing-search-round2-20261019.json을 따른다.
