# 발주계획의 발주요청 전표 불러오기 수정

사용자가 운영 0.44.0에서 발주계획 → 발주요청서 전표 불러오기가 전표별이어야 하나 상세 품목행으로 나뉜다고 확인했다. 사용자 확인을 이 수정의 표시 단위 기준으로 삼는다. 원본 입력행 조작이나 서버 저장 규칙을 새로 추정하지 않는다.

원인은 dist/entry-ui.js openDocuments가 documentCandidates의 전표를 flatMap으로 품목행에 펼쳐 공통 chooser에 전달하는 것이다. 실제 기준 소스 c5a4a38을 보존하며 UI와 관련 테스트만 수정한다.

발주계획의 일반 전표 불러오기와 발주요청 전용 버튼을 모두 전표별 기본으로 표시한다. 일반 창에서 발주요청 종류를 선택할 때도 전표별로 전환한다. 전표 한 건은 한 줄/한 선택이고 품목 요약·행 수·원본/불러올 수량 합계로 구분한다. 선택 적용 시 그 전표의 사용 가능한 원본 품목행들을 기존 stageDocuments에 넘겨 lineId, 수량, 단가, 거래처, 적요, sourceLineId와 잔량 초과 검증을 보존한다. 라인별·품목별 선택 기능과 다른 종류의 기존 기본값은 유지한다. 전표별에서는 수량 합계를 한 품목 수량처럼 수정하지 않는다.

검사: 복수/동일 품목 원본행, 부분 처리 잔량, 전표 단위 페이지·검색·선택 유지, 기존 머리항목·연결 모드·권한·취소, 원본 변경 시 잘못된 적용 차단. 관련 Node/jsdom, 합성 브라우저, 전체 검사와 빌드 후 버전 0.44.1을 기존 WSL·Supabase·Cloudflare에 반영하고 운영 창 표시를 확인한다. 운영 업무자료는 생성하거나 수정하지 않는다.

## 검사 및 근거

전표별 UI에서 복수 품목·같은 품목의 다른 단가·부분 잔량·전표 단위 페이지/검색 밖 선택·복수 전표 잔량 연결 차단·원본 변경·취소·읽기 전용 검사를 추가했다. 합성 Chromium으로 일반/전용 진입과 한 전표 선택 → 두 품목행의 수량/단가 유지, 저장 자료 무변경을 확인했다.

전표별 내용 복사는 기존 구조화 품목별 복사와 같은 보존 규칙을 사용해 다른 단가·적요를 잃지 않으며 동일 조건의 행을 합치면 출처와 총수량을 유지한다. 잔량 연결은 정확한 sourceLineId별로 유지한다. 원본의 비공개 저장/병합 동등성을 새로 선언하지 않는다.

REA 6.4.0으로 수정한 자체 core/UI 2개를 입력·결과 해시와 근거 검증으로 확인했다. 파싱 실패 0이며 의미 그래프는 unknown, 잘림은 없다. 기존 원본 86개 누계에 합산하지 않는다. 전체 검사에서 버전 query가 붙은 컴파일 자원을 기존 테스트가 파일명으로 읽던 문제가 드러나 self-settings·stock-report 통합 검사도 실제 Worker 응답의 버전 자원을 읽도록 바로잡았다.
