# 구매현황 날짜 단축 조회 0.16.0

구매현황 날짜 단축 버튼은 범위를 설정하고 즉시 조회한다. 종료일을 활성화해 현재 선택한 종료일 하루를 조회한다. 이번 주·지난주 범위는 현재 원본 계정에서 관찰한 일요일 시작을 구매현황에 적용했다. 다른 현황의 기존 날짜 버튼과 월요일 시작 기준은 유지한다.

## 직접 관찰

2026년10월18일의 원본 구매현황에서 검색 조건과 결과 화면만 확인했다. 성공한 조회는 조건창이 숨겨지고 Search(F3)로 해당 기간을 다시 열 수 있었다.

| 버튼 | 보존된 조회 기간 |
| --- | --- |
| 금일 | 2026-10-18 ~ 2026-10-18 |
| 금주(~오늘) | 2026-10-18 ~ 2026-10-18 |
| 전주 | 2026-10-11 ~ 2026-10-17 |
| 금월(~오늘) | 2026-10-01 ~ 2026-10-18 |
| 전월 | 2026-09-01 ~ 2026-09-30 |
| 전월+금월 | 2026-09-01 ~ 2026-10-18 |
| 종료일 | 10/01~10/18에서10/18~10/18, 9/01~9/30에서9/30~9/30 |

전일 버튼에서는 '등록된 데이터가 없습니다.' 안내와 조건창을 확인했고 날짜는 이전 성공 조회의10/18~10/18로 남았다. 이 경우 서버로 전달된 기간, 이전 결과의 정체나 금액은 수집하지 않았다. 현재 회사의 주 시작일이 일요일이라는 관찰을 모든 회사 공통 규칙이나 회사 설정 연동으로 일반화하지 않는다.

기존 공개 원문 네 본문에서 단축 키1/2/3/4/5/6/9/17의 구체 날짜 공식과 클릭 핸들러는 찾지 못했다. V3 위젯은 동적 simpleSearch 설정을 외부 날짜 컨트롤에 전달한다. V56 일반 조회의 폼 숨김과 검색 DMC 보관은 소스로 확인했다. 개별 버튼과 해당 소비자의 실제 연결은 미확인이며 근거를 분리해 기록했다. 새 GET·원본 업무 저장·설정 적용을 실행하지 않았다. 고유 공개 코퍼스69개·10,214,621B는 변함없다.

## 자체 동작과 검증

날짜 단축 조회는 현재 품목·거래처·통화·집계 조건을 사용한다. 후보 기간의 조회가 성공하면 날짜를 적용하고 폼을 닫는다. 오류나 자료 없음이면 수정 중인 조건과 마지막 성공 결과를 유지하며 폼을 열어 안내한다. 최초 조회부터 자료가 없으면 출력할 결과를 만들지 않는다. 기존 결과가 남을 때 혼동하지 않도록 결과 표 제목, 내보내기 파일명, 인쇄 미리보기에 성공한 조회 기간을 표시한다. 전일의 기본 기간은 기존 자체 날짜 계산을 사용하며 원본 오류 사례의 실제 서버 기간을 확인했다고 주장하지 않는다.

종료일은 오늘과 독립적으로 선택한 종료일을 사용한다. 월·연 경계와 윤년 일자, 빈/불가능한 종료일, 일요일·주중의 주간 범위, 일곱 단축 버튼의 즉시 조회와 F3 조건 보존, 무자료의 이전 결과/기간 보존과 최초 출력 차단, 다른 현황의 기존 동작을 합성자료로 검사한다. 기존 보고서·통합 검사32개에 새 검사7개를 추가한39개가 통과했다. 전체·배포 결과는 `evidence/global-rea-20261018/report-date-shortcuts/validation.json`에 기록한다.

DB·백업 형식과 권한을 바꾸지 않는다. 관리 브라우저 로컬 미리보기 연결 부재로 대체 미리보기를 시작하지 않았으며, 호스팅 로그인 후 업무 QA는 미검증이다. 원본 서버의 소계·기간 비교·회사별 달력 설정·날짜 단축 내부 오류 복구는 남아 있다. 원본 정렬/소계설정의 세 행·페이지분할·소계라인·올림/내림을 읽었지만 기준 선택과 적용 규칙은 아직 미확인이다. 설정창에서 임시 검색어만 입력하고 적용 없이 닫았으며 원본 주 입력행을 조작하지 않았다. 전역/버튼별 재현 완료 기준은 그대로 미완료다.
