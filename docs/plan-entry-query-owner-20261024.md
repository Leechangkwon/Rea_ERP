# 주문·재고 보조창의 조회 전 계정·입력창·저장본 확인

## 기존 → 변경과 이유
0.89.0 이후 계획된 독립 보조창 수명주기를 확인한다. 공통 EntryUI dialog.guard는 입력 권한과 open만 확인하고 주문/재고 검색 refresh는 이를 통과하지 않고 DB/초안을 읽는다. 계정·회사·역할·권한/저장본이 바뀌거나 부모 입력창을 제거한 뒤에도 검색을 재실행하는 것을 합성 재현했다. 왜 수정하는가: 적용을 막아도 이전 화면의 자료를 새 계정/창에서 다시 조회하는 것은 올바르지 않기 때문이다.

공통 current 검사에 기존 assertCurrent를 연결한다. 최초 표시 전은 허용하고 표시 후 닫힌/분리된 창은 거절한다. 검색·필터·행 redraw와 선택/적용 전에 검사하며 실패하면 표를 지우고 오류를 표시한다. 부모 초안/저장 자료와 helper 선택의 내부 원문은 바꾸지 않는다. 검증은 조회 호출 카운터/0신규 읽기·표 제거·미저장 보존·정상 검색·닫힌 callback이다. 기존 readonly 단독 컴포넌트 조회는 유지한다.

## 범위와 검증
주문/일반 전표·재고/안전재고의 EntryUI만 수정한다. 바코드 입력/검증은 다음 독립 단위다. 원본 로그인/주 입력행/설정 저장/발송0, 기존 PRD/P1 기반 자체 보존 수정이며 원본 기능 동등성으로 완료하지 않는다. 운영0.89.0 release5cef35e에서 격리0.89.1 후보를 만들고 관련 Node/브라우저·필요 전체회귀·REA6.4 후 source/release push와 기존운영 배포/자료·계정·양식·메일 보존을 검증한다. root전체빌드/VAT5/매핑 설치 금지. 운영 지속세션1061 poll/terminate 금지.
