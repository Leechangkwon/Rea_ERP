# 바코드 입력·수량 대조의 현재 입력창 확인

## 기존과 변경, 이유

0.89.1 다음 계획 OWN-BARCODE-HELPER-LIFECYCLE을 따른다. 바코드 입력은 부모 적용 시에만 계정을 확인하고 그 전에 기존 자료로 단가를 계산한다. 별도 수량 대조는 스캔·재계산·행 수정·정렬·My품목 불러오기에서 부모 검사를 통과하지 않는다. 계정/회사/역할/권한·저장본 변경과 부모 제거를 실제 입력 컴포넌트에 연결한 합성자료로 재현한다. 왜 변경하는가: 적용 차단만으로는 다른 계정이나 변경된 저장본에서 이전 화면의 조회·검증 결과를 계속 만드는 것을 막을 수 없기 때문이다.

입력은 계산 전후 현재 입력창과 쓰기 권한을 확인한다. 수량 대조는 현재 입력창 검사와 쓰기 권한 검사를 분리해 기존 조회 전용 검증을 유지한다. 최초 표시 전 초기화는 허용하고 표시 후 닫힌/분리된 창의 callback은 중단한다. 실패하면 이전 비교 결과를 지우고 미저장 스캔 원문·부모 초안·저장 자료는 보존한다. 정상 계정/저장본 복구 후 재검증할 수 있다.

## 검증 및 배포 경계

신규 Node에서 현재 부모와 연결한 7가지 무효화·이미 열린 정렬·분리된 보조창·정상 입력/복구를 검증한다. 기존 조회 전용·소수 수량·검증결과/개인 그룹 검사를 유지하고 실제 셸 브라우저 390/1280px에서 확인한다. 격리 후보는 운영 release42c51b4에서 만들며 root의 미배포 VAT/매핑과 기존 dirty12파일은 보존한다. 후보 전체 verify:local/자체 REA6.4 후 커밋/push·기존 WSL/Supabase/Cloudflare 배포·계정/자료/양식/메일 보존을 확인한다. 원본 로그인/주 입력행/설정 저장/업무 발송0이며 원본 전체동등성 완료로 처리하지 않는다.
