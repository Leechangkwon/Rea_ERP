# 서버 CSV 미리보기 0.25.0

Self의 엑셀자료올리기 화면에서 품목·거래처의 실제 가져올 값을 적용 전에 확인하도록 보완했다. 거래처 그룹1/2를 포함한 지원 열 안내와 거래처 예제 다운로드를 추가했다. 기존 코드가 있으면 차단하는 서버 동작과 다르게 ‘기존 코드는 수정’이라고 표시하던 안내도 고쳤다. 원본 ECOUNT의 가져오기 동등성을 주장하는 변경은 아니다.

## 동작과 합격 조건

- 품목은 code/name/spec/unit/group/memo/buyPrice/sellPrice/safety의 아홉 열, 거래처는 code/name/kind/group1/group2/memo의 여섯 열을 안내하고 미리보기에 모두 표시한다. 기존 코드·이름 두 열만으로 숨겨지던 그룹·가격·규격·적요도 적용 전에 보인다.
- 서버는 기존대로 전체 최대500행을 검증하고 앞20행을 미리보기로 반환한다. 반환된 행보다 총수가 많으면 ‘앞20개 행’임을 명시한다. 전체 검증과 표시 표본을 구분한다.
- 내용이나 자료 종류를 바꾸면 미리보기와 적용 버튼을 제거한다. 검증 중 변경한 입력도 적용되지 않는다. 서버의 businessRevision·앱 revision·미리보기 만료·중복 가져오기 규칙은 바꾸지 않는다.
- 기존 품목 예제를 유지하고 group1/2가 든 거래처 CSV 예제를 추가한다. 두 파일은 합성 예시와 UTF8 BOM을 포함하고 다운로드 자체는 API 호출이나 업무 저장을 만들지 않는다.
- 신규 등록 전용 서버 정책을 정확히 안내한다. 기존 코드는 덮어쓰지 않고 중복 자료는 전체 검증 단계에서 차단한다. 프로젝트 CSV 가져오기나 새 API는 추가하지 않는다. 스키마·저장 형식도 바꾸지 않는다.

신규 Worker/jsdom 통합 검사3개로 25행 거래처의 그룹 미리보기·20행 표시 제한·변경 후 재검증·실제 검토한 값만 저장·중복 코드 실패 무반영, 품목 아홉 값과 종류 변경 시 적용 해제, 두 예제 파일의 실제 헤더/BOM·업무 무변경을 확인했다. 기존6개와 집중9개가 통과했고 독립 검토에서 확정 결함을 발견하지 않았다. 전체 결과는 validation.json에 기록한다. 인증된 호스팅 업무 QA는 미수행이다.

## 기간 비교의 별도 연구

기존78본문의 실제 REA6.4.0 근거22개와 원본 읽기 전용 조회를 대조했다. 전월동일기간은 날짜 범위 두 헤더가 각각 다섯 열을 감싸고 집계 다섯 열이 좌우 두 세트로 표시된다. 숫자를 가린 날짜 형식·헤더 폭만 보관했다. 조사 뒤 사용안함으로 일반 다섯 열 조회를 복원했다.

원문은 두 기간 배열의 표식/합치기와 키·정렬·추출기 설정을 외부 WidgetDLTBuilder에 전달하는 경계까지 확인된다. 실제 키 매칭·누락 행·빈칸/0 처리와 서버가 계산하는 전년/월/주/일의 월말·윤년·주차 규칙은 미확인이다. 자체 기간 비교를 구현하거나 일반 날짜 라이브러리의 계산을 원본 동작으로 추정하지 않았다. 근거와 중단 상태는 period-comparison/에 보존한다. 새 GET·원문 실행·회사 기록 수집은 없다.

전역759경로의 버튼별 동등성, 주차·거래유형·관리항목 축, 소계·상세 이동·비교·그래프·설정 저장·원본 서버 정렬/집계·그룹 SID와 이력 정책이 남아 있다.
