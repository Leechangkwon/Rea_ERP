# 발주서 생성 전 참조 일괄지정 · 0.73.0 계획

운영0.72.0/0ac0623을 기준으로 생성 전 일괄변경을 이어간다. 기존 PRD/아키텍처/로드맵과 모든 자료·양식·메일을 보존하고 main VAT5 연구는 배포에서 제외한다.

## 원본 근거와 창고 보류

EC-HELP-PLAN-GENERATION-MODES 공식 영상 ivdIVimbCDU 전체 자막의2:01~2:10은 생성 전 직접입력 일괄변경을 안내한다. 확인한2:08 화면에 참조를 포함한8필드가 있다. 기존 자막/프레임의 SHA를 재검증했고 원본 조회·도움말 세션은 유효하다. 원본 저장/입력행/설정 변경은 하지 않는다.

입고창고 일괄변경은 현재 InventoryCore의 planAllocations 검증이 source.warehouse===generated.warehouse를 요구하며, 일반 plan→purchaseorder 연결도 같은 창고만 허용한다. 구매 입고창고 변경 예외(발주서→구매)와는 다른 연결이다. 영상의 필드 존재만으로 원본 배분·백업·기존 후속전표 변경 규칙을 확정할 수 없어 이 계약을 보류한다. 현재 guard를 제거하거나 기존 자료를 이관하지 않는다. 납기 직접변경의 머리/품목행 적용 범위도 미확인으로 남긴다.

## 구현 범위

참조 일괄지정의 비어 있지 않은 텍스트만 선택적으로 request.referenceOverride에 담는다. 제공하지 않은 경우 기존 생성 결과를 유지하고, 명시한 경우 그룹 계산 후 생성 발주서의 reference만 지정한다. 원본 계획의 참조를 자동 상속하는 기본입력 규칙이나 빈값을 강제로 지우는 동작은 구현하지 않는다. 공백만 있거나 텍스트가 아닌 직접 API 값은 거부하며 입력된 문자열 자체는 임의 정규화하지 않는다. 새 스키마·그룹·수량·단가·부가세·배분·권한 변경은 없다.

설정 입력은 기존36/44px 필터 배치를 사용하고 입력 즉시 미리보기를 무효화한다. 참조를 전표별 미리보기 조건에 textContent로 표시하고 명시 생성/저장·재조회·백업에 같은 값이 남아야 한다. 미리보기 후 참조/원본/권한 변경과 저장 실패 때 기존 자료를 보존한다.

## 합격·반영 범위

5방식 및 기존 담당자 지정을 함께 적용해 참조 외 그룹/행/금액/원본이 같음을 확인한다. 형식 오류·미리보기 조작·원본 참조 변경·권한 회수·저장 실패·취소를 검사한다. 실제 app shell390/864/1280 합성 화면에서 선택/입력/미리보기/저장/reload와 버튼 상·하한/overflow를 확인한다. REA6.4 관련 범위 분석, 운영기반 분리후보 전체 verify:local→커밋/push→기존 WSL/Supabase/Cloudflare에 반영 후 기존 로그인/자산/브라우저 JSON·양식·서버/메일을 대조한다. 운영계획0건이므로 실제 유자료 생성은 합성 검증이며 전체 매뉴얼 done은false다. 모아 인증이 변하지 않은 상태에서 반복 조회하지 않고 기록을 로컬에 보존한다.
