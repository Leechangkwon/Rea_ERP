# 구매 반품 저장 계약과 현황 연결 · 2026-10-21

## 다음 단위 · 0.64.0 이후 구매현황 작업 탭 상태

기존 PRD 공통 화면/작업탭 요구와 실제 0.58.0에서 확인한 탭 전환 초기화를 보완한다. app.js renderMenuPage는 InventoryUI.beforeNavigate로 현황을 destroy한 뒤 새 render를 실행하며, PurchasingReportUI.snapshot/restore는 세부 팝업 복귀에만 쓰여 작업 탭에는 연결되지 않는다. 원본 현재 w_flag 별도창 모드는 작업 탭을 직접 노출하지 않는다. 원본 구매현황의 외자/금일 읽기 조회→Search(F3) 재열기→미검색 내자 조건→접기에서 기존 성공 결과와 대기 조건이 분리됨을 관찰했다. 새창열기 메뉴는 확인했으나 실제 새 창 생성·탭 복귀 보존은 이번 환경에서 미검증이다. 이 작업은 REA의 기존 작업 탭 계약 보완이며 원본 탭 전체 동등성 완료로 주장하지 않는다.

지원 중인 구매계열 현황에 한해 현재 화면의 적용 조건·대기 조건·빠른검색·오류·검색 펼침·그래프/집계/정렬 및 표 스크롤을 메모리에서 보관하고 같은 열린 작업 탭 복귀 시 복원한다. 전표·양식·메뉴 설정·서버·메일·브라우저 영구 저장소에는 새 자료를 쓰지 않는다. 재조회가 필요한 기존 세부 팝업 복귀 계약은 유지한다. 실제 메뉴의 작업 탭 ID를 넘겨 별칭 메뉴도 분리하며, 메인 이동은 보관하고 명시 탭 닫기/모두 닫기는 폐기한다. 닫기 취소는 보관 상태도 유지한다. 새로고침은 메모리 캐시를 복원하지 않는다.

계정/회사/역할·조회 권한이 바뀌면 보관 상태를 적용하지 않고 폐기한다. 다른 화면에서 전표/양식/설정이 변경됐으면 이전 결과를 자동으로 새 결과처럼 표시하지 않는다. 저장 자료가 바뀐 경우 최신 유효 자료를 읽고 대기 조건만 복원해 검색(F8)을 안내한다. 잘못된 외부 백업은 덮어쓰지 않으며 기존 읽기 오류를 유지한다. 외부 저장 변경은 새 상태 복원 판단에 포함한다. 수동 조회와 변경 없는 탭 복귀를 구분하고, 저장 권한을 추가하지 않는다.

합격은 실제 app.js 작업 탭 통합으로 구매현황 검색→미적용 조건/오류/그래프/스크롤→다른 조회/입력 탭→원래 탭 복귀→기존 결과·CSV·인쇄 동일→명시 재검색 갱신→메인 복귀→닫기/재열기 초기화다. 기존 입력 초안·닫기 거절을 보존하고, 자료/사용자/권한 변경과 외부 저장 오류, 별칭 두 탭, 반복 이동·미저장 창 정리를 검사한다. 운영0.64.0 기반 격리 후보에서 전체 검증 후 commit/push/기존 WSL·Supabase·Cloudflare 반영과 실제 로그인/전표/양식/서버/메일 보존을 확인한다. main VAT5 연구 빌드는 설치하지 않는다.

## 원본과 차이
원본 도움말 「구매한 품목을 반품했을 때 처리 방법」(EAM012M_937173820665)은 기존 구매를 복사한 음수 구매 저장과 직접 음수 입력, 구매현황의 구매구분 전체/일반/반품을 설명한다. 일반은 양수 수량, 반품은 음수 수량이다. 원본 저장은 실행하지 않았다.

현재 REA는 양수 purchasereturn 별도 전표에 sourceAmounts/returnAmounts를 고정하고 credit만 채무를 차감한다. purchase 현황은 이 전표를 누락한다. 음수 purchase 저장은 금지돼 있다. 이번 단위는 기존 구매/차감반품 저장자료 → 구매현황 구분 조회 → 집계/상세/CSV/인쇄/그래프이며 기존 저장자료를 변환하지 않는다.

## 순서와 합격
1. 차감반품을 현황에서 수량·공급가·세액·합계를 음수로 투영한다. 고정 returnAmounts를 그대로 사용하고 원본 전표/행을 유지한다.
2. 구매현황에 구매구분 전체(기본)/일반/반품을 추가한다. 행 수량의 부호로 나누며 다른 메뉴와 잘못된 조건은 거부한다. 취소/미확인/삭제 정책은 기존 listed 계약을 따른다. 교환반품·교환입고는 채무영향0인 기존 계약에 따라 금액 보고에서 제외한다. 이는 호환 정책이며 원본 교환 동등성은 미확인이다.
3. 적용 전 변경·다시작성·조회실패·화면이동 복원에서 마지막 성공 조건과 결과를 보존한다. 집계/상세/내보내기/인쇄/그래프는 같은 필터와 부호를 사용한다.
4. 합성 구매10 저장 → 차감반품3 저장/재조회 → 전체7/일반10/반품-3, 재고7·채무770 대사. 취소반품/교환 제외, frozen 금액, 단가 양수, 문서/양식/백업 불변을 검사한다. 관련 Node/jsdom 및 브라우저 한 절차, 분리 운영후보 전체 회귀 후 push/배포/운영 읽기와 보존 대조.

## 별도 후속: 음수 구매 저장/복사 반품
세액 Math.round 음수 대칭성, 반품 배분/원구매 연결/초과반품/혼합부호, 기존 반품의 이중차감 방지, 재고/재고가액/회계 signed 금액, 백업 검증·복원·후속참조 계약을 먼저 정한다. 원본 본문에 없는 초과수량·혼합부호·VAT 할당은 추정 구현하지 않는다. main VAT5충돌 연구는 운영에 넣지 않는다. 이번 현황 연결을 음수 구매반품 전체 완료로 처리하지 않는다.

## 기록
새로 읽은 「서로 다른 메뉴를 연결하여 입력된 자료를 불러오는 방법」은 매핑센터의 원본/목표 메뉴·항목 연결과 적용 절차다. 전체수량/초과입고/다중원전표 저장 증거는 아니며 별도 요구사항으로 기록한다. 기존 PRD/아키텍처/로드맵에 반영하며 중복 문서를 만들지 않는다. 모아 인증이 복구되기 전에는 로컬 대기 기록으로 남긴다.
