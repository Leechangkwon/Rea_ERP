# 기초등록 사용자 계산식의 참조·형식 변경 보존

## 기존과 변경, 이유

0.89.5 다음 계획 OWN-MASTER-FORMULA-PRESERVATION과 기존 기초등록 양식 계획을 잇는다. 문자 사용자항목을 숫자형으로 바꾸면 HTML number 입력이 기존 비숫자 원문을 공란으로 만들었다. 숨긴 항목도 값을 읽어 저장하므로 다른 항목만 저장해도 원문이 사라질 수 있었다. 계산식 오류 후에는 비활성 결과칸의 공란을 초안으로 읽거나 양식 전환 자체가 실패했다. 왜 변경하는가: 유형·양식 변경은 기존 품목 값과 미저장 초안을 지우는 명령이 아니기 때문이다.

숫자 입력이 표현하지 못하는 원문을 임시 문자 입력으로 보여 주고 수정 안내·오류 표시를 제공한다. 숨긴 해당 항목은 복구를 위해 일시 표시한다. 값 수정 또는 명시적 공란 입력 전에는 숫자 검증을 실패시키며 저장 시 해당 탭/입력에 초점을 둔다. 읽기 스냅샷은 비숫자 원문·마지막 저장된 계산값·미저장 일반 항목을 보존해 문자 양식 복귀를 허용한다. 실제 저장과 실시간 계산은 엄격하게 검사하고 실패한 계산 결과는 화면에서 지운다. 계산 결과 칸을 계산의 입력 원문으로 사용하지 않는다.

FormCore의 수식·참조/순환·백업 정책과 저장 schema를 바꾸지 않는다. 기존 문자 참조가 있는 양식도 임의 재작성/삭제하지 않는다. 유효한 숫자형 항목은 기존 number 입력을 유지한다. 0x10/1,200/1e309 등을 명시적 수정 없이 다른 값이나 공란으로 바꾸지 않는다.
