# 구매 집계 상세 0.33.0

일반 집계행의 마지막 축 표시값을 누르면 해당 집계에 속하는 자체 구매 내역을 조회합니다. 소계/총합계는 상세 링크가 아니며 전표별·라인별 축은 범위가 확인될 때까지 일반 표시를 유지합니다.

## 사용 예와 합격 조건

품목별·거래처별로 조회하고 한 행의 거래처 표시값을 누르면 두 축과 성공 조회기간을 모두 만족하는 행만 나와야 합니다. 부모의 날짜/축을 바꿔도 검색하지 않았다면 성공 조건을 사용해야 합니다. CSV와 인쇄는 열린 상세 결과를 내보내고 저장 자료를 바꾸지 않아야 합니다. Escape/닫기는 집계를 유지하고, 다른 메뉴로 이동하면 상세와 그 안에서 연 인쇄 미리보기도 제거해야 합니다.

## 원본 관찰·실제 REA

원본 두 축에서 첫 축/숫자는 span, 마지막 거래처 축은 anchor였습니다. Playwright 클릭은 시간 초과였고 이후 새 DOM/접근성 요소로 클릭해 같은 탭의 별도 구매현황 팝업을 확인했습니다. F3 조건은 현황 선택·라인별·비교기간 사용안함이었습니다. Escape 후 원래 집계가 남았습니다. 원본 팝업의16열은 근거 JSON에 기록했으며 실제 업무 이름/값/건수는 보관하지 않았고 저장·주입력행 조작·출력은 실행하지 않았습니다.

기존82본문의 common StandardUserAction 후보는 마지막 검색조건에 선택 비날짜 축 전체와 우선순위 날짜 축1개를 덮어쓰고 V5 팝업 HEADER 조회를 예약합니다. 실제REA callable16참조와 정적span46개를 연결했습니다. 현재 link→action ID·다른 축의 실 바인딩·소계/총합계 연결·정확 서버 조건과 출력은 미확인입니다. 후보의 전표/라인 처리는 날짜만 제한하므로 특정 전표/행 범위를 임의로 주장하지 않습니다. 원본 코드는 실행하지 않았으며 common OOM과 Flexion 의미분석 timeout도 유지했습니다.

## 자체 구현

지원17축의 원래 코드/그룹/날짜 버킷을 모두 비교합니다. 표시 이름으로 묶지 않고 마지막 성공 기간·거래처/품목/창고/프로젝트·통화·빠른검색 조건을 유지한 채 현재 자체 자료를 재조회합니다. 선택 키가 없어졌으면 오류를 알리고 범위를 넓히지 않습니다. 서로 다른 통화를 합치지 않고 입력 자료를 바꾸지 않습니다.

자체 상세는 기존19열 구매 양식을 사용합니다. 원본의 회사별16열 양식과 분류·매핑·시리얼/로트의 의미/동작을 재현했다고 주장하지 않습니다. 자체 상세의 날짜/번호 순서를 위해 집계용 정렬은 해제합니다. 원본 generic 후보가 정렬을 보존하는 것과 구분합니다. 팝업의 F3 조건 편집·문서 수정/저장은 아직 연결하지 않으며 F3/F8이 부모 검색을 실행하지 않게 막습니다. 인쇄/CSV/닫기는 연결했습니다. 인쇄 콜백이 만든 창도 추적해 화면 이동/상세 닫기 때 함께 정리합니다. 이 누락은 독립 검토에서 발견했고 실제 모듈 경로 검사로 보완했습니다.

## 기간 비교의 추가 근거

원본 전월동일기간 두 축 조회는 날짜범위2개와6열2세트였습니다. 일반행 한쪽 기간이 없으면 반대6칸이 빈칸인 구조를 관찰하고 사용안함으로 복원했습니다. 새 GET 없이 기존 Flexion을 좁혀62정적span/16기존REA참조를 연결했습니다. 엔진은 추출 축 키로 양기간을 합치고 같은 키/같은 기간은 필드별 뒤쓰기이며 누락 일반 셀은 참조 없는 정의로 만듭니다. 숫자0을 직접 주입하는 경로와 다릅니다. 다만 날짜 쌍은 외부 입력이며 월말·윤년·주차/시차·백엔드 기간 계산이 미확인이라 기간 비교 기능은 계속 비활성입니다.

새12개와 관련 집중/전체 검사 완료는 drilldown/validation.json에 기록합니다. 저장 형식/DB 변경은 없습니다. 호스팅 로그인 업무와 실제 기기 검증·전체 원본 동등성은 미완료입니다.
