# P1 — 공통 기반·기초자료·양식·권한

## 당초 계획과 이유

기초 코드/필드 ID, 기존 양식/백업, 저장 adapter, 회사와 사용자 경계를 먼저 안정화한다. **왜:** 같은 품목·거래처·통화·양식이 요청부터 구매까지 이어져야 후속 전표가 일관된 결과를 낼 수 있기 때문이다.

## 기존 → 변경과 이유

- 선택적 자유 텍스트 구매처 → 0.62.0에서 신규 품목은 활성 등록 구매처를 참조하고, 검색/선택 모달과 모달 내 신규 거래처 명시 저장을 연결했다(`f02093b`). **왜:** 사용자의 요청→계획→발주 테스트에서 품목 기본 구매처 누락과 수동 재지정을 확인했기 때문이다. 과거 공란 품목은 자동 보정하지 않는다. 신규 거래처 저장과 부모 품목 저장도 별도 동작이다.
- 단순 조건양식 → 로그인/거래처 등 조건의 AND와 등록 권한그룹 기반 선택으로 확장했다(0.61 `d65e9eb`, 0.63 `fd26896`). **왜:** 조건 이름만 같아도 다른 계정·회사·역할의 양식을 적용하면 잘못된 조회/입력 권한이 생기기 때문이다.
- 필수값 오류가 불명확한 입력 → 0.80~0.82에서 BODY 필수열 힌트·품목 순번/코드 오류와 머리 항목 입력 순서를 분리했다. **왜:** 어느 행이 저장을 막는지 알 수 있어야 하고, 화면 표시 순서를 바꾸는 것이 키보드 입력 순서나 과거 필드 값을 바꾸어서는 안 되기 때문이다.
- 무조건 숫자 기본값 → 0.75~0.77의 nullable 정밀도와 표시/업로드 입력 정책 분리, 0.84~0.85 통화 부가정보·인라인 등록을 보완했다. **왜:** 미지정·명시 0·표시 자릿수·입력 허용 자릿수를 섞으면 기존 금액이나 자료 해석이 바뀌기 때문이다. 통화 등록 성공은 외화 계산/출력 합격이 아니다.
- 양식창을 열 때만 권한 확인 → 0.88.1~0.88.3에서 현재 계정/회사/역할·수정번호 재검증, 역할 변경 및 닫힌 창의 늦은 동작 거절을 보완했다(`ba9c430`·`1ab248a`·`3c826d6`). **왜:** 창이 열린 뒤 권한이나 화면 생명주기가 달라질 수 있기 때문이다.

## 매핑 연구를 운영에 넣지 않은 이유

필드 연결 저장/가져오기 후보와 0.88 호환 rebase(`bbe1144`)는 존재한다. 그러나 원본 legacy `TC101P_01`의 선택·제거·적용·취소·권한·저장 계약과 운영 수락이 미확인이다. 현대식 derive 편집기로 대체하지 않는다. **왜:** 이름이나 유사 기능만으로 같은 편집기·같은 저장 의미라고 볼 수 없기 때문이다. 예전 dirty 후보 12파일은 보존하고, 호환 후보도 0.88.1~0.88.11의 후속 수정 11개를 통합하기 전 배포하지 않는다.

## 검증과 다음 작업

관련 기능의 합성 저장/재조회·취소·권한·닫힌 창 검사는 수행됐고 운영에서는 기존 자료 보존과 안전한 열기/닫기를 확인했다. 원본/운영 설정 저장의 최종 합격과 다중 사용자 공용 업무 저장은 남아 있다. **왜 다음에도 보존을 먼저 확인하는가:** 공통 양식·기초자료 변경은 여러 구매 단계에 동시에 영향을 주기 때문이다.

## 2026-10-24 · 전체 기초등록 필드·문자/숫자·계산식 (0.89.0)

당초 공통 기초등록/양식을 마련했으나 목록은 기본5필드만 양식에 넘겼고 품목 상세의83필드 설정은 공통 양식과 연결되지 않았다. 사용자 제보로 보조창보다 이 작업을 우선했다. **왜:** 구매처 등록을 해도 해당 품목의 구매처를 조회열에 선택할 수 없고, 커스텀 계산식이 실제 입력에 반영되지 않는 상태를 화면 완성으로 넘길 수 없기 때문이다.

전체83필드와 구매처7표시 항목·문자/숫자 추가·항목 선택식 계산 도우미를 연결했다. 계산 결과는 실시간 표시/저장 전 재검증하며 수식 실행은 안전한 기존 파서만 사용한다. 기존열ID를 읽을 때만 안정ID로 연결하고 명칭/순서/수식/typed 복합기본값·기존자료를 보존한다. **왜:** 확장 기능이 이미 쓰던 양식이나 값을 바꾸면 안 되기 때문이다. 기존4품목의 구매처 공란은 사용자가 명시 연결하며 자동 추측하지 않는다. 조회 계산은 표시/CSV, 입력 계산은 실제 저장으로 적용 범위를 구분한다.
