# P4 — 견적·주문·판매·출하·반품·채권

## 당초 계획과 현재 상태

공통 장부/기초자료를 기반으로 판매→재고/채권, 포털·쇼핑몰 외부주문, 부분 처리와 실패 복구를 검증한다. 현재 일부 공통 전표·조회/변환 기능이 있더라도 판매 전체 본문·저장·운영 수락은 미완료다.

## 기존 → 앞으로의 변경과 이유

구매와 비슷한 화면/이름으로 처리 → 판매의 고객·출하·채권 계약을 분리한다. **왜:** 0.88.5의 새 발주서가 영업 `order` 정규식 때문에 고객을 상속했던 실제 결함처럼, 명칭 유사성에 따른 공통 분기는 구매처/고객의 의미를 섞을 수 있기 때문이다.

주문 수집/전표 생성 → 중복 주문·부분 출하·반품·취소·외부 실패 재시도에서 수량/재고/채권을 함께 대사한다. **왜:** 화면에 주문이 보이는 것과 외부 주문이 한 번만 반영되는 것은 다른 합격 조건이기 때문이다.

## 선행 조건·합격 기준

관련 공식 본문, 고객/품목과 장부 계약, 공용 저장·역할 권한을 확인한다. 외부 계약이 없는 연동은 합성 결과와 실제 API/계정 결과를 구분한다. 구매 교재의 규칙을 판매 전체 또는 그 반대로 확대하지 않는다.
