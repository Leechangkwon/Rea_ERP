# P10 — 전역 심사와 현재 다음 작업

## 당초 계획과 현재 판정

전체 매뉴얼 요구사항의 미분해·미확인·차이·실패를 해소하고 보존·운영·기록까지 심사한다. 0.88.11 기준 **색인77/본문47/공식 요구사항44/최종 합격0, 전체완료 false**다. 전체 모수가 확정되지 않았으므로 완료율을 만들지 않는다. 합격0은 기존 구현이나 검사 성공이 없다는 의미가 아니라 최종 매뉴얼 수락 조건이 남았다는 의미다.

## 기존 → 변경한 완료 기준과 이유

테스트/배포 성공 → 출처와 버전, 정상/오류/권한 절차, 저장·재조회·연계·원장·출력, 합성/브라우저, 공용 기능의 두 사용자/두 브라우저·동시성, 기존 자료 보존, 운영 및 모아 저장 재조회까지 확인한다. **왜:** 한 단계만 통과해도 업무에서는 다른 단계의 누락으로 결과가 달라질 수 있기 때문이다.

원본 저장을 눌러 확인 → 안전한 조회·분리 팝업·비활성 공개 코드·자체 합성자료로 범위를 좁혔다. **왜:** 주 입력행/행 이동의 자동 임시초안과 북마크의 선행 저장을 실제로 확인했기 때문이다. 원본 로그인 만료는 로그인 필요로 기록하고 인증을 우회하거나 동일 시도를 반복하지 않는다.

## 다음 실행 순서와 각각의 이유

1. **단가 비교확정→발주 생성의 거래유형·세율 보존 대조.** 현재 인계의 다음 독립 작업이다. **왜:** 머리 적용·계획 묶음·일반 변환의 손실은 고쳤지만 이 경로의 계약은 별도로 확인해야 하기 때문이다. 결함을 사전 선언하지 않고 재현된 차이만 수정한다.
2. **구매 5단계의 미완료 수락 조건 정리.** 실제 본문·오류/권한·저장·재조회·원본행·부분수량·잔량·재고/채무를 연결한다. **왜:** 흐름별 작은 수정의 합계가 전체 절차 합격을 자동 보장하지 않기 때문이다.
3. **VAT5·최소구매단위·legacy 매핑의 근거가 확보될 때 재개.** 선택된 식·수치 예제·편집기/권한/저장 계약을 확인한다. **왜:** 같은 helper/기존 통과 회귀의 반복은 남은 충돌을 해결하지 못하기 때문이다. 매핑 후보 배포에는 후속 source 11개 수정의 통합도 필요하다.
4. **공용 저장/신원·권한과 P3~P9를 의존성 순서로 확장.** **왜:** 공유 데이터/원장이 안정되지 않은 상태에서 결재·급여·외부연동의 운영 수락을 선언할 수 없기 때문이다. 초기 구현이 있는 기능도 해당 본문 기준으로 다시 심사한다.
5. **모아의 실제 문서 기록 복구.** 프로젝트 트리·본문·편집 권한·버전을 읽고 기존 설계를 보존하여 세부 기록을 생성/갱신한 뒤 실제 저장 본문을 재조회한다. **왜:** 로컬 원고나 과거 링크만으로 현재 업무 프로젝트에 기록됐다고 볼 수 없기 때문이다.

## 이번 기록 작업의 결과와 경계

기존 계획 단위에 맞춘 초기/운영/P0~P10의 16개 세부 원고와 색인을 로컬 저장소에 작성했다. 현재 대화에는 모아 업무문서 도구가 없어 원격 생성/갱신/재조회는 실행하지 않았다. 플러그인 스킬 버전1.0.2와 도구 노출은 별개이며 인증 실패라고 단정하지 않는다. 기존 개인 페이지 쓰기로 대체하지 않았다.

운영 앱·자료·계정·양식·메일, 미배포 VAT5 및 기존 dirty 후보는 변경하지 않았다. 기록/내부 링크/근거를 검사하되 앱 빌드·전체 회귀·운영 재시작을 실행하지 않는다. **왜:** 이번 변경은 문서뿐이고 root 전체 빌드는 미완료 연구를 운영에 섞을 위험이 있기 때문이다.

모든 변경에는 기존→변경과 **왜**, 검증 한계, 보존, 다음 일의 이유를 계속 남긴다. 전체 매뉴얼 합격이 입증되거나 사용자가 중단할 때만 개발 자동화를 종료한다.

## 0.88.12 이후 큐 갱신

첫 번째 대조에서 실제 머리 거래유형 누락을 재현하고0.88.12로 수정·배포·보존 확인했다. 왜 다음 큐를 바꾸는가: 이 경로의 합성 저장/재조회는 통과했으므로 같은 회귀를 새 진척으로 반복하지 않고 원본의 미확정/요청가확정 거래처 계약을 먼저 확인해야 하기 때문이다. 단가요청 비교확정의 미확정행·요청가확정과 거래처 지정 세부 계약을 기존 공식 본문/공개 코드부터 대조한다. 이미 합격한 확정가·거래처·명시 머리·부분수량 회귀를 변화 없이 반복하지 않는다. VAT5 입력식5충돌·최소구매단위·TC101P_01 매핑의 원본/운영 수락 gate는 유지한다. 매뉴얼77/47/44/0과 모아 미게시 상태는 유지한다.
