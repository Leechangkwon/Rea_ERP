# P0 — 매뉴얼 조사와 완료 정의 변경

## 당초 계획

전역 메뉴뿐 아니라 버튼의 하위 메뉴·팝업·입력 조건·오류·권한·저장·결과·보관을 대조한다. 공식 본문을 요구사항으로 분해하고, 기존 구현 및 원본의 안전한 조회·공개 코드 분석과 연결한다.

## 기존 → 변경과 이유

메뉴/정적 액션 후보/자체 테스트 중심의 진척 설명 → **매뉴얼 절차와 결과의 합격 기준**으로 전환했다. **왜:** 사용자가 ‘매뉴얼대로 실제 업무가 되는 것’을 완료 조건으로 요청했고, 보이는 UI와 파싱 성공만으로는 저장·권한·예외·보존을 입증하지 못하기 때문이다. 기존 구현을 폐기한 변경이 아니라 완료 판단의 기준을 엄격히 한 변경이다.

2026-10-21 PRD·아키텍처·조사대장/로드맵을 기존 모아 프로젝트에 게시하고 본문을 재조회했다(`ffe797a`, `c44b4fd`). 날짜 검색 0.51.0 진행 기록이 마지막 실제 게시/재조회 버전이다. **왜 기존 프로젝트를 사용하는가:** 개발 기록과 설계의 연결을 유지하고 별도 개인 페이지에 분산시키지 않기 위해서다.

## 실제 조사와 한계

최초 공개 교육목차는 551항목·545고유 영상이었다. 이것은 본문 검토 수가 아니다. 0.88.11 기준 조사 누계는 색인 77·본문 47·공식 요구사항 44·전체 매뉴얼 최종 합격 0이다. 전역 전체 모수가 확정되지 않아 완료율을 계산하지 않는다.

근거의 우선순위는 사용자 지시, 공식 본문/버전, 안전한 실제 관찰, REA 정적 분석, 과거 교재다. 서로 다르면 충돌을 남긴다. **왜:** 회사별 동적 속성이나 원본 서버 계산은 공개 코드만으로 단정할 수 없기 때문이다. 원본 로그인 만료·주 입력행/행 이동의 자동초안·북마크의 선행 저장이 확인된 경우 관찰 범위를 줄인다. 이는 조사 완료가 아니다.

## 앞으로 할 일과 이유

P0의 설계 최초 게시와 전역 본문 조사 완료를 구분한다. 새 본문이 생기면 기존 기준판·해시·영향 요구사항을 남기고 필요 항목을 다시 연다. **왜:** 새 근거가 과거의 동작 가정을 바꾸는 경우도 있기 때문이다. 이번 16개 기록도 모아 도구가 제공될 때 실제 트리/권한/버전을 읽고 저장 후 재조회해야 게시 완료가 된다.
