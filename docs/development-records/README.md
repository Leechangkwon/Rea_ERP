## 이력의 신뢰 범위

현재 Git의 첫 두 커밋은 2026-10-18의 `d6d4d1f`(초기화), `008c735`(0.42.0 소스·검사·근거 가져오기)다. 그 이전 개발은 가져온 문서와 근거를 이용해 재구성했다. 현재 저장소에 없는 세션별 대화·정확한 개발일·개인 판단을 새로 만들어 넣지 않았다. 버전 순서와 Git 커밋 시각도 구분한다.

현재 기준은 [릴리스 근거](../../evidence/global-rea-20261018/current-release.json), [진행 기록](../manual-parity/PROGRESS.md), [실행 로드맵](../manual-parity/ROADMAP.md), [현재 인계](../handoff-windows-controller.md)다. 문서의 이전 상태판은 당시 기록이며 최신 운영 상태로 읽지 않는다. 원문이 명시한 판단과 재현된 결함 원인을 중심으로 이유를 적었다. 기능 효과를 설명하는 ‘왜’와 미래 작업의 필요성은 현재 근거를 바탕으로 이번에 정리한 설명이며, 확인되지 않은 당시 발언이나 개인적 동기를 복원한 것이 아니다.

## 앞으로 모든 변경에 남길 내용

1. **당초 계획/근거:** 어떤 업무 절차와 기존 요구사항을 대상으로 했는가.
2. **기존 → 변경:** 사용자의 어떤 입력에서 결과가 어떻게 달라지는가.
3. **왜:** 기존 방식의 구체적인 결함·새 근거·사용자 요청은 무엇인가. 종전 계획을 바꾸면 그 이유도 적는다.
4. **검증과 한계:** 정적 분석, 합성 저장/재조회, 브라우저, 실제 운영/원본 수락을 구분한다.
5. **보존:** 기존 자료·계정·양식·메일 및 미커밋 변경에 어떤 영향이 있는가.
6. **다음 일과 이유:** 미완료 항목, 필요한 근거·선행 조건·합격 기준을 적는다.

기록에 이유가 없으면 추정하지 말고 ‘기록된 이유 없음/추가 확인 필요’로 남긴다. 코드·검사 수나 버전 수를 매뉴얼 완료율로 바꾸지 않는다. 이번에는 기록만 추가했으며 앱 버전·계산식·운영 설정·자료를 변경하지 않았다.
