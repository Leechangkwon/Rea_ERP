# 구매 품목그룹 집계 0.22.0

구매현황에 품목그룹1별·2별·3별을 추가했다. 기존 축과 함께 열세 종류에서 최대 다섯 축을 선택한다. 현재 품목 등록정보의 그룹 문자열을 사용하며 그 기준을 검색 도움말·성공 조회 제목·인쇄에 표시한다. 원본의 SID·코드·명과 과거 전표 분류 정책은 미확인이다.

## 원본과 공개 근거

원본 후보를 열고 품목그룹1·2·3 단독 조회에서 각각 축 이름, 수량, 공급가액, 부가세, 합계의 다섯 열을 직접 확인했다. 회사의 그룹 값·기록·금액·세션 URL을 보관하지 않았다. 원본 업무·설정 저장은 실행하지 않았다.

기존 실제 REA6.4.0 자료의 정확한 구간21개를 대조했다. V5의 summary_prod_group1/2/3는 prod_group1/2/3 검색 refer_type, V56은 prod$prod$prod_group1/2/3 검색 prop_id로 바꾼다. 이는 집계 행의 드릴다운 필터 경로다. 별도 레거시 검색 조건 변환은 SID 배열을 연결해 PROD_CLASS_CD1/2/3로 넘긴다. 현재 원본 일반 GROUPBY·그룹 축의 실제 prop_id·SID/코드/명·빈 값·과거 분류 기준의 증거로 확대하지 않는다. 새 GET·원문 실행·전체 REA 분석은 없고 기존78본문/19,149,569B와 부분·시간/메모리 중단 상태를 유지한다.

## 자체 동작과 합격 조건

- 현재 ItemCore의 group1/2/3는 문자열 필드이며 독립적인 그룹 코드/명 마스터가 없다. 이 문자열을 구분 키와 라벨로 사용한다. groupNName을 임의로 코드/명 관계나 식별자로 바꾸지 않는다. 원본 그룹 자료 모델 동등성은 미완료다.
- group1이 없을 때만 예전 group 값을 사용한다. 명시적인 빈 group1은 지운 값으로 보존한다. 빈 그룹은 미지정으로 묶는다. 등록 문자열이 같으면 하나로 합치고 각 행의 수량·금액을 한 번씩 더한다.
- 현재 품목 등록의 그룹을 바꾸면 이후 조회에서 기존 전표도 새 그룹으로 집계한다. 과거 전표에 그룹 스냅샷을 추가하지 않는다. 성공 결과·인쇄에도 현재 등록정보 기준임을 표시해 아직 조회하지 않은 조건과 구분한다.
- 날짜·행 거래처 등 다른 축과 조합하고 필터와 취소 제외를 먼저 적용한다. 축별 방향과 명시 정렬을 연결하며 축 교체·지우기는 사용할 수 없는 정렬을 해제한다. 다른 통화 합산은 계속 거부한다.
- 재조회·CSV·인쇄와 조회 전용 권한을 유지한다. DB 스키마·기존 저장 자료 형식은 변경하지 않는다.

## 검증과 잔여 범위

신규 합성 검사9개와 관련 집중 검사87개로 세 단독 축, 빈 값·예전 group 호환·명시적 지우기, 그룹 문자열 식별, 현재 등록정보 변경과 합계 보존, 날짜/거래처와 다섯 축 조합, 정렬·교체, 성공/미조회 조건 분리, 조회 전용 CSV·인쇄의 열·안내를 검사했다. 전체 결과는 validation.json에 기록한다. 관리 브라우저를 사용할 수 없어 인증된 호스팅 업무 QA는 미수행이며 합성 Worker/jsdom 검사와 구분한다.

거래처·프로젝트 그룹과 주차·거래유형·전표·관리항목·라인 등 추가 축, 독립 그룹 마스터/원본 SID·코드·명과 이력 정책, 원본 소계·상세 이동·서버 공식·정렬·비교·그래프·설정 저장 및 전역759경로의 버튼별 동등성은 남아 있다.
