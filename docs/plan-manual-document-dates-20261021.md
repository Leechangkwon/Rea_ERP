# 매뉴얼 첫 차이: 작성일/수정일 검색 · 0.51.0 계획

## 근거와 범위
2026-10-21 원본 발주요청조회 > 도움말 > 온라인매뉴얼 36항목을 확인했다. 「전표 작성일자/수정일자 기준으로 검색하는 방법」 본문은 최초작성일/최종작업일과 전표 기준일의 교집합, 미수정 전표의 두 일자 동일을 명시한다. 원본 검색항목설정 > 위젯설정에서 최초작성일자(write_dtm), 최종수정일시(update_dtm) 필드도 직접 확인했으며 설정은 저장/적용 없이 닫았다. 매뉴얼의 최종작업일자와 현행 UI의 최종수정일시는 같은 요구사항의 명칭 차이로 기록한다. 원본 서버 질의/시간대 내부 구현은 미확인이다.

첫 구현은 발주요청조회에 한정한다. 공통 helper는 재사용 가능하게 만들고 다른 조회는 각각 실제 항목을 확인한 뒤 연결한다. 기존 구매실 자료/사용자 양식/계정/메일을 유지한다. 거래별 부가세와 구매관리 기본 흐름은 본문 확인 후 다음 요구사항으로 등록하며 이번에 세금 계산을 변경하지 않는다.

## 구현 계약
- 최초작성일자 시작/종료, 최종수정일시 시작/종료를 빈 값 기본으로 추가한다. 기존 사용자 양식의 ID·순서·숨김·명칭·기본값을 변경하지 않는다. 날짜 조건은 일 단위며 종료일 포함, 한국어 기존 업무일 정책 Asia/Seoul을 적용한다. 원본 시간대 내부 동일성은 미확인이다.
- 기준일자, 작성일, 수정일은 AND. 입력 중에는 기존 결과/선택/CSV를 유지하고 검색(F8) 시 적용한다. 역전 기간은 기존 결과/적용 조건/선택을 유지하며 오류를 표시한다.
- 신규 구매 전표는 최초 성공 저장 시 createdAt=modifiedAt을 같은 시각으로 기록한다. 기존 createdAt은 수정 payload에 의해 바뀌지 않는다. 수정/상태변경은 기존 규칙대로 실제 성공 변경 때만 modifiedAt 갱신한다.
- 옛 전표를 읽거나 복원할 때 시각을 만들지 않는다. 정확한 보관 이력이 있으면 최초 신규 이벤트와 최종 이벤트를 조회용으로 참고한다. 증거가 없는 일자는 미기록이며 해당 날짜 조건에서는 제외한다. 입력 조건을 해제하면 기존 자료가 다시 나타난다.
- 의미있는 단위 검사: KST 날짜 경계·윤일·AND·미기록·보관 이력·최초 시각 위조 차단·실패/무변경·기존 백업 무변경. UI 검사: F8·기간 오류·선택/CSV·기존 양식 보존.
- REA 공개 원본 해시 재검증 및 좁은 분석, 자체 변경 분석. 관련 검사 → verify:local → 소스 커밋/푸시 → 비공개 보존 백업 → 지정 운영 서버만 반영 → 공개/로그인 화면 검사 → 자료 보존 → 모아 기록.
