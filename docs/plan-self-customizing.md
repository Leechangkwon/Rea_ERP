# 앱 계정과 Self Customizing 0.6.0

사용자의 수정 지시: 앱의 ID와 비밀번호로 로그인하며 ChatGPT 식별자를 ERP 사용자로 간주하지 않습니다. Sites 스킬의 기본 인증 지침보다 이 명시적 요구를 우선합니다. 현재 비공개 호스팅 접근 범위는 유지합니다.

- 앱 계정: 최초 관리자 등록, ID·비밀번호 로그인, HttpOnly 세션, 로그아웃, 비밀번호 변경, 실패 제한·잠금, 활성 세션 폐기. 비밀번호 원문과 세션 토큰은 로그·소스·브라우저 저장소에 남기지 않습니다.
- 역할: 서버에서 사용자·그룹·관리자·승인 상태와 현재 권한을 검사합니다. 비활성화·권한 변경은 기존 세션에도 적용하며 마지막 관리자는 제거하지 않습니다. 기존 Sites 식별자만으로 업무 API를 호출할 수 없게 합니다.
- 데이터: 기존 gateway_state의 업무·키·송수신 이력을 보존하고 별도 app_state에 회사·계정·설정·감사 정보를 저장합니다. 적용된 마이그레이션은 변경하지 않습니다.
- Self Customizing: 정보관리, 사용자관리, 환경설정, 기타관리시스템, 보안관리, 다운로드의 모든 표시 경로를 실제 설정·관리 화면으로 연결합니다. 외부 제공자와 연결하지 않은 기능은 연결 완료로 표시하지 않습니다.
- 기능 적용: 회사명·로고, 기본 창고·통화·부가세, 음수재고·단가 우선순위, 로그인 보안, 사용자 권한, 허용 IP를 실제 코드에 연결합니다. 기존 브라우저 재고 영역과 서버 API 자료의 차이는 유지하고 표시합니다.
- 자료 관리: 백업·안전한 초기화·CSV/엑셀 붙여넣기 가져오기 미리보기와 검증을 제공합니다. 송수신 이력이 있는 업무 영역은 임의 초기화하지 않습니다.
- 검증: 실제 인증/권한/경합/잠금/세션 폐기·설정 적용·전 경로 렌더링·API 문서 경로 대조를 확인합니다. 로컬 계정 검증과 호스팅 최초 관리자 등록 전 화면 확인을 구분합니다.
- 초기 관리자 비밀번호는 사용자가 배포된 화면에 직접 입력합니다. 배포에 기본 비밀번호나 미리 만든 계정을 포함하지 않습니다.

## REA 전체 재구성 범위 확대

사용자는 기존에 REA 없이 구현한 부분도 로그인까지 포함해 모두 REA를 거쳐 재구현하도록 요구했습니다. 공개 원본 11개, 기존 배포0.5.1의 전체 JavaScript와 Worker, 새 구현을 구별하여 정적 분석하고 메뉴·재고·양식·API·문서·인증·Self별 대조 근거를 남깁니다. 수학적 계산 커널은 검증된 로직을 유지하면서 권한·명령 정책·양식 조건·기본값·세션·문서를 재구성합니다. 정적 근거와 독립 구현 테스트를 원본 서버 동작의 증명으로 해석하지 않습니다.

사용자의 추가 지시에 따라 REA 증거·인증 검토·Self UI 검증을 별도 에이전트에 분업하고 메인 작업자는 브라우저 검증·통합·배포를 담당합니다. 파일 소유권을 나누어 충돌을 피하며 최종 빌드와 전체 검증은 합친 상태에서 실행합니다.
